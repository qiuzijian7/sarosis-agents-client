聊天框切换 TUI 显示 — 调研报告

项目：sarosis-agents-client (vssaros v2.2.26037) · 生成于 2026-09-20 · 全部结论基于源码实测
结论：已经支持，且已完整实现 —— 不是「能否」，而是「已上线」

项目内已存在 xterm.js 驱动的 TUI 聊天面板 XtermCliPanel，并通过命令 agentStudio.toggleCliStyle（Ctrl/Cmd + Shift + L）在富文本气泡模式与 CLI 模式间实时切换，会话状态与布局均会持久化。

我之前答复中「缺渲染器抽象 / 需半天工作量」的判断不成立——那是在未读 nativeChatEditorPane.ts 时的误判。此处更正。

2. 架构：两套面板，一个接口

关键设计是 IChatPanel 接口 —— 两种渲染器实现同一契约，上层 NativeChatEditorPane 完全无感知。

// nativeChatEditorPane.ts:863-869
// Choose panel type based on cliMode.
// - XtermCliPanel: xterm.js-based TUI rendering (true terminal emulator)
// - AgentChatPanel: rich bubble UI (default)
// Both implement IChatPanel so the rest of the pane code is agnostic.
const useCliPanel = this.input instanceof NativeChatEditorInput && this.input.cliMode;
const PanelCtor = useCliPanel ? XtermCliPanel : AgentChatPanel;
this._chatPanel = this._register(new PanelCtor({ ... }));

模式 A — AgentChatPanel（默认）

  • 富文本气泡 UI（DOM）
  • 继承链组合：Panel → Header → Send → … → Base
  • 支持富卡片：mermaid / drawio / kanban / 搜索结果 / 确认卡
  • 文件：agentChatPanel.base.ts 等 14 个

模式 B — XtermCliPanel（CLI）

  • xterm.js 真实终端模拟器，ANSI 渲染
  • Markdown → ANSI：mdToAnsi.ts
  • 代码高亮：syntaxHighlight.ts
  • 工具树渲染：toolTreeRenderer.ts
  • 主题适配：ansiTheme.ts + xterm-cli.css

其内部分层（取自源码注释 xtermCliPanel.ts:50-58）：

┌──────────────────────────────────────┐
│  xterm.js Terminal (output)          │   ← 真终端，ANSI
│  markdown → ANSI → terminal.write()  │
├──────────────────────────────────────┤
│  HTML textarea (input)               │   ← 保留 DOM（刻意）
├──────────────────────────────────────┤
│  DOM status bar                      │
└──────────────────────────────────────┘
输入区保留 textarea 是有意为之（xtermCliPanel.ts:48）：注释写明 "The input area and status bar remain as DOM elements for better UX (textarea, keyboard handling)"。即「输出 TUI 化、输入仍走原生」，兼顾终端观感与中文 IME / 多行编辑体验。

5. 持久化：重启后仍记得

cliMode 不是临时开关，而是随 编辑器布局 一起保存/恢复的：

位置作用
nativeChatEditorInput.ts:131字段 private _cliMode = false
:239-247get cliMode() / setCliMode()
:280序列化成 cliMode 字段
agentStudio.contribution.ts:2343-2351反序列化：if (data.cliMode) input.setCliMode(true)
workbench.ts:1735-1736布局恢复时还原 CLI 态
agentLayoutWorkbench.ts:511-512多编辑器组同样生效

即：每个聊天标签页可独立记忆自己的显示模式，可以在一个组用气泡、另一个组用 CLI。

唯一实质代价：富卡片降级。气泡模式下的 mermaid / drawio / kanban / 搜索结果卡片在 CLI 模式没有等价渲染，会退化为文本或树形。这是「终端字符网格」的固有限制，非缺陷。若某条消息强依赖图形，应留在气泡模式。

7. 更正与遗留不确定项

对我此前答复的更正

我此前基于部分检索判断「TUI 渲染器已写好，但缺渲染接口抽象、需接 xtermTui、需加切换开关，约半天工作量」——该判断错误。
事实：① IChatPanel 接口抽象已存在；② XtermCliPanel 已接线到 nativeChatEditorPane；③ 切换命令与快捷键已注册。三者均非待办，而是已完成代码。错误源于我未读 nativeChatEditorPane.ts 的面板选择与同步逻辑。

仍未核实（诚实声明）

  • ▸xtermCliPanel.ts 全文 771 行，我仅读前 80 行；富卡片在 CLI 下的具体降级行为（是忽略、转文本还是报错）未实证，需读 renderMarkdownToAnsi 对该类节点的处理
  • ▸CLI 模式下 中文 / CJK 宽度对齐是否正确（xterm 需 east-asian-width 处理），未实测
  • ▸快捷键 Ctrl+Shift+L 是否与其它命令冲突，未查全局 keybinding 表
  • ▸实际运行截图未获取（当前环境无 GUI 实例），mockup 为按源码逻辑还原
