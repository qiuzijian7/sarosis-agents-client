Understanding VS Code Extensions API
https://code.visualstudio.com/api/extension-guides/overview 4,283 chars

VS Code is built on a modular architecture that lets you build extensions using any programming language. The Extension API provides hooks into the editor's lifecycle, from activation events to UI contribution points.

Extensions are packaged as npm modules that can be published to the Visual Studio Marketplace. Each extension has a unique identifier in the format publisher.name.

Activation Events

Extensions are activated when certain conditions are met. Common activation events include:

  • onLanguage:{languageId} — when a file of a specific language is opened
  • onCommand:{commandId} — when a specific command is invoked
  • onDebug — when a debug session is started
  • workspaceContains:{pattern} — when the workspace contains files matching a pattern

Activation events are declared in the extension's package.json under the activationEvents array.

Contribution Points

Contribution points define what an extension contributes to VS Code. Examples include commands, menus, settings, keybindings, themes, and more.

Each contribution point is declared in package.json under the contributes object. For example, to register a command:

{
  "contributes": {
    "commands": [{
      "command": "myExtension.helloWorld",
      "title": "Hello World"
    }]
  }
}

The extension host runs in a separate process from the editor, ensuring extensions don't block the UI thread. Communication between the extension and the editor happens through the Extension API.

Extensions can register providers for features like hover information, code completion, document symbols, and more. These providers are called on-demand as the user interacts with the editor.

The vscode.window namespace provides access to the UI, while vscode.workspace provides access to the file system and workspace settings.

Getting Started with React

React is a JavaScript library for building user interfaces. It lets you compose complex UIs from small and isolated pieces of code called "components".

React components can be class components or function components. Since React 16.8, function components with Hooks are the recommended way to write React components.

To get started with React, you can create a new React application using Create React App, Vite, or a framework like Next.js.

The most important concept in React is the idea of declarative UI. You describe what the UI should look like for a given state, and React takes care of efficiently updating the DOM to match.

Components are the building blocks of React applications. A component is a JavaScript function or class that accepts inputs (called "props") and returns React elements describing what should appear on the screen.

The File System API provides an extensive set of methods for interacting with the file system in Node.js. It includes both synchronous and asynchronous variants for every operation.

The module provides operations for file system operations such as reading, writing, updating, and deleting files, as well as directory operations like creating, listing, and removing directories.

File System Constants

The following constants are exported by the fs module:

ConstantDescription
fs.constants.F_OKFile exists (use with access)
fs.constants.R_OKFile is readable
fs.constants.W_OKFile is writable
fs.constants.X_OKFile is executable
fs.constants.S_IRWXURead, write, execute by owner
fs.constants.S_IRWXGRead, write, execute by group
fs.constants.S_IRWXORead, write, execute by others

fs.readFile(path, options, callback)

Asynchronously reads the entire contents of a file. The callback is passed two arguments (err, data) where data is the contents of the file.

When the path is a directory, the behavior of fs.readFile() is platform-specific. On Linux and macOS, an error is returned. On Windows, an error is returned as well.

fs.writeFile(path, data, options, callback)

Asynchronously writes data to a file, replacing the file if it already exists. The callback is passed a single argument err.

The data argument can be a string, buffer, or Uint8Array. When the data is a buffer, it is written as-is. When it is a string, it is encoded using the specified encoding.

fs.appendFile(path, data, options, callback)

Asynchronously appends data to a file, creating the file if it does not exist. The callback is passed a single argument err.

fs.stat(path, options, callback)

Asynchronously returns information about a file. The callback is passed two arguments (err, stats) where stats is an fs.Stats object.

An fs.Stats object provides methods to check if the file is a regular file, directory, symlink, or other special file types.

fs.mkdir(path, options, callback)

Asynchronously creates a directory. The callback is passed a single argument err.

Options include recursive (boolean) and mode (number). When recursive is true, parent directories are created as needed.

fs.rmdir(path, options, callback)

Asynchronously removes a directory. The callback is passed a single argument err.

Note: The fs.rmdir() method is deprecated. Use fs.rm() instead for removing files and directories.

fs.readdir(path, options, callback)

Asynchronously reads the contents of a directory. The callback is passed two arguments (err, files) where files is an array of filenames in the directory.

The files array is returned with filenames as strings. When the withFileTypes option is set to true, the files array will contain fs.Dirent objects.

fs.unlink(path, callback)

Asynchronously removes a file or symbolic link. The callback is passed a single argument err.

fs.symlink(target, path, type, callback)

Asynchronously creates a symlink. The callback is passed a single argument err.

The type argument can be 'file', 'dir', or 'junction'. On Windows, the default is 'junction'.

fs.watchFile(filename, options, listener)

Watches a file for changes. The listener is called each time the file is accessed or modified.

Options include interval (number of milliseconds between polling) and persistent (whether to keep the process running).

fs.unwatchFile(filename, listener)

Stops watching for changes on the specified file.

fs.createReadStream(path, options)

Returns a readable stream for the specified file. The stream supports the standard readable stream interface.

fs.createWriteStream(path, options)

Returns a writable stream for the specified file. The stream supports the standard writable stream interface.

fs.copyFile(src, dest, callback)

Asynchronously copies a file from source to destination. The callback is passed a single argument err.

If the destination already exists, it is overwritten. The callback is invoked when the operation completes.

fs.chmod(path, mode, callback)

Asynchronously changes the permissions of a file. The callback is passed a single argument err.

The mode argument is an integer representing the file permissions (e.g., 0o644 for read/write for owner, read-only for group and others).

fs.chown(path, uid, gid, callback)

Asynchronously changes the owner and group of a file. The callback is passed a single argument err.

fs.utimes(path, atime, mtime, callback)

Asynchronously changes the access and modification times of a file. The callback is passed a single argument err.

The atime and mtime arguments can be Date objects or Unix timestamps (in milliseconds).

fs.truncate(path, len, callback)

Asynchronously truncates a file to a specified length. The callback is passed a single argument err.

fs.rename(oldPath, newPath, callback)

Asynchronously renames a file from oldPath to newPath. The callback is passed a single argument err.

fs.access(path, mode, callback)

Asynchronously tests a user's permissions for the file specified by path. The callback is passed a single argument err.

The mode argument can be one or more of the fs.constants values (e.g., fs.constants.R_OK | fs.constants.W_OK).

fs.link(existingPath, newPath, callback)

Asynchronously creates a new link to an existing file. The callback is passed a single argument err.

fs.readlink(path, options, callback)

Asynchronously reads the contents of a symbolic link. The callback is passed two arguments (err, linkString).

fs.realpath(path, options, callback)

Asynchronously computes the canonical pathname by resolving symbolic links. The callback is passed two arguments (err, resolvedPath).

fs.mkdtemp(prefix, options, callback)

Asynchronously creates a unique temporary directory. The callback is passed two arguments (err, folder).

The directory name is generated by appending six random characters to the given prefix.

fs.rm(path, options, callback)

Asynchronously removes files and directories. The callback is passed a single argument err.

Options include force (ignore non-existent paths), recursive (remove directories), and maxRetries.

fs.cp(src, dest, options, callback)

Asynchronously copies an entire directory structure. The callback is passed a single argument err.

Options include recursive, force, preserveTimestamps, and more.

fs.exists(path, callback)

Asynchronously tests whether a file exists. The callback is passed a single boolean argument exists.

Note: This method is deprecated. Use fs.stat() or fs.access() instead.

fs.readFileSync(path, options)

Synchronously reads the entire contents of a file. Returns the contents of the file.

fs.writeFileSync(path, data, options)

Synchronously writes data to a file, replacing the file if it already exists.

fs.appendFileSync(path, data, options)

Synchronously appends data to a file, creating the file if it does not exist.

fs.statSync(path, options)

Synchronously returns information about a file. Returns an fs.Stats object.

fs.mkdirSync(path, options)

Synchronously creates a directory. Returns undefined.

fs.rmdirSync(path, options)

Synchronously removes a directory. Returns undefined.

fs.readdirSync(path, options)

Synchronously reads the contents of a directory. Returns an array of filenames.

fs.unlinkSync(path)

Synchronously removes a file or symbolic link. Returns undefined.

fs.symlinkSync(target, path, type)

Synchronously creates a symlink. Returns undefined.

fs.chmodSync(path, mode)

Synchronously changes the permissions of a file. Returns undefined.

fs.chownSync(path, uid, gid)

Synchronously changes the owner and group of a file. Returns undefined.

fs.utimesSync(path, atime, mtime)

Synchronously changes the access and modification times of a file. Returns undefined.

fs.truncateSync(path, len)

Synchronously truncates a file to a specified length. Returns undefined.

fs.renameSync(oldPath, newPath)

Synchronously renames a file from oldPath to newPath. Returns undefined.

fs.accessSync(path, mode)

Synchronously tests a user's permissions for the file specified by path. Returns undefined.

fs.linkSync(existingPath, newPath)

Synchronously creates a new link to an existing file. Returns undefined.

fs.readlinkSync(path, options)

Synchronously reads the contents of a symbolic link. Returns the link string.

fs.realpathSync(path, options)

Synchronously computes the canonical pathname by resolving symbolic links. Returns the resolved path.

fs.mkdtempSync(prefix, options)

Synchronously creates a unique temporary directory. Returns the folder path.

fs.rmSync(path, options)

Synchronously removes files and directories. Returns undefined.

fs.cpSync(src, dest, options)

Synchronously copies an entire directory structure. Returns undefined.

fs.existsSync(path)

Synchronously tests whether a file exists. Returns a boolean.

Note: This method is deprecated. Use fs.statSync() or fs.accessSync() instead.

fs.watch(filename, options, listener)

Watches a file for changes. The listener is called each time the file is accessed or modified.

fs.unwatch(filename, listener)

Stops watching for changes on the specified file.

fs.promises

The fs.promises API provides an alternative set of methods that return Promise objects instead of accepting callbacks.

All of the synchronous methods are also available in promise form through the fs.promises API.

Example: const data = await fs.promises.readFile('/path/to/file.txt', 'utf8');
