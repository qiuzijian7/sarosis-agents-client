# 导入 LLM 消息（kb-import-message）

## 输入
- 调用方通过消息提供要导入的聊天消息正文（完整文本或摘要）。
- 调用方消息中会给出**真实绝对路径**：库文件路径、笔记分区根目录、操作日志路径。**必须原样使用，禁止自行推断或编造 vault 根目录。**

## 分类原则（核心：优先复用已有目录结构）
> 目标：让同类内容聚拢，避免每次导入都新建目录，造成碎片化。

1. **先扫描，后归类**：在决定分类前，**必须**先列出「库」与「笔记」分区中**已存在的目录结构**（至少扫描一级、建议扫描到二级子目录），把它作为候选分类清单。
   - 「库」：调用 `file_read` / 目录列举工具读取 `<vault>/库/` 下的现有子目录。
   - 「笔记」：读取笔记分区根目录下的现有子目录。
2. **优先匹配已有目录**：将本次内容的主题与已有目录逐一比对，**只要有语义相近的现有目录，就复用它**（含二级子目录），不要新建近义目录。
   - 例：已有 `技术文档/`，新内容是"性能优化"，应放入 `技术文档/性能优化/` 而非新建 `性能/`。
   - 例：已有 `AI研究/`，不要再建 `人工智能/`、`AI/` 等同义目录。
3. **就近下沉**：若一级目录匹配但更细的二级目录不存在，可在该一级目录下**新建二级子目录**，而不是在根部另起炉灶。
4. **仅在无任何匹配时新建**：只有当所有现有目录都明显不相关时，才在根部新建一个语义清晰的新分类目录，并保持库/笔记两侧目录命名一致。
5. **库与笔记目录对齐**：笔记的分类路径应与库文件的分类路径保持一致映射（同一 `<category>`），便于双向追溯。

## 流程（完整链）
1. **扫描现有结构**：列出「库」「笔记」分区已有目录（见上「分类原则」第 1 条），形成候选分类清单。
2. **自动分类（优先复用）**：解析消息内容（关键词/主题/代码块语言/问答类型），按「分类原则」优先命中现有目录，确定 `<category>` 与标签。
3. **落盘到库**：将消息组装成 Markdown（YAML frontmatter 含 title/date/source/agentid/tags/category + 原文不修改），写入 `<vault>/库/<category>/<YYYY-MM-DD>_<hash>.md`。
4. **结构化抽取**：对刚落盘的文档执行结构化抽取（提炼核心要点/技术概念/问答结论）。
5. **落盘到笔记**：将结构化笔记写入 `笔记分区根目录/<category>/<safe-title>.md`（增量合并同名笔记，`<category>` 与库文件保持一致）。
6. **操作日志**：完成后向调用方给定的操作日志路径追加一行 JSONL 记录（含 chosen category、是否复用已有目录 reusedExisting: true/false）。

## 执行硬约束
- **必须真实调用工具**（`file_read`/`file_write` 等）完成读取与写入，禁止仅用文字描述"已完成"。
- **禁止编造路径**：一切写入基址只能来自调用方消息中提供的真实绝对路径。
- 归类前**必须**先扫描现有目录；不得跳过扫描直接新建目录。
- **禁止创建或修改系统维护文件**：笔记分区根目录下的 `index.md`（全量索引）、`overview.md`（高层导航）、`insights.md`（图谱洞察）由系统在每次导入/删除后**自动重建**，agent 不得手动创建、改名或写入它们。
- **`sources` 由系统注入**：笔记 frontmatter 的 `sources: [...]`（源文件追溯，供删除时级联清理）由系统在导入完成后自动写入，agent 无需维护；agent 仍可继续写单值 `source` 字段作为可读备注。

## 输出
- 导入完成后，向用户报告：库文件路径 / 笔记文件路径 / 最终分类结果（并注明是"复用已有目录"还是"新建目录"）/ 操作日志摘要。
