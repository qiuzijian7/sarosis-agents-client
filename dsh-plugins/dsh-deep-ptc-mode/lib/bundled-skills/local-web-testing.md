# 本地 Web 交互验证

适用于验证真实浏览器中的一个具体行为，例如提交表单后只产生一次通知。先找仓库已有的浏览器测试入口和可用的 Playwright 环境。

1. 明确一个动作和一个可观察的结果。已有测试地址时复用它；需要自己启动服务时记录本次任务的后台任务 ID 与地址。
2. 打开页面，等目标控件可见、可用。桌面插件的页面可能保持长连接；优先等具体控件或状态。读当前页面上的角色、可见名称或测试 ID 选择元素。
3. 执行动作，断言用户看到的状态。遇到重复提交问题，额外核对请求或接收消息的次数。记录相关控制台错误、失败请求或一张能说明问题的截图。
4. 关闭自己创建的页面和临时服务。交付时区分浏览器里实际验证的链路与组件测试覆盖的链路。

本篇为 DSH 场景独立编写。工作流参考 [Anthropic 官方 webapp-testing](https://github.com/anthropics/skills/blob/main/skills/webapp-testing/SKILL.md)。
