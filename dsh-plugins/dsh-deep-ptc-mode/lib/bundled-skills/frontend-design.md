# 从使用场景到可用的前端界面

先确定页面服务的对象、首要操作和完成标志。例如插件管理页的核心是找到目标、看到当前版本、执行操作并确认生效。现有项目先看最相近的页面、组件、颜色与间距变量。新增页面沿用已有语言；独立项目可围绕内容选一种明确的排版和视觉方向。

- 用真实长度的标题、数量、单位和按钮文案排版。信息层级由内容顺序、字号、留白和对齐表达。把状态说明放在会改变用户下一步的位置。导航、提交、取消、重试都要连到实际行为。
- 数据密集界面先确定用户比较哪几列，对齐数值和单位；小屏优先保留主任务，给次要细节一个可访问入口。品牌或展示类页面围绕一个主视觉组织首屏，保留文字可读性与加载后的布局稳定性。
- 一次提交要能区分未保存、提交中、已保存和失败。失败保留输入，重复点击不产生第二次提交；异步更新时确认当前对象仍与请求对应。
- 验收时至少走通主操作，再按页面风险选择窄屏、长文本、空状态、键盘操作或失败恢复。记录实际观察。需要操作浏览器时加载 `deep-ptc-local-web-testing`；开发 DSH 自身界面时从 Cordis Inspect 读取实际插槽和主题。

### 可运行的界面切片

用浏览器打开附带的 [构建记录示例](examples/frontend-states.html)。输入 `empty` 可看无结果，输入 `error` 可看可恢复错误。先查 `slow` 并马上改查 `main`，即使旧查询最后返回，屏幕也应停在 main。复用这段实现时，把 lookup 替换成项目的数据源，保留请求代号检查与状态区。查询允许改选，付款或提交订单则要把按钮禁用到确认完成，服务端使用幂等键。

将同一套数据做成两种页面时：后台列表优先把名称和状态放一行，数值列用等宽数字，筛选放在列表上方；公开展示页先决定访客要理解的主张与代表图，再确定行动按钮的位置。可在浏览器用 375px 与 1280px 宽度检查主操作和焦点顺序。

本篇针对 Deep PTC 编写，视觉设计参考 [Anthropic 官方 frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)。
