# Deep PTC 与 DSH 操作导航

用户问「怎么用 DeepSeek Harness」时，先区分要操作的是当前会话、用户界面，还是某个插件。会话里的工具以当前 SDK 声明为准；界面位置和支持的配置跟随已安装宿主版本。

- 查功能或界面：先从 Skill 目录找 `dsh-doc`，可用时读取相应章节。缺少文档时，只检查这项操作涉及的命令帮助或已安装版本的声明。说明结论适用的版本。
- 查 CLI：`dsh --help` 查 profile（宿主配置组合）和启动方式，`dsh plugin --help` 查插件包管理。先确认用户的目标 profile。Web 和桌面可以有各自的插件清单。
- 找工具和 Skill：在 Deep PTC 用 `deep_ptc_tools` 的 `search` / `skills` 查能力，按返回的 `loadWith` 读取正文。用户询问未加载的第三方能力时，以当前会话目录为准。
- 分清三类状态：本次任务的目标、约束和验收在 `task_brief`；长期项目约定在项目卡；当前作业的运行和完成状态在侧栏与 `job_output`。依赖用户决定时按当前提问开关选择工具。
- 查卡片细节：界面块与按钮读 `deep-ptc-cards`，开发场景模板读 `deep-ptc-card-examples`，长期约定、提案与回滚读 `deep-ptc-project-cards`。按需加载对应的一篇。
- 查当前 Deep PTC：侧栏列出执行环境和任务，工具目录给出本会话可用能力。设置保存成功和已运行会话采用新预设是两件事；新增预设能力在新会话验证。
- 做插件开发：深度创造模式可从侧栏开启。官方文档没写到的宿主细节（提示词缓存代价、SDK schema 子集、插槽渲染时机、桌面版测试）读 `deep-ptc-dsh-plugin-dev`；在虚拟 DSH 里测试改动读 `deep-ptc-virtual-dsh-testing`。新会话里读取宿主提供的 `cordis-plugin-development`；改预设时找 `editing-cordis-compositions`，核对 YAML 用 `cordis-composition-reference`，设计工具描述用 `agent-experience`。通过 Cordis Inspect 查用到的实际接口；在独立测试实例中挂载开发包。在真实桌面安装或启用插件是单独的操作。
- 排查故障时记录触发操作、宿主与插件版本、目标 profile 和第一条相关错误。优先读取具体组件的诊断，避免把整份会话历史或账户文件送入上下文。

### 卡片：哪些要等用户，哪些不用

卡片一发出就显示给用户：本轮进行中出现在输入框上方，本轮结束后留在对话里。数量不限。

| 需要什么 | 用什么 | 发出后 |
| --- | --- | --- |
| 继续之前必须由用户提供的信息或决定 | `ask_user` 提问卡（单选、多选或文本，标出推荐项） | 说一句在等什么，结束本轮 |
| 用户对你展示的结果做选择 | `ui_card` 加 `choice` 块和带 `reply` 的按钮 | 同上，等待选择 |
| 展示结果、进度或状态 | `ui_card` 展示块，没有 reply 按钮 | 继续工作 |
| 用户之后可能触发的安全操作（停服务、重跑） | `ui_card` 带 `run` 的按钮，需要时加 `keep` | 继续工作 |

回答以 `[Card answer: …]` 消息送达，按钮选择以 `[Card button: …]` 送达。不要在等待期间基于假设的答案继续做依赖它的事。

### 审批与失效工具

- 带 `sandbox_permissions` 的 shell 调用会立即返回 `approval-N` 任务号，用户同时看到审批框。告诉用户在等什么审批，继续不依赖它的工作；结束本轮前用 `job_output`（`wait: true`）读一次结果。被拒或撤回就是最终结果，不要换个写法重试。
- 第三方工具因提供方不可用或反复失败被隔离后，本会话内不要重试、探测或修复它，除非用户要求；改用可用的替代或官方工具，收尾时列出失效的工具和所属插件。只有用户点「重载所有工具状态」才会解除隔离。

### 常见误用

| 误用 | 改为 |
| --- | --- |
| 翻 DSH 安装目录或本插件源码来了解功能 | 读系统提示、SDK 声明和本篇；宿主事实读 `dsh-doc` |
| 用猜的参数试调工具 | 先读工具声明 |
| 长时间前台等待或 sleep | 改成后台任务，然后继续或结束本轮 |
| 在正文里提问，或把卡片里的问题再用文字问一遍 | 发一张提问卡，然后等 |
| 直接修改设定卡（R） | 用 `project_cards propose`，由用户批准 |
| 没跑过就说测试通过 | 实际运行，或写明「未验证」 |
