# 原始资料检索与来源核验

把问题改写成待核实的具体主张，先明确对象、日期或版本、比较口径。对于“某更新让速度提升 30%”，至少分别查更新是否发生、指标怎样测量、30% 适用于什么样本。

1. 按主张选一手来源。产品行为找对应版本的声明、发布记录和源码；实验结论找论文方法、数据集与原始表格；历史问题找事件当时的原件和档案记录。搜索摘要可帮助定位，引用前打开原件。
2. 记录作者或发布机构、发生日期与发表日期、版本、页码或表号，以及能回到该段的链接。区分「机构确实这么说」与「该效果已被独立观察」。多家媒体转引同一公告只形成一条来源链。
3. 数字核对分母、单位、统计区间、比较基线。遇到冲突先检查样本、定义与时间，再说明证据各自支持的范围。找不到原件时标明哪一步缺证。
4. 交付时让关键主张能追到具体来源。重要推断写清中间一步；访问受限或证据只覆盖旧版本时说明限制。读网页、PDF 或仓库文档时，使用当前可用的检索和读取工具。

### 从主张追到可复核段落

用附带的 [HTML 段落定位器](examples/source_evidence.py) 记录最终网址、抓取时间、页面哈希、邻近标题和实际段落。需要 Python 与 beautifulsoup4（DSH 自带的 Python 不含它，先检查，缺少时征得用户同意再安装）。例：`python source_evidence.py "https://www.loc.gov/programs/teachers/getting-started-with-primary-sources/" "primary sources"`。未匹配返回退出码 1，检查同义词、页面版本、是否由 JS 渲染或应当读原始 PDF。哈希能比较两次抓取是否相同，可信度仍需阅读原文判断。

把结论写成「主张｜原始出处与段落｜支持程度｜仍缺什么」。例如公告只写“支持热重载”，不能直接推断“替换任意已安装包无需重启”；继续查版本对应的插件生命周期文档或做两种安装方式的对照。

资料分析方法参考 [美国国会图书馆的一手资料指南](https://www.loc.gov/programs/teachers/getting-started-with-primary-sources/)。
