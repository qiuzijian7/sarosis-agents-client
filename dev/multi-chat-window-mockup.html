我们项目的 API 应该用 RESTful 还是 RPC 风格？给个建议
C
这取决于你的使用场景。两种风格各有优势：

RESTful 适合：

  • 资源 CRUD 操作（文件、用户、订单）
  • 需要 HTTP 缓存语义
  • 面向外部公开 API

RPC 适合：

  • 动作/命令型操作（执行、转换、计算）
  • 内部微服务通信
  • 需要强类型 schema
对于 Sarosis 的场景，我建议混合方案：商城用 RESTful（资源 CRUD），Agent 执行用 RPC（动作驱动）。
