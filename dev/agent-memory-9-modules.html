1. 记忆 Memory

4-Tier 分层记忆模型 — 源文件: memoryProvider.ts

核心机制

  • Working — 当前会话原始对话流，每轮 fire-and-forget 写入
  • Episodic — L1 自动提取（每 3 轮触发），结构化长期事实
  • Semantic — LLM 跨会话固化，稳定概念与知识
  • Procedural — XML <procedures> 解析，可复用工作流步骤
  • 缓存优化 (P0-P13): 跨请求结果缓存、SessionContextCache、注入幂等去重、BM25 前缀二分、同义词加权、三因子保留评分、Core/Archival 分层 + auto-page

使用说明

// 写入
await provider.writeMemory(agentId, {
  type: 'working', content: '...',
  metadata: { toolCallId: 'tc-1', pinned: true }
});

// 加载上下文
const ctx = await provider.loadContext(
  agentId, sessionId, query,
  { scope: 'agent' }
);

// 搜索
const results = await provider.searchMemory(
  agentId, 'typescript config'
);

2. 槽位 Slots

可编辑固定记忆 — 源文件: slots.ts

核心机制

  • 8 个固定槽位: persona、user_preferences、project_context、tool_guidelines、guidance、pending_items、session_patterns、self_notes
  • 每个槽有 sizeLimit (500~2000 字符) 和 pinned 标志
  • pinned 槽位 不受 token budget 截断，优先注入到 LLM 上下文
  • 支持运行时动态 pin()/unpin()；读写都有 sizeLimit 强制截断
  • 懒加载初始化: 首次 _ensure() 时按 SLOT_DEFINITIONS 创建空槽

使用说明

const slots = provider._slots;

// 设置 + 追加
slots.set(agentId, 'persona',
  'You are a senior developer');
slots.append(agentId, 'user_preferences',
  'tab width: 4 spaces');

// Q3: 运行时固定
slots.pin(agentId, 'project_context', true);

// 构建上下文 (pinned 优先)
const ctx = slots.buildContext(agentId);
slots.list(agentId); // 列出全部
8 个固定槽 sizeLimit 截断 pinned 优先

3. 教训 Lessons

经验沉淀与衰减 — 源文件: lessons.ts

核心机制

  • 自动提取: 正则匹配 "should/must/always/never" 模式 + 错误模式 (error/fail/crash)
  • 衰减模型: Ebbinghaus 遗忘曲线 — 每 60 天衰减一次 (factor=0.95)
  • confidence(t) = max(0.2, initial × 0.95^periods)
  • 强化: 每次 reinforce() 调用 confidence+0.05 (封顶 1.0)
  • 软删除: delete() 标记 deleted=true，不物理删除
  • 24h 节流: 同一 agent 同一窗口不重复提取

使用说明

const le = provider._lessons;

// 自动提取
const nl = le.extract(agentId, entries);
le.reinforce(agentId, lessonId);
le.delete(agentId, lessonId);

// 手动添加
le.add(agentId, content, context, tags);

// 查询
le.getTopLessons(agentId, 5);
le.search(agentId, 'transaction');
正则匹配提取 Ebbinghaus 衰减 24h 节流

4. 固化 Consolidation

4-Tier 跨层提取 — 源文件: consolidation.ts

核心机制

  • LLM 驱动管道: ConsolidationPipeline 分三步提取: Episodic → Semantic → Procedural
  • XML 解析: LLM 返回 <facts> / <procedures>，程序化解析 + 规则回退
  • 阈值控制: Episodic ≥3 轮对话; Semantic ≥5 条 episodic; Procedural ≥3 条 semantic
  • 去重: 相同 fact 指纹去重（内容哈希）
  • setSummarizer(fn) 注入自定义 LLM 实现

使用说明

const pipe = new ConsolidationPipeline();
pipe.setSummarizer(async (prompt) => {
  // 调用 LLM → 返回 XML
  return '...';
});

await pipe.consolidateEpisodic(agentId, entries);
await pipe.consolidateSemantic(agentId);
await pipe.consolidateProcedural(agentId);

// 查询结果
pipe.getSemantic(agentId);
pipe.getProcedural(agentId);
pipe.buildContext(agentId);
LLM 驱动 XML 解析 规则回退 阈值触发

5. 审计 Audit

全量操作日志 — 源文件: auditLog.ts

核心机制

  • 记录 16 种 AuditOperation: write/search/delete/decay/sweep/reinforce/consolidate/session_start/end/contradiction/flush/dedup_skip/retention/cascade/skill_extract/cache_hit
  • 每条记录: {id, timestamp, operation, agentId, targetIds, details}
  • getSummary() 按操作类型聚合计数
  • 配合 _eventBus 在关键操作后自动触发

使用说明

const audit = provider._audit;

// 自动记录（内部调用）
audit.record('write', agentId, [entry.id], {
  contentLength: 200, source: 'l1_auto'
});
audit.record('cache_hit', agentId, [], {
  query: 'config', type: 'context_result'
});

// 查询统计
const summary = audit.getSummary();
// { write:42, search:15, cache_hit:8, dedup_skip:3 }
16 种操作 自动记录 getSummary 统计

6. 钩子 Hooks

生命周期事件订阅 — 源文件: hooks.ts

核心机制

  • 事件驱动: session_start、session_end、prompt_submit、subtask、tool_call、stop 等
  • trigger() 同步触发所有已注册处理器
  • triggerAndCollect() 异步触发并收集 HookResult (observeEntries + finalMessages)
  • register() 注册钩子处理器回调
  • 配合 _triggerSystem (fireSync) + _eventBus (emitSync) 双通道

使用说明

const hooks = provider._hooks;

// 注册处理器
hooks.register('session_end', async (ctx) => {
  // { agentId, sessionId, timestamp }
  await cleanup(ctx.agentId);
});

// 同步触发
hooks.trigger('session_start', { agentId, sessionId });

// 异步收集结果
const result = await hooks.triggerAndCollect(
  'prompt_submit', { agentId, userMessage: '...' }
);
事件驱动 同步/异步 双通道触发

7. 提交 Commits

记忆与代码关联 — 源文件: commits.ts

核心机制

  • 将记忆条目与 Git 提交关联，记录每条记忆的代码变更上下文
  • link() 关联 commit hash + filePath + diffSummary
  • getHistory() 查询某条记忆的所有关联提交
  • 支持跨 session 追溯：记忆 → 哪次提交引入 → 改动了什么

使用说明

const commits = provider._commits;

// 关联记忆与提交
commits.link(agentId, memoryId, {
  commitHash: 'abc123',
  filePath: 'src/memoryProvider.ts',
  diffSummary: 'Added auto-page mechanism'
});

// 查询历史
const history = commits.getHistory(memoryId);
Git 关联 跨 session 追溯

8. 报告 Report

记忆健康度报告 — 源文件: report.ts

核心机制

  • 聚合 agent 记忆系统全维度健康数据
  • 分布: totalMemories / byType (working/episodic/semantic/procedural)
  • 质量: avgStrength / avgImportance / decayRatio
  • 热点: topConcepts (Top 10 概念频率) / topLessons (Top 5 教训)
  • 活动: recentActivity (最近 24h 写入/读取/搜索)
  • 参数: includeRaw (是否返回原始条目), maxEntries

使用说明

const report = provider.generateReport(
  agentId,
  { includeRaw: false, maxEntries: 100 }
);

// 输出
{
  agentId: 'agent-1',
  totalMemories: 142,
  byType: { working:30, episodic:80,
    semantic:20, procedural:12 },
  avgStrength: 0.68,
  topConcepts: [
    {concept:'TypeScript',frequency:45}
  ],
  topLessons: [...],
  recentActivity: {...}
}
全维度健康数据 按需输出原始条目

9. 技能 Skills

可复用知识沉淀 — 源文件: skillExtract.ts

核心机制

  • 指纹去重: skillFingerprint(title, trigger) — 相同指纹的技能被强化而非重新创建
  • SKILL.md 生成: frontmatter (title/slug/confidence) + markdown body (编号步骤)
  • 写入路径: ~/.saros/skills/<slug>/SKILL.md
  • 中文映射: generateSlug() 自动将中文标题映射为英文 slug
  • CRUD: extract / update / delete / markWritten / markUsed / getStats

使用说明

const se = provider._skillExtractor;

// 从会话提取
const skill = se.extract({
  sessionId, agentId,
  observations: [{
    content: 'Step 1: parse config',
    timestamp: Date.now()
  }],
  trigger: 'config-update'
});

// 强化 + 标记已写入
se.reinforce(skill.id);
se.markWritten(skill.id);

// 生成 SKILL.md
const md = generateSkillMd(skill);
// → ~/.saros/skills/config-update/SKILL.md
指纹去重 SKILL.md 自动生成 中文 slug 映射 CRUD 完整
