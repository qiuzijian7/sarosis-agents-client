知识库构建流程全景

VsSaros · Agent Studio · 知识库（KB）—— 截止 2026-09-24 的实现。代码位置： src/vs/sessions/contrib/agentStudio/browser/kbImportController.ts（构建主体）、 views/knowledgeBaseView.ts（视图入口）、 resources/.agents/skills/kb-build/SKILL.md（构建规则手册）、 browser/providers/tool/kbOrganizeTools.ts（目录整理工具）。 函数级输入/输出详见 docs/kb-batch-build-callchain.md。

一句话版本：点「批量构建库」= 检查全部、只构建增量 —— 把「库」里需要构建的素材清单交给 一个知识库专家 agent 会话（聊天框里可见），agent 按 kb-build 技能自己读素材、自己写笔记到「笔记」区， 随后在同一会话里维护 知识体系.md 并可重构目录；宿主最后做缓存、补链、门控、导航收尾。

0. 角色与约定

概念是什么落点 / 载体
库数据源层：素材（PDF 转出的 md、导入的链接…）<vault>/库（raw/…）
笔记知识体系层：构建产物（结构化笔记）<vault>/笔记/…
构建缓存「素材路径 → 笔记路径」映射 + 新鲜度判定（素材 mtime > 笔记 mtime ⇒ 重建）<vault>/.kb-build-cache.json
技能 kb-build构建规则手册（落点/frontmatter/图片/重构约定）；消息里只带数据不带规则resources/.agents/skills/kb-build/SKILL.md
kb_organizeagent 的目录整理工具（小规模 ≤10 项直接动手；checkpoint + vault 外备份，可 undoAll）providers/tool/kbOrganizeTools.ts
KB_REORG大规模（>10 项）重构的计划通道：LLM 出计划 → 宿主校验/备份 → 用户确认 → 执行kbImportController.ts

入口走向说明

2. 批量构建主流程

① 视图侧准备 _batchBuildAll()视图层
前置检查（库/配置）→ 所有库文件行标记「构建中」→ activitybar 徽标「building」→ 调控制器
↓
② 待构建清单（pending） _collectPendingSources()宿主
输入：vault 根。产出：{ libDir, notesDir, pending[], cache }。
· 前置转换：PDF/docx → 同目录同名 .md（仅当源比 md 新才重提取；扫描件不写空 md）主进程 python + PyMuPDF4LLM
· 枚举「库」内全部 .md（跳过 dot 文件与 index/overview/insights/知识体系 等系统文件）
· pending 判定（任一成立即构建）：缓存无此素材 ／ 缓存的笔记已不存在 ／ 素材 mtime > 笔记 mtime（素材构建后又被改过）； 同时排除「本身就是构建产物的笔记」（缓存值集合，防笔记→笔记递归）
↓
③ 打开构建会话 _ensureKbBuildChatSession()宿主
createAgentSession('knowledge-base-expert', '知识库构建 · MM-DD HH:mm')（真实登记 ⇒ 会话列表可见） → NativeChatEditorInput.create(...) + openEditor(pinned) 打开绑定该 session 的聊天页签。
批量 = 整批共用一个会话；同会话跑下一个素材前 replaceHistory 清历史（否则全量历史会当 priorMessages 下发 ⇒ 平方膨胀 + 重复输出旧 FILE 块）
↓
④ 准备数据宿主
_getSchemaStatic() 确保 <vault>/kb-schema.json 存在（agent 自己 file_read）； _describeNoteTree() 渲染笔记区全量目录树（含手写区，深度 ≤4 / ≤400 行）； 目录快照（事后 diff 用）
↓
⑤ Phase 1：agent 自主构建笔记agent（kb-build 技能）
宿主只发一条短消息（触发语 + 素材清单[绝对路径+sources 引用] + 目录树 + 3 条硬约束）， 经 explicitSkillIds: ['kb-build'] 挂载技能全文；⚠ 不传 chatOnly ⇒ 允许写工具。
agent 依次：file_read 读素材 → file_read kb-schema.json → 按落点规则 file_write/patch 写笔记 （优先复用既有目录、能复用绝不新建、同名就地更新；frontmatter 必含 type/title/sources；图片相对路径 assets/…；可选 vision_analyze 逐张看图）
↓
⑥ Phase 2：维护知识体系agent（kb-build 技能）
宿主发一句话触发。agent：search_files 列目录 → 创建/完善 笔记/知识体系.md （目录总览 + 学习路径 + 知识缺口 + 结构评价）；如需重构 ⇒ 见 §3
↓
⑦ 宿主收尾宿主
产出归集（双保险）：工具结果串 wrote N chars to <path> ∪ 笔记区目录前后 diff； KB_ORGANIZE_RESULT 行 ⇒ 修正缓存中被移动的路径；
· 缓存回填：读每篇新笔记的 frontmatter sources 反查来源 → 写 .kb-build-cache.json
· 补链 _enrichNewNotes（整词命中其它笔记标题 ⇒ 包成 [[标题]]，只改本次产物）
· 门控 applyDeabstractionGating（概念/对比/综合/实体类：sources ≥2 ⇒ active，否则 pending）
· 导航 maintainKbNavigation（重写 index.md / overview.md / insights.md / 各主题 .overview.md）
· requestKbRefresh() + 通知「知识库构建完成：新增/更新 N 篇笔记…」
↓
⑧ 视图收尾视图层
清「构建中」标记与进度 → 有产出才亮「有新增」徽标 → 刷新「笔记」「库」两分区 → 搜索索引置脏
「检查全部 vs 只构建增量」的成本：未变化的文件只做「枚举 + 读缓存 JSON + mtime 比较」—— 无 LLM、无 agent 轮次； 只有 pending 里的文件才会让 agent 动手。库文件右侧徽标（待构建/已建笔记）只是展示层标签（按缓存判定），与本次是否构建是两回事。

3. 目录重构：两条通道

kb_organize（工具直动）KB_REORG（计划通道）
适用小规模（≤10 项）大规模（>10 项）
谁执行agent 自己（在会话里连续搬）宿主 _applyReorgPlan()
确认无需逐条审批（沙箱内写默认免审批）通知卡片「应用重构 / 跳过」用户确认
安全域限定「笔记/」区内；拒绝 ..；to 必须不存在（不覆盖）；执行前 checkpoint（聊天页签 undoAll）+ 备份到 vault 之外（备份失败就跳过该项）；「删除」= 移入备份目录（回收站语义）
联动执行后宿主同步修正 .kb-build-cache.json 中被移动的路径 + 重跑导航/门控
为什么需要工具而不是让 agent 用 terminal：agent 工具集里没有移动/删除/重命名工具； terminal 属 execute 档会逐次弹审批（不适合无人值守）⇒ 提示词里禁用 terminal，搬运一律走 kb_organize / KB_REORG。

4. 三条构建路径的差异

路径读素材提炼写盘过程可见触发
buildPendingAsAgentSession（批量默认）agent（file_read，宿主只给路径）agent 多轮（允许写工具）agent（file_write）聊天页签实时可见批量构建库按钮
buildNotesFromLibrary（单文件右键，agentic）宿主把原文塞进 promptagent 多轮（chatOnly:true）宿主（解析回传的 FILE 块）聊天页签可见单文件右键
_buildNoteCore（降级/直连）宿主2 次直连 LLM（STAGE1 分析 + STAGE2 FILE 块）宿主（_writeFileBlocks）不可见降级 / 静态入口 / 单测
三条路径的最终产物形态一致：都落「笔记」区、都有 sources frontmatter、都经缓存/补链/门控/导航收尾；差别只在「谁读、谁写、过程能不能看见」。

5. 产物清单

产物落点执行者

结构化笔记（frontmatter: type/title/sources/status）笔记/<已有目录（含手写层级）>/…agent（新路径）/ 宿主（旧路径）
知识体系.md（目录总览 + 学习路径 + 缺口 + 结构评价）笔记/知识体系.mdagent（Phase 2）

构建缓存<vault>/.kb-build-cache.json宿主
构建会话（全程可见）+ checkpoint（可 undoAll）聊天页签 / 会话历史宿主 + agent
重构备份（仅重构时）<vault 父目录>/<vault 名>-backup-…/宿主 / kb_organize

6. 排障速查

现象先看这里
点了没反应无待构建素材会发 Info 通知；未配「知识库专家」会提前中止并提示（去设置页配 Provider/模型）
该构建的素材被跳过.kb-build-cache.json 里是否有它的条目；素材被改过（mtime 比笔记新）⇒ 会自动重建
笔记没落进既有目录（另起平行树）看会话里 Phase 1 消息是否带了目录树；技能是否挂上（日志 [AgentDriver] Explicit skills added: kb-build）
agent 写不了文件vault 须在沙箱允许根（agentStudio.kb.vaults[].customPath 注册过）；否则弹「安全沙箱限制」卡片
聊天框看不到过程必须走 IAgentChatService.sendMessage（driver 只产流、不广播）；页签必须绑定同一 sessionId
来源显示失效 / 笔记是孤儿库分区右键「修复（清缓存孤儿 / 失效来源）」；体检（kbLint）跑 missing-source / broken-link
双链面板显示无法读懂的 URI / 大量 ⚠已修（路径形/URI 形目标归一到文件名匹配）；重启重建索引后刷新
