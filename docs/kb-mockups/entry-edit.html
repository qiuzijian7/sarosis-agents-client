背景

Agent Studio 在 2026 年初引入知识库能力时，面临一个基础选择：新的界面能力应当落在 workbench 原生视图，还是落在 webview 中。

决策结论
导航与轻量列表放在 workbench 原生视图，富文本编辑与图谱渲染放在 webview，两者通过统一的 KB 服务层共享数据。

方案对比

  • 纯原生：启动快、跟随主题天然，但富文本编辑器需自行实现。
  • 纯 webview：可复用 React 生态，但列表页常驻会有内存开销。
  • 双轨（采纳）：各自承担擅长的部分。

数据同步契约

两轨通过 KnowledgeBaseService 暴露的接口通信，参见 kb_search 混合检索打分公式与调参记录。

interface KnowledgeBaseService {
  queryNotes(notebookId: string): Promise<KbNote[]>;
}
