# 右键菜单：现状对比 ComfyTV 与复刻方案

> 2026-08-12 · 基于 `@comfyorg/litegraph@0.17.2`、ComfyUI 前端 `comfyui_frontend_package@1.48.7`、ComfyTV 源码（`G:\CustomWorkspaces\AIProjects\ComfyTV`）逐项比对。
> ComfyTV 自身**没有任何右键菜单代码**（`onNodeContextMenu`/`getMenuOptions` 均未覆写）——它的右键体验 = ComfyUI 前端在 litegraph 之上的默认菜单。所以"复刻 ComfyTV 右键菜单" = "复刻 ComfyUI 前端的菜单层"。

---

## 1. 三层菜单体系（谁在管什么）

```
┌──────────────────────────────────────────────────────────────┐
│ ComfyUI 前端（ComfyTV 环境）                                  │
│  ContextMenuTranslation 包装 getCanvas/getNodeMenuOptions     │
│  注入扩展菜单项 + i18n 翻译 + Add Node→NodeLibrary 面板        │
├──────────────────────────────────────────────────────────────┤
│ litegraph 0.17.2（我们与 ComfyTV 用的是同一层的类）            │
│  内置：节点菜单 / 画布菜单 / 端口菜单 / 组菜单                 │
├──────────────────────────────────────────────────────────────┤
│ 我们的 React 覆盖层                                           │
│  NodeContextMenu(Add Node 搜索) / GroupMenu+GroupEditPopup    │
└──────────────────────────────────────────────────────────────┘
```

**关键结论**：litegraph 层两边的"原料"完全相同（同一版本类库）。差异全在我们是否消费了它、以及上层补了什么。

## 2. 逐场景差异矩阵

| 右键场景 | 我们 | ComfyTV（ComfyUI 前端） | 差异等级 |
|---|---|---|---|
| **节点** | ❌ 无节点菜单——直接弹画布 Add Node 搜索 | ✅ 完整节点菜单（见 §3） | 🔴 重大 |
| **画布空白** | ✅ Add Node 搜索菜单（React 340px，分组+搜索框） | ✅ litegraph Add Node/Add Group + ComfyUI 扩展项 + NodeLibrary 面板 | 🟡 体验差异 |
| **组** | ✅ Edit Group…/Pin/Remove（3 项） | ✅ litegraph group 菜单：Pin ┄ Title/Color/Font size ┄ Remove | 🟡 缺 Title/Color/Font size |
| **端口/引脚** | ❌ 无 | ✅ 端口右键：Disconnect Links / Remove Slot / Rename Slot | 🔴 缺失 |
| **连接线** | ❌ 无 | ✅ 连线右键 = 断开（ComfyUI 行为） | 🔴 缺失 |
| **多选** | ❌ 无 | ✅ litegraph：Convert to Subgraph 🆕 / Align / Distribute Nodes | 🟡 缺失 |
| **widget 右键** | ❌ 无 | ✅ Convert to Input / Convert to Widget（widgetInputs.js） | 🟢 可缓 |
| **Reroute** | ❌ 无 | ✅ Delete Reroute | 🟢 可缓 |

> 🔴 = 用户可感知的缺失；🟡 = 有但不对齐；🟢 = 可选增强。

## 3. litegraph 0.17.2 内置菜单完整清单（复刻蓝本）

### 3.1 节点右键 `LGraphNode.getMenuOptions` 默认分支（es.js:13883）
```
Inputs  (禁用占位，子菜单)
Outputs (禁用占位，子菜单)
──────────────
Convert to Subgraph 🆕
Properties (子菜单)
Properties Panel
──────────────
Title                    ← 改标题
Mode (子菜单)            ← Always/On Event/On Trigger/On Pause…
Resize / Collapse / Pin  ← 依 resizable/collapsible 条件出现
Colors (子菜单)          ← node 颜色预设
Shapes (子菜单)          ← 圆角/形状
──────────────
Clone
Align Selected To / Distribute Nodes   ← 多选时才出现
──────────────
Remove
```
**三个扩展钩子**（ComfyUI 与我们都可用）：
- `node.getExtraMenuOptions?.(canvas, options)` → 前置追加
- `graph.onGetNodeMenuOptions?.(options, node)` → 末尾追加
- 多选 Align 在 `selected_nodes.size > 1` 时自动出现

### 3.2 画布空白右键 `getCanvasMenuOptions`（es.js:13845）
```
Add Node (子菜单) / Add Group
+ 多选时：Convert to Subgraph 🆕 / Align
```
`processContextMenu`（es.js:14002）在画布分支还会按需前置：
- Reroute 上右键 → `Delete Reroute`
- 组上右键 → `Edit Group`（子菜单=group.getMenuOptions）

### 3.3 组菜单 `group.getMenuOptions`（es.js:1647）
```
Pin/Unpin ┄ Title / Color(子菜单) / Font size ┄ Remove
```

### 3.4 端口菜单（es.js:14014，`processContextMenu` slot 分支）
```
Disconnect Links   ← 有连线时
Remove Slot        ← slot.removable
Rename Slot        ← !nameLocked
```

### 3.5 触发时机（与我们冲突的关键）
- es.js:9842：`pointer.onClick ??= () => this.processContextMenu(node2, e2)` —— litegraph 在**右键点击节点时**（`processPointerDown` 绑定 onClick）自动弹内置节点菜单。
- 我们当前在 React `onContextMenu` 里 `LiteGraph.closeAllContextMenus?.(window)` 把它清掉，然后只弹画布 Add Node 菜单 → 节点右键被吞。

## 4. ComfyUI 前端在 litegraph 之上做了什么（GraphView 反编译）

`useContextMenuTranslation()`（`main` chunk，GraphView-BbJsI-mF.js）：
```js
yi.install(_r.prototype, 'getCanvasMenuOptions')  // 包装画布菜单
getCanvasCenterMenuOptions = (...t) => {
  n = 原 getCanvasMenuOptions()
  n.push(...collectCanvasMenuItems(canvas))        // 扩展注册项
  n.push(...extractLegacyItems('getCanvasMenuOptions')) // 老式扩展钩子
  n.forEach(i => i.content && (i.content = i18n(`contextMenu.${i.content}`)))
}
yi.install(_r.prototype, 'getNodeMenuOptions')    // 包装节点菜单
getNodeMenuOptionsWithExtensions = (...e) => {
  n = 原 getNodeMenuOptions()
  n.push(...collectNodeMenuItems(node))           // 扩展注册项（Convert to Input 等）
  n.push(...extractLegacyItems('getNodeMenuOptions'))
}
X.ContextMenu 覆写：title 按 nodeDef display_name 翻译
```
要点：
1. **不替换 litegraph 菜单，只追加**——默认项全保留。
2. `collectCanvasMenuItems/collectNodeMenuItems` 是 ComfyUI 前端的统一扩展点（TS API，新插件系统）。
3. `contextMenu.*` i18n key；Convert 类菜单按 node 的 input/widget 实际名称生成。
4. Add Node 不再是子菜单——点开后打开 NodeLibrary 搜索面板（新式侧栏，不滚动 300 项）。

## 5. 复刻方案

### 5.0 总体架构（与现状不冲突，渐进落地）

```
新文件：
  menuShell.tsx      通用右键菜单外壳（样式 = 现有 NodeContextMenu/GroupMenu 的统一版）
  nodeActionsMenu.tsx  NodeActionsMenu（节点右键菜单）
  menuItems.ts       纯函数：buildNodeActions(node, ctx) / buildCanvasActions(ctx)
  onNodeContextMenu  prop（LiteGraphCanvas → WorkflowEditorPanel）
改动：
  LiteGraphCanvas.tsx   onContextMenu 增加节点优先判定（graph.getNodeOnPos）
  WorkflowEditorPanel.tsx  ctxMenu 状态机扩展 {kind:'node'|'canvas'|'group'}
  NodeContextMenu.tsx / groupMenu.tsx  改用 menuShell（外观统一）
```

**触发与命中判定**（LiteGraphCanvas `onContextMenu`，当前 907–927 行）：
```
1. graph.getNodeOnPos(gx, gy) 命中 → onNodeContextMenu(node, …)  ← 新增，最高优先
2. graph.getGroupOnPos 命中 → onGroupContextMenu（现状）
3. 否则 → onCanvasContextMenu（现状）
```
保持现有 `closeAllContextMenus`（继续清 litegraph 内置菜单，否则两套菜单叠出）。

**右键即选中**（对齐 ComfyUI）：节点未选中时右键先 `liteCanvas.selectNode` 再弹菜单，多选右键可对选中集批量操作。

### 5.1 节点右键菜单（M1 核心）——对齐 §3.1 + 我们的语义

分组布局（自上而下）：

| 分组 | 菜单项 | 实现 |
|---|---|---|
| 运行 | ▶ Run Node · ▶ Run Upstream/Downstream（可选） | 复用 `onNodeRun` / 新增 graph 遍历 |
| 编辑 | ✏️ Edit Title… · 📐 Collapse/Expand · 📌 Pin/Unpin | Edit Title→复用 NodeEditorPopup（对齐 `Title`）；Collapse/Pin 直调 litegraph `node.collapse()`/`pin()` |
| 复制 | ⧉ Clone · Copy · Cut · Paste | 复用现有剪贴板通道（若未实现→M2） |
| 编组 | Add to Group / Ungroup | 多选才有 Add to Group；M2 |
| 外观 | 🎨 Colors（子菜单：node_colors 预设 + 自定义）· Shapes | 对齐 litegraph `onMenuNodeColors` |
| 属性 | ⚙ Properties / Properties Panel | 对齐我们的 NodeEditorPopup（schema 参数面板） |
| 删除 | 🗑 Remove（Confirm） | 对齐 `onMenuNodeRemove` |

**跳过**：Convert to Subgraph（无子图能力）、Mode（执行器无此语义）、Advanced Widgets（无）。

**schema/native 差异化**：
- schema 节点（ComfyTV/Saros 类）：Properties 打开 NodeEditorPopup；不提供端口级操作。
- 旧 `Saros.*` 节点：无 spec，右键菜单只给 Remove（加载即弃策略的兜底）。

### 5.2 画布右键菜单（M1 增强）——保留搜索 + 补核心项
```
🔍 Add Node…        ← 打开现有搜索菜单（不改默认行为）
⧉ Paste             ← 剪贴板（若已支持）
▦ Add Group
──────────────
⚡ Run Workflow      ← Ctrl+Enter 命令入口（对齐 ComfyUI "Queue prompt"）
🔃 Reset View        ← litecanvas.ds 复位（对齐 ComfyUI 画布菜单）
```
多选时追加：`Align`（对齐算法参照 litegraph `onGroupAlign`）。原"Add Node 即菜单"改成"Add Node…→ 打开搜索层"。

### 5.3 组菜单补齐（M2）——对齐 §3.3
现状 3 项 → 补：`Title`（改标题，直接调 GroupEditPopup）、`Color`（子菜单=GROUP_COLORS 预设，复用 GroupEditPopup 色板）、`Font size`（数字输入→复用 GroupEditPopup）。

### 5.4 端口/连线右键（M2）
- **连线右键 = 断开**：`graph.removeLink(link.id)`（对齐 ComfyUI；当前无右键连线逻辑）。
- 端口右键：仅 **Disconnect Links**（schema 端口由 spec 定义，Remove/Rename 会破坏一致性 → 禁用并说明）。

### 5.5 UI 规格（与现有视觉统一）
```
外壳：背景 #1f1f1f，border 1px rgba(255,255,255,0.12)，radius 8，
      shadow 0 8px 28px rgba(0,0,0,0.6)，zIndex 100
标题区：节点 title（schema 用 spec.title），大写 10px 灰
菜单项：12px，padding 6px 10px，hover rgba(255,255,255,0.08)，disabled #777
分隔线：1px rgba(255,255,255,0.08)
子菜单：右箭头 ▸，悬停侧滑（M3）
定位：fixed + 视口钳制（复用 NodeContextMenu 算法）；Esc 关闭
```

### 5.6 数据与测试
- `menuItems.ts` 纯函数：`buildNodeActions(node, ctx) → MenuItem[]`（`{id, label, icon, danger?, disabled?, submenu?, onPick}`）；`ctx` 携带 `kind/schema?/selectedCount/pinned/collapsed`。
- 单测 `workflowComfyContextMenu.test.ts`：单节点/schema/原生/多选/无 spec 旧节点各自的菜单项快照；Collapse/Pin 文案随状态翻转；Remove 依赖 `removable`。
- e2e：右键节点 → 断言 NodeActionsMenu 出现 + 点 Collapse 后节点折叠；右键连线 → 断开断言。

### 5.7 冲突与风险
| 风险 | 处理 |
|---|---|
| litegraph 内置节点菜单先弹 | 保持 `closeAllContextMenus`（现有 912 行）；不覆盖 `getNodeMenuOptions`，避免与升级后行为耦合 |
| 右键与拖拽/双击冲突 | 只在 `button===2` 走菜单路径（现有判断）；右键即选中须在 pointerdown 之后（现有 contextmenu 时机 OK） |
| schema 节点端口删除导致 spec 失配 | 端口菜单只给 Disconnect Links |
| 多选右键批操作 | `selected_nodes` 集合遍历（对齐 litegraph Pin 的批量写法 es.js:13947） |
| 与 NodeEditorPopup 焦点冲突 | 菜单 zIndex 100 < popup 101，开子菜单/弹窗时先关菜单 |

## 6. 里程碑

| 里程碑 | 内容 | 工作量 |
|---|---|---|
| **M1** | 节点右键 NodeActionsMenu（运行/编辑/复制/外观/属性/删除）+ 画布菜单核心项 + `onNodeContextMenu` 通道 + menuShell 统一外观 + 单测/e2e | 中 |
| **M2** | 组菜单补齐（Title/Color/Font size）+ 连线右键断开 + 端口 Disconnect + 多选 Align/批量 Pin | 中 |

> 建议从 M1 开始：它补的是用户最可感知的"右键节点没反应"空白，且不触碰现有画布 Add Node 搜索习惯（保留为 Add Node… 入口）。
