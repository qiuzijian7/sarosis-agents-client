读图要点

  • 写入需人工确认是本系统的主轴：AI 的候选事实先落 SUGGESTIONS.jsonl，经用户 approve 才 store.add 进主轨；keyWriteMode 决定 KEY 轨走队列还是直写。
  • 注入是「变化才重发」的文本快照：systemPrompt.context 的 memory:snapshot 由 DSH 物化为 user-role 尾部消息，文本不变就不重发，保住 LLM prefix cache。没有落盘的冻结快照文件。
  • 物理分区按 cwd 上溯 git 根的 hash，不是 workspaceId；deriveMemoryScope() 只提供展示元数据，不改路径。
  • 相邻检索工具 de_session_search / memory_evolve_search_local_files 读的是会话历史与本地文档，不读记忆轨，图上以灰色旁路表示。

推断与「未发现」边界（刻意不画进主图）

项结论等级
locate() 的 target 数实际是 6 个（memory/user/daily/bot/project/key）；「9+1」指 memory-tab.js 的 10 个文件页签行，不是 target 分支纠正
建议队列四态隐式状态：记录里没有 status 字段，由「在队列 / 已写主轨 / 已写归档」推导推断
后台自动审查进程不存在。审查是快照 due 文案驱动主 LLM 调 memory_suggest 的 prompt-driven 流程，真实事件是 agent/turn-stopping纠正
冻结快照 / session 结束 flush / compaction 前 flush未发现专门函数。frozen-ish 是 change-detected 文本注入；bot-history.flush 是 Git 提交刷新未发现
journal.jsonl / snapshots/ / summaries/ / workspace-index.json未发现（那是 ds-bot / P1 提案的结构，不是本系统现状）未发现
SessionStart / PostToolUse / PreCompact hook未发现这些名字；真实 ctx.on 事件见证据索引未发现
add() 的字符上限校验未发现实际判断，只有 store.js:5/978 的历史注释声称有；botMemoryCharLimit:2048 只作用于注入侧截断未发现
COI / Advisor 参与沉淀否：COI 只读注入三轨给外部 CLI，Advisor 独立评审，均不写 SUGGESTIONS.jsonl一手
为什么不引 Mermaid CDN：仓库现有 workflow-sequence-diagram.html / subagent-sequence-diagram.html 用 Mermaid@10 CDN，离线打开会是空图。本稿改为数据驱动自绘 inline SVG，双击本地文件即可渲染，并可一键下载 SVG 嵌入文档。
