§ 02

Agent 系统：不是"一个 AI"，是"一个团队"

多 Agent 协作

WorkBuddy/CodeBuddy 的 Agent 模式是单线程的——一个对话里只有一个 Agent 在工作。VsSaros 的 Agent 系统支持多 Agent 并发、委托、编排——你可以让一个 Supervisor Agent 把任务拆解成子任务，分发给多个子 Agent 并行处理，最后汇总结果。

AgentOS · 核心运行时
6 槽位 Agent 引擎
  • Model / Memory / Tool / Planning / Execution / Retrieval
  • AgentGraph 状态机驱动 ReAct 循环
  • 5 种可插拔 Loop 策略
  • 支持 Hermes / Graph / Delegation / ReadOnly / MIMO 模式
Supervisor · 委托模式
拆任务，派子 Agent
  • Supervisor 拆解复杂目标为子任务图
  • 子 Agent 独立上下文，互不干扰
  • 结果汇总与结构化输出
  • 人只在拍板环节介入
Crew · 团队协作
多 Agent 并行推进
  • DAG 任务编排，自动识别依赖
  • Canvas 可视化编排界面
  • 并发限流 FIFO，避免资源争抢
  • 统一 Agent 调度与生命周期管理
复杂任务处理
WorkBuddy / CodeBuddy：一个对话里逐条处理，任务多时只能排队。复杂任务需要人工拆解后分多次对话完成。
→
VsSaros：Supervisor 自动拆解目标 → 多个子 Agent 并行处理 → 汇总结果。一次输入，全自动推进。
上下文管理
WorkBuddy / CodeBuddy：单对话上下文有限，复杂任务容易超出窗口，需要人工总结后重新开始。
→
VsSaros：子 Agent 各自独立上下文，大文件自动拆给 subagent，避免主 Agent 上下文被撑爆。
失败恢复
WorkBuddy / CodeBuddy：Agent 失败时需要人工介入重新描述需求，之前的工作进度可能丢失。
→
VsSaros：DAG 编排下单个子任务失败只影响该节点，其余并行推进不受阻。分段重试，不用从头来。
关键优势WorkBuddy/CodeBuddy 的 Agent 本质上是"一个对话线程"——你可以创建多个对话，但它们之间不协作。VsSaros 的 Agent 是"一个可编排的工作流"——它们有分工、有协作、有生命周期管理。这在处理像"分支合并"这样需要大量并发工作的场景时，差距是数量级的。

§ 03

Skill 体系：能力不随对话消失，一次写好永久复用

可复用能力包

WorkBuddy/CodeBuddy 也有 Skill/Slash Command，但它们的 Skill 本质上是一个预定义的 Prompt 模板——执行时就是把一段文本注入到对话中。VsSaros 的 Skill 是一个完整的能力包：有版本管理、有使用追踪、有三层加载策略、有市场分发，而且是 Agent 直接调用的工具，不只是 Prompt 注入。

三层加载 · 灵活覆盖
内置 → 用户 → 运行时
  • 内置 Skill：项目级 .agents/skills/ 目录
  • 用户 Skill：~/.vssaros/saros/skills/ 个人配置
  • 运行时注入：对话中动态注册
  • 后注册覆盖同名，灵活可控
标准化格式 · SKILL.md
兼容 Hermes / Claude
  • YAML frontmatter 元数据定义
  • activation / match / category 精确触发
  • recommended_tools 工具绑定
  • Markdown body 为 Agent 执行指令
生命周期管理
安装 → 使用 → 追踪 → 更新
  • Skill 市场：搜索 / 安装 / 发布
  • 使用追踪：统计调用频率与成功率
  • 版本管理：升级不破坏已有工作流
  • 从对话中提取新 Skill
WorkBuddy / CodeBuddy SkillINPUT
# Skill 本质上是 Prompt 模板
触发方式   用户在对话框输入 /command
执行方式   将 SKILL.md 内容注入对话上下文
作用域     当前对话内生效，对话结束即消失
能力复用   跨对话需要重新触发

# 局限：
- 无法被 Agent 主动调用，只能人工触发
- 没有版本管理，更新靠覆盖文件
- 没有使用追踪，不知道哪些 Skill 真正有用
VsSaros SkillOUTPUT
# Skill 是 Agent 直接调用的能力包
触发方式   人工 /command 或 Agent 自动按需调用
执行方式   作为 Agent 的 Tool 被调度执行
作用域     跨对话持久化，注册后全局可用
能力复用   版本化安装，市场分发

# 优势：
+ Agent 可以自己决定何时调用哪个 Skill
+ 版本管理 + 使用追踪 + 市场分发
+ 三层加载策略：项目 → 用户 → 运行时
+ 从对话中提取 Skill，经验自动沉淀
关键优势WorkBuddy/CodeBuddy 的 Skill 是"给用户的快捷方式"——你记住一个命令，输入它，AI 帮你做一件事。VsSaros 的 Skill 是"给 Agent 的工具箱"——Agent 自己知道什么时候该用哪个 Skill，不需要你告诉它。而且 Skill 有版本管理，这意味着团队的 Skill 可以像代码一样 review、迭代、发布——这是真正的工程化能力复用。

知识库：团队的经验不会丢，新人来了直接搜

结构化知识管理

WorkBuddy/CodeBuddy 的"记忆"功能本质上是一个对话摘要存储——它记住你和 AI 聊过什么，下次能引用。VsSaros 的知识库是一个完整的知识管理系统：Obsidian 式 Vault + 代码图谱 + 向量检索 + 社区检测。代码怎么改、坑怎么踩、为什么这样设计——全部结构化沉淀，新人来了直接搜。

Obsidian 式 Vault
笔记 + 双向链接
  • 14 种笔记类型：entity / concept / source / query / comparison / synthesis 等
  • Wikilinks 双向链接，自动发现关联
  • 可配置分类体系 kb-schema.json
  • 别名管理 + 标签系统
代码图谱 · 235KB 引擎
代码即知识
  • LSP 驱动的符号搜索
  • 文件扫描 + Git 历史追踪
  • 增量更新，不重复分析
  • 类继承链 / 调用面自动构建
智能检索
不止是关键词匹配
  • Embedding 向量检索
  • LLM 驱动自动分类
  • 社区检测 / 聚类发现隐藏关联
  • 去重避免知识碎片化
知识存储
WorkBuddy / CodeBuddy：对话摘要存储在隐藏目录，格式不透明。跨项目不共享，换机器就丢失。
→
VsSaros：Markdown 文件存储在项目 .agents/vault/ 目录，Git 可版本化。知识库就是代码的一部分。
知识检索
WorkBuddy / CodeBuddy：基于对话历史的上下文匹配，只能检索"聊过什么"，不能检索"代码怎么写的"。
→
VsSaros：向量检索 + 代码图谱 + Wikilinks 双向链接。搜"这个接口怎么改的"能直接定位到相关笔记和代码。
知识共享
WorkBuddy / CodeBuddy：个人记忆，无法在团队间共享。每个人的 AI 助手都是"新人"。
→
VsSaros：Git 版本化的知识库，团队共享。新人克隆项目即获得全部团队知识沉淀。
关键优势WorkBuddy/CodeBuddy 的记忆是"个人笔记"——你一个人的 AI 助手越来越懂你，但团队其他人享受不到。VsSaros 的知识库是"团队 Wiki"——所有人的经验沉淀在同一个 Vault 里，Git 版本化，新人来了就能用。而且代码图谱让 AI 能理解的不只是文本，还有代码之间的关系——这是做代码级决策的基础。

§ 05

多窗口聊天：一个屏幕，多个上下文，互不干扰

会话管理革新

WorkBuddy/CodeBuddy 的聊天界面是单一面板——你可以在一个面板里切换对话，但同一时间只能看到一个。VsSaros 把聊天框设计成了独立的 Agent Sessions 工作台——三栏布局、多 Chat 聚合、Worktree 隔离、Chat 可弹出独立窗口。一个窗口搞需求分析，一个窗口修 Bug，一个窗口做代码审查，互不干扰。

三栏
Agent Sessions 工作台
左侧 Activity Bar + 中间文件编辑 + 右侧 Agent Studio（Chat / TaskBoard / Canvas 粘性标签）
多 Chat
一个 Session 多个对话
同一 Session 下可创建多个 Chat，共享上下文，不同任务用不同 Chat 推进
Worktree
分支级隔离
每个 Session 绑定独立 Worktree + Git 分支，改代码互不污染
Session 管理
多 Provider 聚合
  • CopilotChat + RemoteAgentHost 多源聚合
  • 统一 ISession facade 抽象
  • Session 持久化，重启不丢失
  • AgentSessionsPicker 快速切换
Chat 管理
弹出 / 聚合 / 切换
  • ChatPopoutService：聊天窗口弹出独立运行
  • 多 Chat 聚合在一个 Session 下
  • 跨 Chat 上下文共享
  • Chat 独立历史记录
工作区隔离
互不干扰的并行工作
  • Worktree 绑定独立 Git 分支
  • 文件变更不跨 Session 泄漏
  • 并行开多个 Agent 窗口
  • 每个窗口独立 Agent 实例
多任务并行
WorkBuddy / CodeBuddy：一个聊天面板，切换对话靠 Tab。做需求时要切出去修 Bug，上下文就断了。
→
VsSaros：一个窗口搞需求，一个窗口修 Bug，各自独立 Agent、独立 Worktree、独立分支。同时推进不打架。
上下文保持
WorkBuddy / CodeBuddy：对话切换时上下文重新加载，大项目里每次切换都要重新描述背景。
→
VsSaros：Session 持久化，重启不丢失。Worktree 绑定意味着改过的代码就是上下文的一部分。
关键优势WorkBuddy/CodeBuddy 的聊天是"一个电话"——你一次只能跟一个人说话，切换就要挂断重拨。VsSaros 的聊天是"一个指挥中心"——多个 Agent 同时在线，各自在独立的工作区里工作，你可以随时切过去看进度、拍板，然后切回来继续做自己的事。这不是 UI 层面的差异，而是工作模式的根本变化。
