工作台默认剥离 [id:…] / [summary:…] 等程序元数据；原文仅在「原文」页签可见。
本稿定位：交互设计稿，不是实现。类名沿用运行时 mt- / me- 前缀体系并新增 st-（设置）/ wb-（工作台）；配色只用 --dsw-alias-* 令牌，落地时删掉稿内两套 token 定义即可自动跟随宿主明暗主题。

现状的三个问题

  • 设置页是一长串开关：MemoryQueueView.tsx 单个 me-block 里约 25 行 me-field，无分组标题/图标/说明；作用域相关键 multiRootScopeEnabled / keyBranchFilter 不在 RUNTIME_KEYS，keyWriteMode / botMemoryCharLimit 虽在却未渲染 → 用户看不到也改不到「记忆作用域」。
  • 工作台以文件行为中心：9 个文件页签切换 + 原文 <pre>，一条记忆没有统一载体；属性散落在 11px 小徽标里；根 chip cursor:default 不可点。
  • 状态不可见：归档建议有文案和 CSS 却没有渲染组件；Bot Git 历史只有 API 没有面板；一条记忆看不到 commit / 注入状态 / 归属链。

重设计的四条原则

  • 按作用域组织，而非按文件组织：设置页分组卡片（作用域/写入/注入/Bot/归档/诊断），工作台作用域树 + 统一条目卡 + 详情检查器三栏。
  • 写之前先看见归属：写入目标选择器（轨 + 根）常驻中栏；建议队列徽标升级为「根 + 项目 + Bot」；采纳按钮显示目标。
  • 区分运行时 / 静态 / 只读：每个控件带徽标，静态键锁定并说明「仅 config.yaml」，避免「改了没生效」。
  • 不新建工作台整页：仍模拟 conversation.view 内插件 Tab；openMemoryDetailReact 外部链路不碰，避免触发 dshModuleContainers 清单守卫。

视觉与可访问性约束

  • 令牌：只用 var(--dsw-alias-*) + color-mix()；状态色沿用 business 蓝 / success 绿 / warn 琥珀 / error 红，不用硬编码色值。
  • 密度：卡片 12px、条目/徽章 8–10px、按钮 6px；字号 11–13px、gap 4–12px；无外阴影，分类色用 inset 3px 色条。
  • 图标：统一 24×24 viewBox 的 inline SVG（Heroicons 风格），不用 emoji 作图标；不使用外网 CDN 字体。
  • 可访问性：role="tablist/tab/radiogroup/radio" + aria-selected/checked/current、:focus-visible 焦点环、<label for>、颜色不是唯一状态指示（均有文字/徽标）、prefers-reduced-motion。
  • 响应式：1100 / 820 / 520px 三个断点；三栏在窄屏降级为「检查器下移」→「树横向滚动」。

刻意不采用的设计系统建议

--design-system 针对「展示型落地页」给出 Vibrant & Block-based / Feature-Rich Showcase / 48px+ 大间距 / 32px+ 大字，与 IDE 密集面板的信息密度、缓存友好、宿主主题跟随要求相反，故不采纳。仅保留其可访问性清单与 Fira 系「技术感」字体意图（本稿改用仓库既有 PingFang SC / Segoe UI + Cascadia Mono 栈，避免外网字体依赖）。

同样未照抄 _vssaros_core_features_share.html 的黑金叙事风格与 tapd-import-mockup.html 的 VS Code 深灰硬编码色：两者都是「独立网页壳」，与真实插件 Tab（mt-panel + 子 tab 条）不是同一形态。
