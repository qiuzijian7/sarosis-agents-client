节点内编辑器 → 独立窗口现状 / 缺口 / 三层方案 / 实施路线

目标：Blender、导演台、OpenPencil 这类节点，点击「⛶ 全屏」能打开独立编辑器窗口。
结论先说：宿主层已具备独立窗口的基础设施（聊天已用它 popout 成窗）， 编辑器组件本身也已经是自包含的（props 只吃初始值 + 回调）； 缺的是三块胶水 —— 单节点 EditorInput/Pane、「打开节点编辑器」RPC、统一编辑器描述符。

02三个示例节点的现状映射

节点当前是否存在承载类型说明
导演台 已存在 A 类 · 项目内 React ComfyTV.StoryboardEditorStage → DirectorConsoleEditor（卡片内联，最小高度 560）。状态写回 widget board_state。已具备左右分栏 + 时间线，是最适合先做全屏的节点。
Blender 不存在 B 类 · 外部应用 仓库无 blender 关键词。若接入的是 Blender Web / 云端实例 / 本地 Web 服务，需 <iframe> 或独立 webview 承载 + postMessage 协议；若是自研 3D 编辑器，可参考现有 Scene3DEditor（three.js 路线，A 类）。
OpenPencil 不存在 B 类 · 外部应用 同为外部 Web 应用 → 与 Blender 同一条承载路径（iframe / 独立 webview + 双向消息）。项目已有 iframe 先例：urlPreviewEditorPane.ts:130。
两类编辑器，两条承载路径 A 类（项目内 React 组件）：导演台、故事板、3D 场景、图层编辑器 —— 直接换宿主即可，成本低。
B 类（外部 Web 应用）：Blender、OpenPencil —— 需要一个 iframe/WebView 宿主组件 + 消息协议（初始化参数、状态变更、保存回调），但开窗机制与 A 类完全相同（都是「Pane 里渲染什么」的差别）。

03目标形态：从卡片到独立窗口的四个台阶

04三层方案

L1 · 全屏浮层1-2 天零宿主改动
做法：复用已有的 createPortal → document.body 模态模式（表情格编辑器已跑通），新增 NodeEditorFullscreen 容器：position:fixed; inset:0; z-index:3000，内部渲染同一编辑器组件，尺寸用 100vw/100vh 减去工具栏。
入口：卡片右上角加「⛶ 全屏」按钮 → setFullscreenEditor({ nodeId, kind })（与现有 editingEmojiCell 同构）。
复用件：nodeCard.tsx:3583-3599 的 portal 模式、stageCardRegistry 的 kind 表、编辑器组件本身。
边界：仍在 webview 内 —— 不能拖到别的显示器、不能与编辑器并排；画布 zoom 仍影响不到它（这是优点）。
L2 · 独立 editor tab3-5 天 · 核心可并排 / 最大化
做法：仿 WorkflowEditorPane（browser/workflowEditorPane.ts:33-158）新建一套 WorkflowNodeEditorInput + WorkflowNodeEditorPane；Pane 内起一个新的 AgentStudioWebviewController，panelType 用新的 'workflow-node'，initialData = { workflowId, nodeId, editorKind }。
webview 侧：index.tsx 按 panelType 分支，只渲染「该节点的全屏编辑器」（复用同一组件 + 同一 store 读 node.data）。
RPC：新增 workflow.openNodeEditor（webview → host），host 侧 openEditor(input, { pinned:true })。协议双侧登记 + 一致性测试守卫（已有 messageProtocolConsistency.test.ts）。
状态同步：宿主服务是单一数据源；新 webview 实例订阅同一批服务（workflowExecutionService / workflowStorageService），编辑回写走已有的 workflow.nodeValuesChanged 回流 —— 这套机制已在「聊天 pane + 工作流 pane 并存」场景验证。
复用件：registerEditorPane 注册模式（agentStudio.contribution.ts:1137-1146）、AgentStudioWebviewController、webview pool。
L3 · OS 独立窗口+2-3 天可拖到第二显示器
做法（两种，均已验证可行）：
① openEditor(input, { pinned:true, auxiliary:{ bounds, alwaysOnTop } }, AUX_WINDOW_GROUP) —— 一步到位（AUX_WINDOW_GROUP = -3，editorService.ts:34）；
② 仿 agentStudio.popoutChat：editorGroupsService.createAuxiliaryEditorPart() + srcGroup.moveEditors(...)（agentStudio.contribution.ts:1808 / 1822）—— 聊天已用它把 webview 型 pane 成功搬进独立窗口。
菜单：编辑器 tab 右键已有原生「Move into New Window」（editorActions.ts:2651）—— 即 L2 做完后，用户已能手动把 tab 拖成独立窗口；L3 只是把它做成节点卡上的一个按钮。
重要：L2 做完，L3 几乎是白送 VS Code 原生支持「把任意 editor tab 拖出成独立窗口」（AUX_WINDOW_GROUP + MoveEditorToNewWindowAction）。 因此只要节点编辑器能开成一个 editor tab，用户就已经可以把它拖成独立窗口；L3 只是补一个「⛶ 直接开窗」的快捷入口。

05核心设计：把「kind」升级为「描述符」

现状 stageCardRegistry 只回答「这个节点用哪个编辑器」。要支持多宿主（卡片 / 浮层 / tab / 窗口），需要让它同时回答承载方式与可全屏性：

// 建议：stageCardRegistry.ts 的 kind 表升级为描述符表（仍是纯数据 + 纯函数，可单测）
export interface NodeEditorDescriptor {
	kind: StageEditorKind;
	title: string;                        // 窗口/tab 标题（如「导演台 · 分镜 3」）
	host: 'react' | 'iframe';           // A 类组件 / B 类外部应用
	/** B 类：外部应用 URL 解析（可带 node 参数） */
	resolveUrl?: (node) => string;
	fullscreen: boolean;                  // ← 是否显示「⛶ 全屏」按钮（新字段）
	minInlineHeight?: number;            // 沿用现有 STAGE_MIN_HEIGHTS
	hiddenFields?: ReadonlySet<string>;     // 沿用现有 STAGE_HIDDEN_FIELDS
}

export const NODE_EDITORS: Record<string, NodeEditorDescriptor> = {
	'ComfyTV.StoryboardEditorStage': {
		kind: 'directorConsole', title: '导演台', host: 'react', fullscreen: true,
	},
	'ComfyTV.BlenderStage': {        // ← 未来接入
		kind: 'blender', title: 'Blender', host: 'iframe', fullscreen: true,
		resolveUrl: (n) => `http://127.0.0.1:${n.data.port}/?scene=${n.data.sceneId}`,
	},
};

为什么值得这样改

  • 「哪个节点可全屏」变成一处数据，不散落在 nodeCard 的十几个布尔里
  • A/B 两类编辑器走同一套开窗逻辑，差别只在 host
  • 新增节点（Blender/OpenPencil）= 加一条描述符 + 一个承载组件
  • 保持纯数据 → 可单测（现有 stageCardRegistry 已是这个风格）

不破坏现状

  • 现有 stageEditorKind() / hasStageEditor() / stageMinHeight() 可从描述符派生，调用方零改动
  • STAGE_HIDDEN_FIELDS 的「两套 UI 重复」教训直接继承
  • 渐进迁移：先只加 fullscreen 标志，其余字段后续按需补

08建议实施路线

阶段内容验收标准依赖
P0 导演台全屏浮层（L1） 卡片点「⛶」→ 全屏浮层显示导演台；编辑后 board_state 正确写回；Esc / ✕ 关闭；与卡片内联内容实时一致 无
P1 描述符化 + fullscreen 标志 stageCardRegistry 升级为描述符（现有函数改为派生）；至少 3 个节点（导演台 / 故事板 / 表情包）声明 fullscreen:true；单测覆盖 P0
P2 WorkflowNodeEditorInput/Pane + workflow.openNodeEditor RPC 点「⛶」→ 开独立 editor tab，渲染同一编辑器；tab 内编辑与卡片同步；协议双侧登记 + 一致性测试通过 P1
P3 「在新窗口打开」入口（L3） 卡片 / tab 右键可开 aux 窗口；窗口内编辑正常回流（AUX_WINDOW_GROUP 或 createAuxiliaryEditorPart） P2
P4 B 类承载组件（Blender / OpenPencil） iframe/WebView 宿主组件 + postMessage 协议（初始化 / 状态变更 / 保存回调）；同一套开窗入口可直接复用 P2 + 外部应用就绪
一个产品决策点 「全屏」到底指哪个？三者可并存但默认值需明确：
① 占满 webview（L1，最快，但仍在编辑器 tab 内）② 占满一个 editor tab（L2，可与画布并排）③ 操作系统独立窗口（L3，可跨显示器）。
建议默认 L2（tab），因为它同时满足「大」与「可并排」，且让 L3 几乎免费；L1 可作为「轻量快速预览」保留给不需要并排的简单编辑器。
