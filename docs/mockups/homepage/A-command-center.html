项说明
定位进化式重设计：把现有的「一行标题 + 12 列网格」升级成有页头、有全局搜索、有主次层级的仪表盘。不改变数据口径。
信息架构页头（问候 / 范围 / 编排）→ KPI 带（12 列）→ 工作台 8 + 用量/诊断 4 → 会话明细 8 + 工作区/时钟/番茄 4。主数字只有 4 个，其余折成副行小字（沿用 KpiCard 样式 B 的结论）。
复用 widget8 个全用：kpi / workbench / usage / diag / sessions / workspaces / clock / pomodoro；只改默认布局 DEFAULT_LAYOUT 的顺序与 w/h，lib/catalog.js 零改动。
新增仅页头 + 顶栏全局搜索（不进网格，属于全局作用域，与「日期范围」同一层）；卡片头部的分区图标用内联 SVG。
落地代价最小：改 lib/layout.js 默认布局、renderDashboardPage() 的页头壳、app.css 的卡片头。data-vssaros-dashboard-* 隐藏 meta 块不动 ⇒ p3-09 探针不受影响。
风险仍是「报表优先」，无法回答「我接下来做什么」；若目标是提高主页打开后的动作率，需要叠加方案 B 的 Hero。

原型里的「自定义」按钮会切换编排态（显示拖拽把手与卡片操作），对应 Dashboard 的 editing 状态；12 列网格在窄容器下按 @container 降为 8 / 4 列，与 app.jsx 的 12→8→6→4 自适应同思路。
