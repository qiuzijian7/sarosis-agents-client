# 生成图片管理 · 设计方案

> 目标：把工作流（AgentStudio LiteGraph 画布）中生成/处理产生的图片从"一次性内存快照"升级为**可持久化、可检索、可复用、可清理**的一等资产。
>
> 调研范围：ComfyUI、AUTOMATIC1111 Stable Diffusion WebUI、InvokeAI、ComfyTV（本项目对接工具）、云端平台（Replicate 等）。

---

## 1. 现状与痛点

### 1.1 现状

- **内存级快照**：`webview/.../comfyHost/mediaSnapshotStore.ts` 的 `MediaSnapshotStore` 每画布实例新建（`LiteGraphCanvas.tsx:152`），后端 `createMemoryBackend()` 存 `Map`，key = `${nodeId}:${port}:${index}`，`maxPreviewRefs=200` LRU 淘汰。
- **消费方**：`nodeCard.tsx` 的 `SnapshotPreview` 用 `useNodeSnapshots` 画卡片缩略图；内嵌编辑器（storyboard/material/scene3d 等）与 `workflowRun.ts`/`stageWorkflowExecutor.ts` 把输出写入该 store。
- **ComfyUI 原生输出**：仅存在于 ComfyUI 自己的 `output/` 目录，通过 `/view?filename&subfolder&type` 引用，本项目不持有任何副本。
- **无元数据、无画廊、无持久化**：刷新标签页即全部丢失；无法按 workflow/节点/时间回溯；无法把历史生成图作为输入复用（除极少数 picker 场景）；磁盘占用不可控。

### 1.2 痛点

| # | 痛点 | 影响 |
|---|------|------|
| 1 | 刷新即失，跨会话不可见 | 无法回到上次结果、无法做 A/B |
| 2 | 无元数据关联 | 记不住"这张图是哪个节点/哪次 prompt 生成的" |
| 3 | 无画廊/检索 | 无法筛选、搜索、对比 |
| 4 | 无法复用 | i2i/参考图/二次处理没有入口 |
| 5 | 无清理策略 | ComfyUI output 无限堆积 |

## 2. 开源方案对比

### 2.1 各项目做法

**ComfyUI（本地节点引擎）**
- 输出落盘 `ComfyUI/output/`（可配置 `output_directory`）；`/history` 返回每次执行输出（filename/subfolder/type），`/view` 按 file 引用；前端仅展示当次 batch 的小画廊。
- 输入在 `ComfyUI/input/`，通过 `/upload/image` 上传。
- 无元数据 DB、无软删除、无检索；文件系统即真源，管理靠外部工具/插件（ComfyUI-Desktop 加了输出面板与目录设置）。
- 可借鉴：**历史接口 + 按 file 引用、输入目录机制**（本项目已复用 /view 模式）。

**AUTOMATIC1111 WebUI（文件即数据库）**
- 输出 `outputs/{txt2img|img2img}/{YYYY-MM-DD}/{seed}.png` + 同目录 `*-grids-*.png` 对比图。
- 每张 PNG 内嵌 tEXt 文本块（`parameters`：prompt、negative、steps、seed、sampler、model 等）；"PNG Info" 页可拖图反解析；`/sdapi/v1/png-info` 读取。
- 历史靠 Gradio 按日期目录浏览；无 DB；**文件系统 + 文件名模式 + 图内元数据**三件套。
- 可借鉴：**元数据内嵌 PNG（可迁移、可分享）**、**按日期分目录**。

**InvokeAI（资产库模式，最接近我们的需求）**
- 架构（Codesea 分析 + 官方文档）：`ImageService` 处理生成图 → 提取元数据 → `DiskImageFileStorage` 写 PNG + JSON metadata sidecar + 生成缩略图 → 在 SQLite（`invokeai.db`，自带迁移框架 `sqlite_migrator`）落 `ImageDTO` 记录。
- 表：`images`、`boards`、`board_images`、`image_metadata`（invokeai_metadata 存 prompt/model/尺寸/seed/版本）。
- 特性：**软删除**（`is_deleted` 标记 + 永久删除）、**Boards 虚拟分组**（收藏/分类）、`/api/v1/images` 分页/过滤/搜索、画廊 UI 多选/筛选。
- 统一管理 images/models/embeddings/loras 等资产（asset library）。
- 可借鉴：**DB 元数据 + 软删除 + Boards 组织 + 缩略图 + 分页查询 API**——这是本项目的最优参照。

**ComfyTV（本项目对接的 ComfyUI 扩展）**
- 数据流 = 项目快照（URL/JSON，非张量），stage 输出以 URL 引用；媒体经 ComfyUI input/output 子目录 `comfytv/` 管理；浏览器端 stage 可重渲染。
- 可借鉴：**"项目快照"概念**——把 workflow 每次执行产出的媒体按项目/执行 id 归类。

**云端平台（Replicate / BFL / HF Spaces）**
- 输出 = 带过期时间的对象存储 URL；API 返回元数据 JSON；无本地生命周期管理。
- 可借鉴：**输出即 URL + 元数据 JSON 的接口形态**（适合我们 BYOK 直连 provider）。

### 2.2 对比矩阵

| 维度 | ComfyUI | A1111 | InvokeAI | ComfyTV | 云端 |
|------|---------|-------|----------|---------|------|
| 存储介质 | 文件目录 | 文件目录 | 文件 + SQLite | 文件 + 快照 JSON | 对象存储 URL |
| 元数据载体 | /history | PNG tEXt | DB + sidecar + PNG | 项目 JSON | API JSON |
| 历史/列表 | /history 接口 | 按日期扫描 | SQL 分页查询 | 项目列表 | API 列表 |
| 删除 | 手动文件 | 手动文件 | 软删 + 永久删 | — | — |
| 组织/复用 | input/ 上传 | 日期目录 + i2i | Boards + picker | 项目快照 | — |
| 画廊 UI | 当次 batch | 简易 | 富画廊(筛选/多选) | 内置 gallery | 简易 |
| 检索/搜索 | 无 | 无 | 文本/参数过滤 | 有限 | 有限 |
| 工程成本 | 低 | 低 | 高 | 中 | 低 |

**结论**：A1111 适合"个人把玩"；ComfyUI 适合"引擎但不管资产"；**InvokeAI 的资产库模式（文件 + DB 元数据 + 软删除 + Boards + 缩略图）是产品化的正确形态**，与本项目（已有 SQLite、数据目录、卡片预览）契合度最高，作为主参考。

## 3. 需求与约束

### 3.1 需求（用户视角）
1. 生成的图片**刷新后仍在**（持久化）。
2. 能按 **workflow / 节点 / provider / 日期 / 关键词** 检索历史图片。
3. 生成图可**复用**：作为 picker / i2i / 参考图 输入。
4. 可**导出/下载**，且导出后元数据不丢（PNG 内嵌）。
5. **磁盘可控**：清理策略 + 软删除（防误删）。
6. 执行中卡片预览体验不回归（现有 SnapshotPreview）。

### 3.2 工程约束
- **renderer 沙箱无 Node**：所有落盘/读盘必须经主进程 IPC，或使用 IndexedDB（blob 持久化）。
- **主进程已有 better-sqlite3**（V8 ABI 敏感，KB 在用）——元数据 DB 可直接复用同一原生模块，注意升级 Electron 需重编。
- **多 provider 输出形态不一**：ComfyUI = `/view` file 引用；BYOK = HTTP URL/blob。
- 数据目录 `~/.vssaros/`（dev `~/.vssaros-dev`），已有 agents/skills/extensions/settings 等子目录。
- 既有 `MediaSnapshotStore`（内存）+ `cardStateStore`（执行状态）+ picker stage，需要平滑演进而非推翻。

## 4. 目标架构

### 4.1 分层视图

```
┌─ renderer（webview，沙箱）────────────────────────────────┐
│  Gallery 面板(筛选/多选/导出)  ←  MediaSnapshotStore(快照层) │
│      │                                   ↑ 写回            │
│      ▼ IPC                               │                 │
│  media.import/list/getMeta/delete/...    │                 │
├──── main process ─────────────────────────────────────────┤
│  MediaService（资产服务，真源）                              │
│   ├─ 文件存储:  ~/.vssaros/media/{yyyy}/{mm}/{id}.png       │
│   │               + .webp(缩略图) + .json(元数据 sidecar)   │
│   └─ SQLite:    media.db (media_asset 表, 可查询)           │
│        ↑ 复用 better-sqlite3（与 KB 同栈）                  │
├─ 外部 provider ────────────────────────────────────────────┤
│  ComfyUI（/view 直连，可在 media/ 建镜像副本或仅索引）         │
│  BYOK（HTTP URL → 落盘 import）                             │
└────────────────────────────────────────────────────────────┘
```

### 4.2 数据模型（media_asset 表，对齐 InvokeAI ImageDTO）

```sql
CREATE TABLE media_asset (
  id            TEXT PRIMARY KEY,        -- uuid
  workflow_id   TEXT,                    -- 所属工作流（可为空=全局媒体库）
  node_id       TEXT,                    -- 产生节点
  provider      TEXT,                    -- 'comfyui' | 'byok:<id>' | 'upload'
  kind          TEXT,                    -- 'image' | 'video' | 'audio' | 'text'
  ref           TEXT NOT NULL,           -- 源引用（/view URL | 原始 URL | blob key）
  file_path     TEXT,                    -- 本地镜像路径（可选）
  thumb_path    TEXT,                    -- 缩略图路径
  meta          TEXT,                    -- JSON：prompt/params/seed/model/width/height...
  created_at    INTEGER NOT NULL,
  size_bytes    INTEGER,
  is_deleted    INTEGER DEFAULT 0,       -- 软删除
  board         TEXT,                    -- 虚拟分组（可选，对齐 Boards）
  favorite      INTEGER DEFAULT 0
);
CREATE INDEX idx_media_node  ON media_asset(node_id, created_at);
CREATE INDEX idx_media_wf    ON media_asset(workflow_id, created_at);
CREATE INDEX idx_media_deleted ON media_asset(is_deleted, created_at);
```

### 4.3 目录布局

```
~/.vssaros/media/
  {yyyy}/{mm}/{assetId}.png        # 原图（生成/导入）
  {yyyy}/{mm}/{assetId}.webp       # 缩略图（320px max edge）
  {yyyy}/{mm}/{assetId}.json       # 元数据 sidecar（可独立迁移/备份）
```

### 4.4 存储后端演进（不推翻现有抽象）

`MediaSnapshotBackend` 已有 `save/load/remove` 接口，按"替换实现"演进：

| 后端 | 位置 | 用途 | 阶段 |
|------|------|------|------|
| `createMemoryBackend`（现有） | renderer | 单次执行/测试 | 保留 |
| `createIndexedDBBackend`（新增） | renderer | blob 本地持久化，**刷新不丢**，零主进程改动 | P0 |
| `createHostFileBackend`（新增） | main IPC | 文件 + SQLite 元数据，跨实例/跨机器，支持画廊 | P1 |

`MediaSnapshotStore.put/load` 语义不变，卡片预览零改动；新增资产语义（workflow_id/元数据/软删）走主进程 `MediaService`。

### 4.5 生命周期与清理

- **软删除**：`media.delete` 置 `is_deleted=1`（对齐 InvokeAI），画廊"回收站"可恢复；永久删除由配额触发。
- **配额策略**（可配置，默认建议）：单 workflow 保留最近 N（如 500）条；全库按 `size_bytes` 总量上限（如 10GB）或天数（如 90 天）淘汰最旧且未收藏/未入 board 的资产。
- **ComfyUI 输出**：默认"索引不镜像"（仅记 /view 引用，避免双份存储）；用户在画廊点"保存到媒体库"时才镜像落盘（对齐 A1111/InvokeAI 的显式保存心智）。

### 4.6 复用入口

- **picker stage**（已有）改为从 `MediaService.list` 取数据（按 workflow/收藏/全部过滤），而不是仅当前会话内存。
- 支持把历史图作为 **i2i / 参考图 / 遮罩** 传入任意 image 输入端口（通过 `media.getAssetUrl` 取 `/view` 或本地 file URL）。

## 6. 关键决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 存储介质 | **文件为主 + SQLite 元数据** | 对齐 InvokeAI；文件可独立备份/迁移，DB 提供可查询 |
| 元数据载体 | **DB 为主 + PNG tEXt 导出辅助** | DB 支持检索/排序；导出时内嵌保证可迁移（对齐 A1111） |
| 删除语义 | **软删除 + 回收站 + 配额永久删** | 防误删，对齐 InvokeAI `is_deleted` |
| 默认后端 | P0=IndexedDB → P1=HostFile | 零主进程改动快速落地，再升级到跨实例资产库 |
| ComfyUI 输出 | 默认索引不镜像，显式"保存"才镜像 | 避免双份存储；保留 ComfyUI 原生文件为真源 |
| 复用入口 | picker stage 改接 MediaService | 复用现有交互，扩展数据源 |

## 7. 风险与待办

- **better-sqlite3 V8 ABI**：media.db 与 KB 同栈同库，升级 Electron 需同步重编（已有 SOP）。
- **磁盘占用**：视频/音频资产体积大，配额策略需对 kind 分级（图片严格、媒体宽松）。
- **IPC 体积**：import 图片经 IPC 有体积上限（建议 ≤50MB blob 走 Buffer，更大走临时文件路径）。
- **多实例并发**：工作流可多开，写 media.db 需互斥（参考 KB 的 index.lock 模式）。

> 工作区当前已实现：主进程 `mediaStore` 后端（文件+SQLite）+ channel/proxy/controller、webview 协议与客户端、`MediaGallery` 面板、自动收录、配额、Boards、picker 复用、导入入口。与第 5 章对应关系：

| 阶段 | 状态 | 说明 |
|------|------|------|
| P0 本地持久化 + 卡片历史 | ✅ 落地 | IndexedDB/快照落盘；卡片缩略图轮播；下载 |
| P1 资产库 + 画廊 | ✅ 落地 | MediaService RPC；media.db；Gallery 面板筛选/多选/导出/删除恢复 |
| P2 组织与配额 | ✅ 落地 | Boards 分组；配额/清理；picker/i2i 复用接通 |
| P3 工程硬化（下表） | ⬜ 设计 | 见 8.1 |

### 8.1 P3 —— 工程硬化（缩略图管线 / 配额分级 / 清理 / 互斥 / 元数据导出）

- [ ] **缩略图管线**：
  - 生成时机：import 落盘后异步队列（后台任务，不阻塞返回）；失败降级为原图直链。
  - 规格：`{id}.webp` 320px max edge（画廊）；`{id}-full.webp` 1280px（详情大图）。
  - 命中策略：读时优先 thumb_path，缺失则降级 file_path；`thumbnail` RPC 延迟生成。
- [ ] **配额分级**（kind 分级，对齐风险节）：

  | kind | 默认单资产上限 | 全库总量上限 | 保留策略 |
  |------|--------------|------------|---------|
  | image | 20MB | 10GB | 最旧 N=2000 |
  | video | 500MB | 50GB | 天数 90 |
  | audio | 100MB | 10GB | 天数 180 |
  | text | 1MB | — | — |

- [ ] **清理策略（软删 → 永久删）**：
  - 回收站：`is_deleted=1` 保留 30 天 → 定时任务永久删除（文件+DB+缩略图）。
  - 容量触发：超上限时淘汰「未收藏 ∧ 未入 board ∧ 最旧」，按 kind 分级顺序（video→audio→image）。
  - 收藏/入 board 的资产豁免淘汰（对齐 InvokeAI 心智）。
- [ ] **多实例互斥**：复用 KB `index.lock` 模式（60s/5min fail-open）保护 media.db 写事务；WAL + `journal_mode` 已由 better-sqlite3 提供并发读。
- [ ] **IPC 体积**：`media.import` ≤50MB 走 Buffer 传递；更大走 `文件路径引用`（renderer 提供临时路径）避免 IPC 阻塞。
- [ ] **元数据内嵌导出**：导出 PNG 时写 tEXt 块（prompt/params/seed/model/provider，对齐 A1111 PNG Info）；`media.export` RPC 返回带元数据文件；导入时反向解析（`png-info`）。
- [ ] **taskId 关联**：`canvas_get_task_status`（见《Agent-画布编排设计方案.md》P1）的 taskId 作为 `media_asset.task_id` 落库，画廊可追溯「这次生成的全部产物」。
