# QA Risk Analysis — 风险分析

输入：阶段 0 的 `context.json`。输出：`risk-analysis.json`。
**只识别风险，不设计用例、不写测试、不判断质量。**

## 工作流

### 1. 确定风险维度

按重要性排序：

1. **业务主路径** — 必须端到端验证的核心旅程
2. **改动影响面** — 用 `detect_changes` 拿 diff，用 `trace_path` 追下游调用
3. **数据边界** — 空值、越界、并发、大额/大数据量
4. **外部依赖** — 第三方服务、数据库、消息队列的失败路径
5. **历史故障区** — 查 `.qa-agent/knowledge/` 经验库

### 2. 影响面传播

用 `trace_path` 从改动函数向下游追（direction=callees），标记：
- 被改动的直接下游
- 跨模块边界的传播
- 扇入高（inDegree 大）的节点——改动影响面广

### 3. 风险分级

| 级别 | 判定标准 | 验证要求 |
|---|---|---|
| 高 | 主路径 / 资金 / 数据一致性 / 扇入高 | 必须有 P0 用例，端到端 |
| 中 | 次要功能 / 边界条件 | P1 用例 |
| 低 | 边缘路径 / 展示层 | P2 用例，可跳过 |

### 4. 输出 `risk-analysis.json`

每条风险包含：`id`、`业务路径`、`风险等级`、`触发条件`、`必需验证点`、`关联代码位置`。

## 纪律

- 风险必须**指向具体代码位置**（`path:line`），不做无依据的泛泛而谈
- 主路径不清晰时，回到阶段 0 补收集，不要靠猜
- 播报：`▶ 风险分析完成 — 5 条高风险路径`，然后继续
