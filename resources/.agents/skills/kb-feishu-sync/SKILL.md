# 知识库 → 飞书同步（kb-feishu-sync）

## 前置条件（不满足就照实转告用户，别硬跑）

1. 设置里已启用飞书同步并配置好凭证 —— 没启用时工具会直接返回引导文案（指向「知识库设置 → 飞书同步」），原样转达；
2. 本机装了 `lark-cli` 且已登录 —— 没装时工具会返回安装指引，原样转达。

## 流程（固定两步，不要跳步）

1. **先预览**：调 `kb_feishu_sync`（`mode` 默认 `"dry-run"`）→ 把计划（将新建/更新/跳过哪些篇目、落到哪个飞书知识库）
   **讲给用户确认**；
2. **再执行**：用户确认后调 `kb_feishu_sync`（`mode: "apply"`）；
3. **汇报**：把结果讲清楚 —— 新建/更新/跳过/失败的篇数，失败项的原因（工具返回的日志尾部里有）。

## 规则（严格遵守）

- **增量**由脚本按每篇 frontmatter 的 `feishu.hash` / `remoteHash` 判定 ⇒ 重复同步**不会**重复创建；
  ⚠ **绝不要手改任何笔记的 `feishu.*` 字段**（token/url/hash/remoteHash/syncedAt 都是同步记账，
  改了会导致重复创建或冲突误判）。
- 冲突策略（远端被手工改过怎么办）与目标知识库由**设置**决定（`知识库设置 → 飞书同步`）—— 不是你决定的；
  用户想改就引导他去设置页。
- **哪个分类落到哪个飞书知识库**同样不由你决定：类别 = 同步源目录下第 N 级目录（设置「类别层级」），
  或用 vault 内 `.feishu-space-map.json` 显式映射（优先）。要新建分类 / 关联某个已有知识库 ⇒ 见技能
  `kb-category-feishu`（含改分类后的跨库自动搬迁语义）。
- **同步范围默认只有「笔记」**（库里的原始素材不同步）；用户明确要求连同库一起时才传 `srcDirs: ["库", "笔记"]`。
- 本地删除默认**不**清远端（`prune=false`）；只有用户明确要求时才传 `prune: true`。
- 一次同步可能跑几分钟（每篇有间隔，写远端）⇒ **一次调用里耐心等它返回，不要重复发起**；
  重复发起会产生并发写远端的冲突。
- 失败处理：凭证/网络类失败 ⇒ 把脚本报错原文转告用户；**不要自己重试超过一次**。
- **图表会自动转换**（2026-09-24 起工具与视图按钮口径一致）：`apply` 前宿主会把笔记里的 mermaid / drawio
  代码块与 `![[x.canvas]]` 嵌入渲染成 PNG 并改写引用（飞书不渲染图表源码、图片也不支持 SVG）——
  这是**正常现象**，不要因为笔记正文被改写成 `![[xxx.png]]` 就认为出错。
- `dry-run` **只统计图表数量、不改任何文件**（预览不产生本地副作用）；工具会告诉你 apply 时会转换几张图。
- 若用户反馈「飞书里图显示成源码」：那是转换失败（工具返回里会写明「N 张失败（已保留源码）」）——
  把失败信息**如实转告**用户，不要自己去改笔记里的图表源码。
