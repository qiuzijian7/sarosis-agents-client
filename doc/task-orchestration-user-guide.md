## 1. 功能概述

任务编排（Task Orchestration）是 Agent Studio 的核心功能，允许您通过自然语言描述目标，系统自动将复杂任务分解为可执行的子任务、创建 Agent、建立依赖关系，并自动调度执行。

### 1.1 主要能力

- **目标分解**: 自动将复杂目标拆分为多个子任务
- **依赖管理**: 自动建立任务间的依赖关系（DAG）
- **Agent 创建**: 自动创建执行任务所需的 Agent
- **智能调度**: 自动分配任务给最合适的 Agent
- **执行监控**: 实时查看任务执行状态和进度

### 1.2 适用场景

- 复杂的多步骤开发任务（如"开发一个用户认证系统"）
- 需要多个 Agent 协作的项目
- 希望自动化任务分配和调度的场景

## 2. 核心概念

### 2.1 角色模型

任务编排基于三种角色协同工作：

| 角色 | 说明 | 数量限制 | 职责 |
|------|------|----------|------|
| **Planner** | 规划者 | 多个 | 分析目标，创建编排计划（分解任务） |
| **PM** | 项目经理 | **仅 1 个** | 审批计划，调度任务执行 |
| **Worker** | 执行者 | 多个 | 执行被分配的具体任务 |

### 2.2 编排计划（Orchestration Plan）

编排计划是任务编排的核心数据结构，包含：

- **目标（Goal）**: 用户描述的原始目标
- **摘要（Summary）**: Planner 生成的计划说明
- **任务列表（Tasks）**: 分解后的子任务集合
- **状态（Status）**: 计划的当前状态

### 2.3 任务状态

任务在执行过程中会经历以下状态：

```
Pending (待执行) → Running (执行中) → Done (已完成)
                    ↘ Error (错误) → Pending (重试)
                    ↘ Paused (已暂停) → Pending (恢复)
                    ↘ Cancelled (已取消)
```

### 2.4 计划状态

编排计划的生命周期：

```
Pending Approval (等待审批) → Approved (已批准) → Executing (执行中) → Completed (已完成)
                              ↘ Rejected (已拒绝)
                              ↘ Error (执行错误)
```

## 3. 使用前准备

### 3.1 创建 Planner Agent

Planner 负责分析目标并创建编排计划。

**步骤**:

1. 在 Agent Studio 的 WebView 中，点击 **"创建 Agent"** 按钮
2. 在弹出的模态框中，填写 Agent 信息：
   - **名称**: 例如 "Master Planner"
   - **角色**: 例如 "Architect"
   - **Agent 类型**: 选择 **"Planner"** ⚠️ 重要！
3. 选择合适的模型和系统提示词
4. 点击 **"创建"** 按钮

**验证**: 创建成功后，Agent 列表中会显示该 Agent，并标记为由 "📐 Planner" 徽章。

### 3.2 创建 PM Agent

PM（项目经理）负责审批计划并调度任务。**每个工作区仅允许一个 PM**。

**步骤**:

1. 在 Agent Studio 的 WebView 中，点击 **"创建 Agent"** 按钮
2. 在弹出的模态框中，填写 Agent 信息：
   - **名称**: 例如 "Project Manager"
   - **角色**: 例如 "Project Manager"
   - **Agent 类型**: 选择 **"PM"** ⚠️ 重要！
3. 选择合适的模型和系统提示词
4. 点击 **"创建"** 按钮

**验证**: 创建成功后，系统会提示 "PM 已创建"。如果已有一个 PM，创建第二个会失败。

### 3.3 检查准备状态

在启动任务编排前，请确认：

- ✅ 至少有一个 Planner Agent
- ✅ 有一个 PM Agent（每个工作区仅一个）
- ✅ 有可用的 Worker Agent（可选，系统可自动创建）

## 4. 快速开始

### 4.1 启动任务编排

有三种方式可以启动任务编排：

#### 方式一：从 TaskBoard 面板（传统方式）

1. 在 Agent Studio 的 WebView 中，找到 **TaskBoard 面板**（通常在底部或侧边）
2. 点击 **"🎯 任务编排"** 按钮
3. 在弹出的对话框中：
   - **选择 Planner**: 从下拉菜单中选择一个 Planner Agent
   - **描述目标**: 在文本框中输入您的目标（例如："设计一个用户认证系统，包含登录、注册、密码重置功能"）
   - 点击 **"生成计划"** 按钮

#### 方式二：从 Planner 聊天 `/plan` 命令（快速方式）

1. 在 Agent Studio 的 WebView 中，与 **Planner Agent** 聊天
2. 在聊天框中输入：`/plan <目标描述>`
   - 例如：`/plan 设计一个用户认证系统，包含登录、注册、密码重置功能`
3. 按 **Enter** 发送
4. 系统自动弹出**任务编排计划对话框**，并开始生成计划

#### 方式三：从 Planner 聊天头部按钮（直观方式）

1. 在 Agent Studio 的 WebView 中，与 **Planner Agent** 聊天
2. 点击聊天头部右侧的 **"🎯"** 按钮
3. 在弹出的对话框中：
   - **选择 Planner**: 默认使用当前 Planner（可更改）
   - **描述目标**: 在文本框中输入您的目标
   - 点击 **"生成计划"** 按钮

**推荐**: 如果您已经在和 Planner 讨论需求，使用**方式二**（`/plan` 命令）最快捷。

### 4.2 审批计划

Planner 生成计划后，您需要作为 PM 审批该计划：

1. 查看计划摘要和任务列表
2. 确认任务分解是否合理
3. 检查任务依赖关系（可切换到"依赖图"视图）
4. 如果满意，点击 **"✅ PM 批准调度"** 按钮
5. 如果不同意，点击 **"❌ 拒绝计划"** 按钮

### 4.3 监控执行

计划批准后，任务会自动开始执行：

- 在对话框中可以看到任务状态实时更新
- 可以展开任务查看详细信息
- 可以对单个任务执行操作（重试、暂停、恢复、取消）

### 4.4 查看结果

任务执行完成后：

- 在 **任务看板** 中查看所有任务的状态
- 点击任务查看详细信息和执行结果
- 在 **Overview** 中以看板形式查看整体进度

## 5. 详细使用说明

### 5.1 创建编排计划

有三种方式可以创建编排计划：

1. **从 TaskBoard 面板**: 点击 "🎯 任务编排" 按钮（传统方式）
2. **从 Planner 聊天 `/plan` 命令**: 输入 `/plan <目标>` 并发送（快速方式）
3. **从 Planner 聊天头部按钮**: 点击 "🎯" 按钮（直观方式）

方式 2 和 3 仅在您与 **Planner Agent** 聊天时可用。如果使用方式 2，系统会自动使用当前 Planner 生成计划。

#### 5.1.1 使用 `/plan` 命令（推荐）

`/plan` 命令是最快捷的创建编排计划的方式。

**基本语法**:
```
/plan <目标描述>
```

**示例**:
```
/plan 设计一个用户认证系统，包含登录、注册、密码重置功能
```

**执行流程**:
1. 在 Planner 聊天框中输入 `/plan <目标>`
2. 按 **Enter** 发送
3. 系统自动拦截该消息（不会出现在聊天记录中）
4. 弹出**任务编排计划对话框**
5. Planner 开始分析目标并生成计划
6. 生成完成后，对话框显示计划摘要和任务列表

**命令自动补全**:
- 输入 `/` 时，系统显示可用命令菜单
- 使用 **↑↓** 键选择 `/plan` 命令
- 按 **Enter** 或 **Tab** 确认选择
- 继续输入目标描述
- 按 **Enter** 发送

**注意事项**:
- `/plan` 命令仅在 Planner Agent 的聊天中可用
- 如果当前 Agent 不是 Planner，命令菜单中不会显示 `/plan`
- 目标描述可以为空，系统会使用默认目标"默认目标"

#### 5.1.2 编写目标描述

目标描述越详细，Planner 分解的任务越准确。建议包含：

- **功能需求**: 要做什么
- **技术要求**: 使用什么技术
- **质量标准**: 代码规范、测试要求等
- **交付物**: 期望的输出（代码、文档、测试等）

**示例**:

```
设计一个用户认证系统，包含以下功能：
1. 用户注册（邮箱+密码）
2. 用户登录（JWT token）
3. 密码重置（邮件验证）
4. 登录状态管理（Redis session）

技术要求：
- 后端：Node.js + Express + TypeScript
- 数据库：PostgreSQL
- 缓存：Redis
- 认证：JWT + bcrypt

质量标准：
- 所有 API 必须有单元测试（Jest）
- 代码覆盖率 > 80%
- 遵循 Airbnb JavaScript 规范

交付物：
- 完整的源代码
- API 文档（Swagger）
- 单元测试
- README 部署指南
```

#### 5.1.2 选择 Planner

如果有多个 Planner，选择最适合当前任务的：

- **架构师 Planner**: 适合系统设计和架构规划
- **开发 Planner**: 适合编码任务分解
- **测试 Planner**: 适合测试计划

#### 5.1.3 查看生成的计划

Planner 生成计划后，对话框会显示：

- **计划摘要**: Planner 对目标的分析和计划说明
- **任务列表**: 分解后的子任务，按依赖关系排序
- **统计信息**: 任务总数、Agent 数量、新建 Agent 数等

**任务列表视图**:

每个任务显示：
- 状态图标（⏳ 待执行 / ⚡ 执行中 / ✅ 已完成 / ❌ 错误）
- 任务标题
- 分配的 Agent（🆕 表示需要新建 Agent）
- 依赖任务
- 重试次数（如有）
- 超时时间（执行中时）

**依赖图视图**:

点击 **"依赖图"** 标签，可以看到任务的依赖关系图：

- 横向按层级（depth）排列
- 每个节点显示任务状态和分配的 Agent
- 箭头表示依赖方向

### 5.2 审批计划

#### 5.2.1 检查计划

在审批前，请仔细检查：

1. **任务分解是否合理**: 每个任务是否足够小且独立？
2. **依赖关系是否正确**: 任务执行顺序是否符合预期？
3. **Agent 分配是否合适**: 每个任务是否分配给了合适的 Agent？
4. **是否需要新建 Agent**: 系统是否自动创建了所需的 Agent？

#### 5.2.2 批准计划

如果计划满意，点击 **"✅ PM 批准调度"** 按钮：

- 计划状态变为 "Approved"
- 系统开始调度任务执行
- 符合条件的任务（无依赖或依赖已完成）会自动开始执行

#### 5.2.3 拒绝计划

如果计划不满意，点击 **"❌ 拒绝计划"** 按钮：

- 计划状态变为 "Rejected"
- 可以重新描述目标，再次生成计划

**常见拒绝原因**:

- 任务分解太粗或太细
- 依赖关系不合理
- 缺少关键任务
- Agent 分配不当

### 5.3 监控执行

#### 5.3.1 实时状态更新

计划批准后，对话框会显示任务执行的实时状态：

- **待执行（Pending）**: 灰色，等待依赖完成
- **执行中（Running）**: 蓝色，Agent 正在执行
- **已完成（Done）**: 绿色，任务成功完成
- **错误（Error）**: 红色，任务执行失败
- **已暂停（Paused）**: 紫色，任务被暂停
- **已取消（Cancelled）**: 灰色，任务被取消

#### 5.3.2 查看任务详情

点击任务项可以展开查看：

- **描述**: 任务的详细描述
- **错误信息**: 如果任务失败，显示错误原因
- **执行时间**: 开始时间和完成时间
- **结果**: 任务完成后的输出

#### 5.3.3 任务操作

对于执行中的计划，可以对任务执行以下操作：

| 操作 | 图标 | 适用状态 | 说明 |
|------|------|----------|------|
| **重做** | 🔄 | Error, Cancelled | 重新执行任务（重试次数 +1） |
| **暂停** | ⏸ | Running, Pending | 暂停任务执行 |
| **恢复** | ▶ | Paused | 恢复任务执行 |
| **取消** | ✕ | Running, Pending, Paused | 取消任务（不可逆） |

## 6. 任务看板

### 6.1 打开任务看板

任务看板是查看和管理所有任务的中心位置。

**方式一：Activity Bar**

1. 点击 VS Code 左侧 Activity Bar 中的 **"任务"** 图标
2. 打开 Tasks View 面板

**方式二：Overview 按钮**

1. 在 Tasks View 面板中，点击 **"📋 Overview"** 按钮
2. 在 Editor Pane 中打开任务看板

### 6.2 Tasks View 面板

Tasks View 是 Activity Bar 中的侧边面板，用于快速浏览和筛选任务。

#### 6.2.1 功能特性

- **搜索框**: 输入关键词搜索任务（按标题、描述、Agent 名称）
- **工作区选择器**: 选择查看哪个工作区的任务（"🌍 All Workspaces" 或具体工作区）
- **状态筛选器**: 按状态筛选任务（All / Todo / Running / Done / Cancelled）
- **任务列表**: 显示符合条件的任务，点击可查看详情

#### 6.2.2 使用搜索

在搜索框中输入关键词，系统会实时筛选任务：

- 匹配任务标题
- 匹配任务描述
- 匹配 Agent 名称

#### 6.2.3 切换工作区

点击工作区下拉菜单，选择：

- **"🌍 All Workspaces"**: 查看所有工作区的任务
- **具体工作区**: 仅查看该工作区的任务

#### 6.2.4 筛选状态

点击状态筛选器按钮：

- **All**: 显示所有任务
- **Todo**: 显示待执行的任务
- **Running**: 显示执行中的任务
- **Done**: 显示已完成的任务
- **Cancelled**: 显示已取消的任务

#### 6.2.5 打开任务详情

点击任务列表中的任意任务，会在 Editor Pane 中打开该任务的详情页面。

### 6.3 任务看板（Overview）

任务看板以看板（Kanban）形式展示所有任务，按状态分列。

#### 6.3.1 打开方式

在 Tasks View 面板中，点击 **"📋 Overview"** 按钮。

#### 6.3.2 看板布局

看板分为 5 列：

| 列名 | 说明 | 颜色 |
|------|------|------|
| **Todo** | 待执行的任务 | 黄色 |
| **Running** | 执行中的任务 | 蓝色 |
| **Done** | 已完成的任务 | 绿色 |
| **Cancelled** | 已取消的任务 | 灰色 |
| **Archived** | 已归档的任务 | 灰色 |

#### 6.3.3 工作区筛选

在看板顶部，可以选择工作区：

- **"🌍 All"**: 显示所有工作区的任务
- **具体工作区**: 仅显示该工作区的任务

#### 6.3.4 任务卡片

每个任务以卡片形式展示，包含：

- **状态图标**: 表示任务当前状态
- **任务标题**: 任务的名称
- **Agent 名称**: 执行该任务的 Agent
- **操作按钮**: （根据状态显示重试、暂停、恢复、取消等）

#### 6.3.5 拖拽任务

（如果支持）可以将任务卡片从一个列拖拽到另一个列，改变任务状态。

## 7. 任务管理

### 7.1 查看任务详情

#### 7.1.1 打开方式

**方式一：从 Tasks View**

1. 在 Tasks View 面板中，点击任务列表中的任务
2. 在 Editor Pane 中打开任务详情

**方式二：从任务看板**

1. 在任务看板（Overview）中，点击任务卡片
2. 在 Editor Pane 中打开任务详情

#### 7.1.2 详情页面内容

任务详情页面包含以下信息：

- **任务标题**: 任务的名称
- **状态**: 当前状态（带颜色标识）
- **描述**: 任务的详细描述
- **依赖任务**: 该任务依赖的其他任务
- **分配的 Agent**: 执行该任务的 Agent 信息
- **执行信息**:
  - 创建时间
  - 开始时间
  - 完成时间
- **重试信息**:
  - 当前重试次数
  - 最大重试次数
- **超时设置**: 任务超时时间（毫秒）
- **结果**: 任务完成后的输出（如果已完成）
- **错误信息**: 任务失败的原因（如果失败）

#### 7.1.3 详情页面操作

在详情页面中，可以执行以下操作：

- **🔄 重做**: 重新执行任务
- **⏸ 暂停**: 暂停任务执行
- **▶ 恢复**: 恢复任务执行
- **✕ 取消**: 取消任务

### 7.2 任务操作详解

#### 7.2.1 重做（Retry）

**适用场景**: 任务执行失败或被告知取消后，希望重新执行。

**操作方式**:

1. 在任务详情页面，点击 **"🔄 重做"** 按钮
2. 系统会将任务状态改为 "Pending"，重试次数 +1
3. 如果重试次数未超过最大重试次数，任务会重新排队等待执行

**注意事项**:

- 重试次数超过最大重试次数（默认 3 次）后，任务会被永久标记为 "Cancelled"
- 重做会丢失之前的执行结果

#### 7.2.2 暂停（Pause）

**适用场景**: 希望临时停止任务执行（例如需要手动干预）。

**操作方式**:

1. 在任务详情页面，点击 **"⏸ 暂停"** 按钮
2. 系统会将任务状态改为 "Paused"
3. 任务停止执行，但保留当前进度

**注意事项**:

- 暂停的任务不会释放已占用的资源
- 可以同时暂停多个任务

#### 7.2.3 恢复（Resume）

**适用场景**: 暂停的任务需要继续执行。

**操作方式**:

1. 在任务详情页面，点击 **"▶ 恢复"** 按钮
2. 系统会将任务状态改回 "Pending"
3. 任务重新排队等待执行

**注意事项**:

- 恢复后的任务会重新等待依赖完成（如果有依赖）
- 恢复不会重置重试次数

#### 7.2.4 取消（Cancel）

**适用场景**: 任务不再需要执行，或执行错误无法修复。

**操作方式**:

1. 在任务详情页面，点击 **"✕ 取消"** 按钮
2. 系统会将任务状态改为 "Cancelled"
3. 任务停止执行，且无法恢复

**注意事项**:

- 取消是**不可逆**操作
- 取消任务后，依赖该任务的其他任务可能无法执行
- 建议先暂停，确认后再取消

### 7.3 自动容错机制

系统内置了多种自动容错机制：

#### 7.3.1 超时监控

- 每个任务有超时时间（默认 5 分钟 = 300,000 毫秒）
- 如果任务执行超过超时时间，系统会自动将任务标记为 "Error"
- 超时后任务会根据重试策略决定是否重试

#### 7.3.2 自动重试

- 任务失败时，系统会自动重试（默认最多 3 次）
- 重试次数在任务对象中记录（`retryCount`）
- 超过最大重试次数后，任务会被标记为 "Cancelled"

#### 7.3.3 依赖自动解锁

- 当某个任务完成时，系统会自动检查依赖该任务的其他任务
- 如果依赖已满足（所有依赖任务都完成），下游任务会自动变为 "Pending" 状态
- 这确保了 DAG 依赖关系的自动传播

#### 7.3.4 并发控制

- 系统限制同时执行的任务数量（默认最大 3 个）
- 如果有太多任务同时变为 "Pending"，只有前 3 个会开始执行
- 其他任务会等待，直到有任务完成释放并发槽位

## 8. Planner 聊天中的任务编排

> **新功能** (v1.1): 现在可以直接在 Planner Agent 的聊天框中触发任务编排，无需离开聊天界面。

### 8.1 使用 `/plan` 命令

在 Planner Agent 的聊天框中，您可以直接使用 `/plan` 命令来触发任务编排。

#### 8.1.1 基本用法

**语法**: `/plan <目标描述>`

**示例**:
```
/plan 设计一个用户认证系统，包含登录、注册、密码重置功能
```

**执行流程**:
1. 在 Planner 聊天框中输入 `/plan <目标>`
2. 按 **Enter** 发送
3. 系统自动拦截该消息（不会作为聊天消息发送）
4. 弹出**任务编排计划对话框**
5. Planner 开始分析目标并生成编排计划
6. 生成完成后，您可以审批计划并启动执行

#### 8.1.2 命令自动补全

当您输入 `/` 时，系统会显示可用命令菜单：
- `/skill` - 选择并使用技能
- `/plan` - **任务编排**（仅 Planner Agent 显示）
- `/help` - 显示帮助信息
- `/clear` - 清除聊天记录

**使用 Tab 或 Enter 选择 `/plan` 命令**:
- 选择后，命令会插入到输入框
- 继续输入您的目标描述
- 按 **Enter** 发送，触发任务编排

#### 8.1.3 注意事项

- `/plan` 命令**仅在 Planner Agent 的聊天中可用**
- 如果当前 Agent 不是 Planner，命令菜单中不会显示 `/plan`
- 发送 `/plan` 命令后，消息不会出现在聊天记录中（被拦截）
- 目标描述可以为空，系统会使用默认目标

### 8.2 使用聊天头部按钮

在 Planner Agent 的聊天界面中，聊天头部会显示一个**任务编排按钮**（🎯）。

#### 8.2.1 按钮位置

按钮位于聊天头部的右侧操作区，与其他操作按钮（设置、信息等）在一起。

#### 8.2.2 点击按钮

1. 点击 **"🎯"** 按钮
2. 弹出**任务编排计划对话框**
3. 在对话框中选择 Planner（默认使用当前 Planner）
4. 输入目标描述
5. 点击 **"生成计划"** 按钮

#### 8.2.3 与 `/plan` 命令的区别

| 方式 | 优点 | 缺点 |
|------|------|------|
| `/plan` 命令 | 快速，一站式输入目标和触发 | 需要先输入 `/plan` 前缀 |
| 按钮方式 | 直观，对话框中有更多选项 | 需要两次点击（按钮 + 生成计划） |

### 8.3 两种入口对比

| 入口方式 | 适用场景 | 操作步骤 |
|----------|----------|----------|
| **TaskBoard 面板按钮** | 从任务管理界面启动编排 | 1. 打开 TaskBoard 面板<br>2. 点击 "🎯 任务编排" 按钮<br>3. 选择 Planner + 输入目标<br>4. 点击 "生成计划" |
| **Planner 聊天 `/plan` 命令** | 在聊天中快速触发编排 | 1. 与 Planner 聊天<br>2. 输入 `/plan <目标>`<br>3. 按 Enter<br>4. 自动弹出对话框并生成计划 |
| **Planner 聊天头部按钮** | 从聊天界面启动编排 | 1. 与 Planner 聊天<br>2. 点击头部 "🎯" 按钮<br>3. 输入目标<br>4. 点击 "生成计划" |

**推荐工作流**:
1. 与 Planner 讨论需求和目标（在聊天中）
2. 确认目标后，使用 `/plan` 命令快速触发任务编排
3. 在弹出的对话框中审批计划
4. 返回聊天界面继续与 Planner 讨论其他事项

## 9. 常见问题

### 9.1 无法启动任务编排

**问题**: 点击 "🎯 任务编排" 按钮后，提示 "未创建 Planner" 或 "未创建 PM"。

**原因**: 任务编排需要至少一個 Planner 和一个 PM 才能工作。

**解决方法**:

1. 创建至少一个 Planner Agent（Agent 类型选择 "Planner"）
2. 创建一个 PM Agent（Agent 类型选择 "PM"）
3. 刷新页面，重新尝试

### 9.2 Planner 生成计划失败

**问题**: 点击 "生成计划" 后，长时间无响应或报错。

**原因**: 可能是 Planner Agent 配置不当，或目标描述不清晰。

**解决方法**:

1. 检查 Planner Agent 的模型配置是否正确
2. 检查 Planner Agent 的系统提示词是否合适
3. 尝试简化目标描述，分多次生成计划
4. 查看开发者工具控制台（F12）查看详细错误信息

### 9.3 PM 审批按钮灰色不可点击

**问题**: 计划生成后，"✅ PM 批准调度" 按钮是灰色的，提示 "需要 PM 才能执行"。

**原因**: 当前工作区没有 PM Agent。

**解决方法**:

1. 创建一个 PM Agent（Agent 类型选择 "PM"）
2. 确保每个工作区只有一个 PM
3. 刷新页面，重新查看计划

### 9.4 任务执行失败

**问题**: 任务状态变为 "Error"，错误信息显示超时或执行错误。

**原因**: 可能是 Agent 执行失败，或任务超时。

**解决方法**:

1. 查看任务详情中的错误信息
2. 如果是超时，可以尝试增加任务的 `timeoutMs` 设置
3. 如果是执行错误，检查 Agent 配置和代码
4. 点击 "🔄 重做" 按钮重试任务

### 9.5 任务一直卡在 Pending 状态

**问题**: 任务状态一直是 "Pending"，不开始执行。

**原因**: 可能是依赖任务未完成，或并发数达到上限。

**解决方法**:

1. 检查任务的依赖任务是否都已完成
2. 在任务看板中查看 "Running" 列，确认是否达到并发上限（默认 3 个）
3. 如果有任务卡住，可以尝试暂停或取消该任务

### 9.6 无法创建第二个 PM

**问题**: 尝试创建第二个 PM Agent 时，系统提示 "每个工作区仅允许一个 PM"。

**原因**: 系统设计为每个工作区只能有一个 PM。

**解决方法**:

1. 如果需要更换 PM，先删除或停用现有的 PM Agent
2. 再创建新的 PM Agent

### 9.7 任务看板不显示任务

**问题**: 打开任务看板后，所有列都是空的。

**原因**: 可能是没有任务，或筛选条件不正确。

**解决方法**:

1. 检查工作区选择器是否选择了正确的工作区
2. 检查状态筛选器是否选择了 "All"
3. 在搜索框中清除搜索关键词
4. 确认是否有编排计划被创建和执行

## 10. 最佳实践

### 10.1 编写高质量的目标描述

- **具体明确**: 避免模糊的描述，提供具体的功能需求
- **分步骤**: 如果目标很复杂，可以分多个计划逐步完成
- **包含上下文**: 提供技术栈、代码规范、测试要求等信息
- **期望输出**: 明确说明期望的交付物

### 10.2 合理设计 Agent 角色

- **专门的 Planner**: 创建专门的 Planner Agent，不要复用 Worker 作为 Planner
- **唯一的 PM**: 每个工作区只设置一个 PM，避免调度冲突
- **多样的 Worker**: 创建不同专长的 Worker Agent（前端、后端、测试等）

### 10.3 管理任务依赖

- **避免循环依赖**: 确保任务依赖关系是无环的（DAG）
- **适度拆分**: 任务拆分不要太细，避免依赖链过长
- **并行设计**: 尽量设计可以并行执行的任务，提高执行效率

### 10.4 监控和调试

- **实时查看**: 计划批准后，保持对话框打开，实时查看任务状态
- **查看日志**: 在开发者工具控制台查看详细日志
- **分批验证**: 关键任务完成后，先验证结果再继续

## 11. 技术参考

### 11.1 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxRetries` | 3 | 任务最大重试次数 |
| `timeoutMs` | 300,000 (5 分钟) | 任务超时时间（毫秒） |
| `maxConcurrency` | 3 | 最大并行执行任务数 |

### 11.2 状态枚举

**计划状态**:

```typescript
type OrchestrationPlanStatus =
  | 'pending_approval'  // 等待审批
  | 'approved'          // 已批准
  | 'executing'         // 执行中
  | 'completed'         // 已完成
  | 'rejected'          // 已拒绝
  | 'error'             // 执行错误
```

**任务状态**:

```typescript
type PlanTaskStatus =
  | 'pending'     // 待执行
  | 'running'     // 执行中
  | 'paused'      // 已暂停
  | 'done'        // 已完成
  | 'cancelled'   // 已取消
  | 'error'       // 错误
```

### 11.3 Agent 类型

```typescript
type AgentType = 'planner' | 'pm' | 'worker'
```
