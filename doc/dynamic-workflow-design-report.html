01背景与目标

让 Agent 获得「模型自主编写 JavaScript 编排脚本 → 脚本内扇出子代理 → 结构化结果回传」的动态工作流能力（对齐 Claude Code / deepseek-harness 的 dynamic-workflows 范式），并与本项目现有的 LiteGraph 画布工作流、快照总线、子代理调度体系统一串联。

什么是「动态工作流」

与画布上的可视化节点图（静态、用户手工搭建）相对：动态工作流的编排逻辑由模型在对话中即时编写——一段纯 JS 脚本，用 agent() 扇出多个子代理，用 parallel()/pipeline() 控制并发与流水线，最后 return 一个 JSON 值作为工具结果。脚本本身没有任何文件/网络能力，子代理干活，脚本只做协调。

02参照实现解析（deepseek-harness）

脚本模型（hook 契约）

脚本在 node:vm 中执行，注入的全部全局只有 6 个：

agent(prompt, opts?)

起一个子代理跑到完成。无 schema → 返回最终文本；有 → 返回校验后的对象。子代理自身失败 → null（脚本 .filter(Boolean)）。opts 仅 label / phase / schema / provider / model。

pipeline(items, ...stages)

每个 item 独立串行流过所有 stage（stage(prev,item,index)），无跨 stage barrier。普通 stage 抛错 → 该 item 置 null。

parallel(thunks)

并发执行零参函数并全部等待（barrier）。抛错的 thunk → null。

phase(title)

进度分组叙事（纯观察，不施加执行结构），后续 agent() 归入该 phase。

log(message)

进度日志，投给观察者/UI。

args

工具调用传入的 args，structured clone 隔离，脚本改不动调用方数据。

失败语义分级 —— 最值得移植的设计 Fatal 引擎/契约错误（SCRIPT_PARSE / INVALID_ARGUMENT / AGENT_CAP / CANCELLED / RESULT_UNSERIALIZABLE…）穿透 parallel/pipeline 杀死整个脚本，worker 侧用 instanceof 判定（realm 外构造，脚本无法伪造也无法误吞）； 普通失败 子代理自身失败只把对应 item 置 null，脚本继续。

host ⇄ worker 闭合协议

  • worker → host：ready / phase / log / agent-start / agent-end / child-start{callId,request} / child-dispose / result（终态唯一）
  • host → worker：go / cancel{reason} / child-started / child-start-error / child-settled / child-failed / child-disposed
  • payload map 单一真源 + 判别联合 + assertNever，全部 plain JSON 过线（structured clone）
  • host 收到 child-start 后调 SubagentRuntime.start() —— 引擎不实现子代理，只做桥

04总体框架图（优化方案架构）

引擎放在 renderer（与子代理调度同进程），脚本跑 blob Web Worker（worker 源码以字符串常量内联，规避打包注册铁律），子代理走 UnifiedSubAgentDispatch 新增的轻量入口。

关键决策与理由

决策选择理由
引擎位置renderer（与 dispatch 同进程）child 桥零 IPC；卡片事件流不断链；blob worker 已有 CSP 处理先例
脚本隔离blob Web Worker（非 node:vm）renderer 无 Node；worker.terminate() 防死循环。隔离口径与 dsh 一致：可终止 + 结果边界，非安全边界
worker 源码形态字符串常量内联规避「URL worker 必须在 buildfile 注册」打包铁律，无独立产物文件
子代理 seamdispatch 新增入口，不建私有池预算/权限/看门狗/卡片全复用，与 delegate_task 行为一致

5.3 子代理桥：startWorkflowChild

// UnifiedSubAgentDispatch 新增最小入口（复用 fiber/预算/权限档，绕过 completionGate）
export interface IWorkflowChildRequest {
    prompt: string;
    schema?: JsonObjectSchema;   // 受限子集：type/properties/required/items/enum/const/oneOf
    agentId?: string;          // 内置/自定义 Agent 身份（缺省 general 档）
    model?: string;             // 模型覆写
    phase?: string; label?: string;
}
export interface IWorkflowChildHandle {
    id: string;
    result: Promise<{ output: string; structured?: unknown; stopReason: string }>;
    dispose(): Promise<void>;      // 幂等，memoized
}
  • schema 请求 → 子代理末步注入「输出 JSON」指令 → StructuredOutputParser 解析；失败 → stopReason:'failed' → 脚本见 null（符合 dsh 契约）
  • 卡片流：以 batchGroupId 投 SubAgentEvent，UI 天然获得并行子代理卡片组
  • 为何绕过 completionGate：脚本（schema + 自定重试）是比完成门更可靠的消费者

06失败 / 取消 / 限额（逐条对齐 dsh）

机制设计
fatal vs per-item nullWorkflowError + isFatalWorkflowError；组合子（parallel/pipeline）捕获后判定。基建故障 fatal，子代理自身失败 → null
result 永不 reject全路径映射 {value, stopReason:'completed'|'cancelled'|'error', error?, agentsStarted}
取消turn abort → handle.cancel() → worker hooks 抛 CANCELLED + slot waiter reject + children interrupt + grace 5s force-settle + terminate
恰好配对host liveAgents 账本；worker 死亡/grace 时合成缺失的 agent-end{cancelled}
capsmaxConcurrentAgents（默认=dispatch 并发）· maxTotalAgents=1000 · maxItemsPerCall=4096；设置键 sessions.agentStudio.workflow.*
模型纠错回路meta 校验/语法错同步抛 → isError 工具结果 → 模型改脚本重调
结果边界materializeFromRealm 只放行 plain JSON（拒函数/symbol/循环/稀疏数组/非有限数），违规 → RESULT_UNSERIALIZABLE fatal
与 dsh 的已知差异（如实声明） 无 node:vm 的同步切片 timeout → 纯同步死循环（while(true){}）会卡死 worker 线程，只能靠 host terminate 兜底（丢脚本进度）。缓解：工具 description 约束「避免无界同步循环」+ 启动前 new Function 编译做语法检查。
安全边界（与 dsh 口径一致） worker 隔离目标是可终止 + 结果物化 + 防误用遮蔽（fetch/WebSocket/importScripts 置 undefined），不是安全边界。能力面没有扩大：脚本自身无任何工具，一切副作用都经有权限档的子代理发生（explore 只读等）。

07节点串联三层设计（保证 IO 正确）

「节点正常串联、正常输入输出」在三层同时成立；串联正确性的根基全部复用既有设施，零新概念。

统一端口值模型（跨三层同一表示）

type PortValue =
  | { kind: 'text';  value: string }
  | { kind: 'json';  value: unknown }
  | { kind: 'media'; url: string; mime: string; stageUid?: string };
  • 编辑期：连线按 PortSpec.type 亲和校验（SAROS_JSON↔json、TEXT↔text、IMAGE/VIDEO↔media、ANY 通配）——现有 spec 体系直接支持
  • 运行期 fail-loud：kind 与端口期望不符 → 节点 ErrorBanner；上游无快照 → 明确报「上游节点尚无输出」，绝不传 undefined
  • 归档键一致性：继续走 registerAlias(nodeId, stageUid) 双前缀合并（run 写 uid、弹窗 savePayload 写 nodeId 的既有两路不变）

08工作流 UI 显示设计

聊天框中 workflow 以一张可折叠容器卡片呈现整个 run：头部聚合进度、展开体是 phase / agent / log 流、完成态附结果 JSON 卡。设计语言与 delegate_task 卡片同族（同族不同色：委派紫 🤝 vs 编排蓝 🔀），agent 行与 batchGroup 并行子代理卡片同源。

8.1 设计原则

  • 容器化聚合：几十个 agent 不刷屏——默认折叠为一行 + 3px 分段进度条；详情按需展开
  • 单一动画源：运行态只有头部 chip pulse + 运行中进度段流动，两处动画；聊天滚动时视觉安静
  • 事件驱动：卡片是 WorkflowEngineEvent 的纯投影（start/phase/agent-start/agent-end/end → UI 状态），无独立状态机，与 recorder/画布桥共享同一事件面
  • 失败可视化但不打扰：失败的 agent 是红色段 + failed → null 徽标（脚本能处理），只有 fatal 才让整卡转红
  • toolDisplayRegistry 注册：workflow → { emoji:'🔀', title:'工作流', renderType:'WorkflowRun' }，走既有工具卡片解析管线

8.2 卡片状态机与事件 → UI 映射

卡片状态进入条件（引擎事件）呈现
pending工具调用解析成功，引擎 start() 前头部骨架（meta.name + spinner chip），无进度条
runningstart蓝色 chip「运行中」pulse；分段进度条随 agent-start/agent-end 增段变色；头部计数 n/m agents · phase「当前」 + 计时器
completedend(stopReason:'completed')绿 chip；phase 条全勾；结果卡 = return 值折叠 JSON + agentsStarted + 总耗时 + 复制按钮（超 50k 字符截断提示）
cancelledend(stopReason:'cancelled')中性灰 chip（非错误）；进度条保留现场；说明行「Stop → 5s 内收敛、子代理全中断」
errorend(stopReason:'error')红边框 + 红 chip；等宽错误块（如 AGENT_CAP / SCRIPT_PARSE 原因）；isError 工具结果 → 模型下轮自我修正

10脚本编写规范

五条铁律 ① 纯 JavaScript（非 TS），顶层 await 可用，禁止 export const meta（meta 是参数不是代码）；
② 必须以 return <JSON值> 结束，返回值必须可 JSON 序列化（函数/symbol/循环引用 → run 失败）；
③ 无 fs / 网络 / 定时器 / Node API——子代理干活，脚本只协调；
④ agent() 失败返回 null（不是 throw）：下游先判空；
⑤ 用错 hook / 未知选项 / 超 caps 会立即杀死整个脚本（不会静默变 null）。

hook 速查

签名返回失败语义
agent(prompt, {label?, phase?, schema?, agentId?, model?})string（无 schema）/ 校验对象（有 schema）子代理失败 → null
pipeline(items, s1, s2, …)，stage(prev, item, index)any[]（与 items 对齐）stage 抛错 → 该 item → null，跳过其后续 stage
parallel([thunk, …])any[]thunk 抛错 → null（barrier：等全部）
phase(title) / log(msg)void—
args调用方传入的对象—
nodeOutput(stageUid, slot?) M2json 原值 / string / {kind:'media',…}查无 uid → fatal

const angles = ['架构', '性能', '安全']
const findings = await parallel(angles.map(a => () =>
  agent(`从 ${a} 角度评估本方案：${args.topic}`, {
    label: a, phase: '研究',
    schema: { /* 受限 JSON Schema：type/properties/required/items/enum/const/oneOf */ }
  })
))
phase('汇总')
const ok = findings.filter(Boolean)              // ★ 失败项是 null，先滤掉
return { count: ok.length, report: await agent(`合并以下发现写结论：${JSON.stringify(ok)}`) }

范式二：流水线串联（pipeline 无 barrier）

const topics = await pipeline(args.files,
  // stage 1：每文件一组发现（item A 在 stage2 时 item B 可仍在 stage1 —— 无整体等待）
  (prev, file) => agent(`分析 ${file}`, { schema: FINDINGS }),
  // stage 2：上游 null 短路，保持数组索引对齐（★ 推荐 pattern）
  (prev) => prev === null ? null : agent(`复核：${prev.title}`, { schema: REVIEW })
)
return topics.filter(Boolean)

范式三：取画布上游 + 结果回流（M2）

const sketch = await nodeOutput(args.sketchUid, 0)   // {kind:'media',url,mime}
const drafts = await pipeline(args.styles,
  (prev, style) => agent(`以 ${style} 风格细化此草图：${JSON.stringify(sketch)}`, { schema: DRAFT }))
return { drafts: drafts.filter(Boolean) }               // → 自动按 stageUid 归档 SAROS_JSON → 画布 OUTPUT
schema 受限子集：仅 type / properties / required / additionalProperties / items / enum / const / oneOf —— 不支持 pattern / format / 数值边界。超集 → UNSUPPORTED_SCHEMA fatal。
