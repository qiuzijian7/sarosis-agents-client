Sarosis 知识库 · 图谱生成与 MD 导出使用说明

Hyper-Extract（TS 移植引擎）接入后的实操指南 · 适用于 agentStudio 内置 kb_* 工具与侧边栏「知识库」视图
本文档覆盖三件事：① 如何生成图谱　② 如何把图谱导出成 Markdown（.md）文件　③ 检索与 RAG 问答的用法。所有能力均已在 src/vs/sessions/contrib/agentStudio/browser/knowledge/ 实现并通过单元验证（19/19 用例通过）。

一、接入现状一句话

本项目落地的是 Hyper-Extract 接入方案中的 「方案 B + 方案 C 混合体」：

  • 方案 C（TS 移植核心算法）：browser/knowledge/engine/ 下是纯 TS 的 BaseAutoType / AutoGraph / AutoList / OMem / InMemoryCosineIndex 引擎，无 Python 运行时依赖。
  • 方案 B（内置 kb_* 工具）：knowledgeTools.ts 注册了 kb_list_templates / kb_build / kb_add / kb_search / kb_ask / kb_export / kb_list / kb_delete，agent 可直接调用完成「构建 + 检索 + 导出」闭环。
  • 对应 Python 原版的 he parse / he search / he ask / export_obsidian：前三个对应 kb_build / kb_search / kb_ask，export_obsidian 对应本项目新增的 kb_export。
前置条件（缺一则工具会被自动隐藏）：
  • Embedding 服务可用 —— IAiEmbeddingVectorService.isEnabled() 返回 true。图谱检索与 RAG 都依赖向量空间，必须启用。
  • LLM 可用 —— 通过本项目已有的 BYOK / provider 配置解析（resolveChatModel），用于结构化抽取与答案生成。
  • 知识库落盘目录：默认 <userHome>/.saros/knowledge-base/<kbId>/kb.json（与侧边栏 Vault 共享根目录）。可在设置 agentStudio.knowledge.storage.path 中修改，修改后已有知识库会自动迁移到新目录。

二、如何生成图谱

方式 ①（推荐）Agent 工具流：kb_build

让 agent 在对话里直接构建知识库。标准三步：

kb_list_templates # 1. 查看可用模板（完整目录见 2.1，共 41 个：8 通用 + 30 领域 + 3 默认） → 返回: [{ id:"knowledge_graph", kind:"graph", ... }] kb_build # 2. 构建图谱（二选一提供内容） text: "Alice is an engineer at Acme who mentors Bob. ..." # 或 file_path: "docs/intro.md" template_id: "knowledge_graph" # 默认即 knowledge_graph title: "团队知识图谱" # 可选 → 返回: { id:"kb_xxxx", ... } # 记下这个 id，后续检索/导出都用它 kb_add # 3.（可选）增量追加文档，合并进同一图谱 id: "kb_xxxx" text: "Bob joined the platform team in 2024."

引擎内部流程（与 Python 版一致）：

kb_build → KnowledgeManager.create(templateId) 建空 session → manager.parseText(session, source) 摄入文本 → AutoGraph._extractData (two_stage) 先抽 nodes，再以 nodes 为上下文抽 edges → _pruneDangling 剪枝悬挂边（边两端必须存在节点） → OMem.add (nodeMemory / edgeMemory) 按 key 去重 + 合并 → manager.buildIndex() embedder 向量化 → InMemoryCosineIndex → manager.persist() 落盘 .saros/kb/<id>/kb.json
模板说明：kind:"graph" 的模板走 AutoGraph（输出 nodes + edges，支持 Mermaid 可视化 + Obsidian 双链导出）；kind:"list" 的模板（entity_list / faq / 各 model / set / hypergraph 类）走 AutoList，导出为 Markdown 条目列表（不再是「not supported」）。具体映射见 2.1。

2.1 模板目录（共 41 个，移植自 Hyper-Extract 预设）

方式 ② 侧边栏「知识库」视图（用户手动）

对应面板 KnowledgeBaseViewPane（视图 id agentStudio.knowledgeBase）：

  • UI 点击视图头「新建」→ createVault('我的知识库','📚') 创建知识库（Vault），自动建立 library/ 与 notes/ 两个分区。
  • UI 往分区里放文档后，文件增删改会触发 markSearchDirty()，选中/搜索时调用 rebuildSearchAssets() → _nativeKernel.build() + _index.build() + _graph.build() 重建全文索引与双链图谱。
两套入口的落盘位置不同：① Agent 工具走 .saros/kb/ + 引擎索引（语义检索/RAG）；② 侧边栏视图走 Vault 文件夹 + 原生内核索引（全文/双链）。二者目前不互通，按使用场景选择。

三、如何把图谱导出成 Markdown（.md）

这是 Hyper-Extract 原版 export_obsidian 在本项目的对应能力，由新增工具 kb_export 提供。

3.1 工具调用

kb_export id: "kb_xxxx" # 必填，kb_build 返回的 id output_path: "kb/team.md" # 可选：相对 workspace 或绝对路径，写盘为 .md title: "团队知识图谱" # 可选：文档标题（默认用 KB 标题） mermaid: true # 可选：是否包含 ```mermaid 图（默认 true） wikilinks: true # 可选：节点名是否用 [[wikilink]]（默认 true） # 省略 output_path 时，直接把 markdown 文本内联返回

行为：

  • 给定 output_path：经 IFileService.writeFile 写入（自动建父目录），返回 { success:true, path, bytes }。
  • 省略 output_path：返回 { success:true, markdown }，由 agent 自行贴回对话或写入。
  • kind:"graph" 模板：导出节点列表（[[wikilink]]）+ 关系列表 + ```mermaid 图。关掉 mermaid 可只留纯文本条目。
  • kind:"list" 模板（entity_list / faq / 各 model / set / hypergraph）：导出为 Markdown 条目列表（每条带字段，数组字段渲染为子列表）。不再返回「not supported」。

3.2 导出文件长什么样

导出的 .md 含三部分：节点列表（Obsidian [[wikilink]]）、关系列表、Mermaid 图谱。示例：

# 团队知识图谱

> 由 Hyper-Extract (TS) 知识引擎自动导出 · 节点 3 · 关系 2

## 节点 (Nodes)
- [[Alice]] (`Person`): 工程师，在 Acme 任职
- [[Bob]] (`Person`): 平台团队成员
- [[Acme]] (`Org`): 雇主公司

## 关系 (Edges)
- [[Alice]] --`works_at`--> [[Acme]]: Alice 受雇于 Acme
- [[Alice]] --`mentors`--> [[Bob]]: Alice 指导 Bob

## 图谱 (Mermaid)
```mermaid
graph LR
  n0["Alice"]:::Person
  n1["Bob"]:::Person
  n2["Acme"]:::Org
  n0 -->|works_at| n2
  n0 -->|mentors| n1
```
把该 .md 丢进 Obsidian / VS Code（装 Mermaid 预览插件）即可获得可点击跳转的图谱。节点名自动成为双向链接锚点。

3.3 直接在代码里导出（给二次开发）

import { KnowledgeManager } from './engine/knowledgeManager.js';
import { AutoGraph } from './engine/autoGraph.js';

// 已加载的 graph session：
const md = manager.exportMarkdown(session, { title: '团队知识图谱' });
// 或直接拿 AutoGraph 实例：
const md2 = graph.toMarkdown();
const mmd = graph.toMermaid();   // 仅 mermaid 块字符串

四、检索与 RAG 问答

构建完成后，检索是只读、低成本操作（仅 embedding + 余弦相似度），与构建（重 LLM 调用）解耦：

工具作用返回
kb_search语义检索，返回最相关的 nodes + edges{ type:"graph", nodes, edges }
kb_askRAG 问答：检索 → 组织成 context → LLM 生成答案{ answer, retrieved }
kb_list列出本工作区所有已持久化的知识库{ knowledgeBases:[...] }
kb_delete删除指定知识库及其索引{ deleted:id }

kb_search / kb_ask 调用链：handler → KnowledgeManager.load(id) → AutoGraph.search/chat → OMem.search → Embedder.embedOne(query) → InMemoryCosineIndex.search(topK)。检索前索引必须已 build（kb_build 已自动完成；从磁盘 load 时会恢复索引，无需重抽）。

五、文件布局与持久化

<userHome>/                       # 默认根目录，跨工作区共享
└─ .saros/
   └─ kb/
      └─ kb_xxxx/
         └─ kb.json        # { data:{nodes,edges}, metadata:{id,templateId,...}, index:{nodeIndex,edgeIndex} }

kb.json 同时保存数据、元数据与向量索引，load 后可无损恢复，无需重新跑 LLM 抽取。

落盘根目录与迁移
  • 默认路径：<userHome>/.saros/kb（解析逻辑见 resolveKbRoot()）。
  • 自定义：设置项 agentStudio.knowledge.storage.path。留空 = 默认；支持 ~（展开为用户主目录）、绝对路径；相对路径按用户主目录解析。
  • 自动迁移：当用户修改该设置时，_maybeMigrateKbStorage() 会把旧根目录下的全部 <id>/kb.json 移动到新根目录（已存在于新目录的不会被覆盖，迁移后旧文件删除）。
  • 历史兼容：早期版本把知识库存于 <workspace>/.saros/kb。首次激活时 _migrateLegacyKbStorage() 会把这些遗留数据一次性迁到新的用户级默认目录。

六、常见问题

Q：kb_build 不在工具列表里？
A：Embedding 服务未启用，embeddingService.isEnabled() 为 false 时整套 kb_* 工具会被隐藏（available 守卫）。先在设置里开启 Embedding。

Q：导出提示 "toMarkdown is not supported"？
A：该报错已移除——kind:"list" 模板（entity_list / faq / 各 model / set / hypergraph）现在也能导出为 Markdown 条目列表。若你仍想要 Mermaid 关系图，请改用 kind:"graph" 模板（如 knowledge_graph）重建。

Q：Mermaid 图渲染不出来？
A：确认 mermaid:true（默认开），且你的 Markdown 预览器支持 Mermaid（Obsidian 原生支持；VS Code 需装 Mermaid 插件）。节点名含双引号会被自动转义。

Q：增量更新后检索结果没变？
A：kb_add 会写回 kb.json 并刷新索引；若手动改了文件，重新调一次 kb_build 或 kb_add 即可重建索引。

八、操作日志格式说明

所有知识库操作（无论来自侧边栏视图，还是 Agent 引擎工具）都会以一行一条 JSON 的形式，追加写入操作日志文件 .op-log.jsonl。该日志用于审计与排障，写入失败会被静默吞掉（best-effort），绝不影响主业务操作。

日志位置
  • 默认：<userHome>/.saros/kb/.op-log.jsonl
  • 自定义：若设置项 agentStudio.knowledge.storage.path 非空，则写在 <该路径>/.op-log.jsonl（与第六节的根目录解析规则一致，支持 ~ / 绝对 / 相对路径）。
  • 侧边栏 Vault 数据本身在 .saros/knowledge-base，但操作日志统一汇聚到上述 .saros/kb 根，两路共用同一份日志。

格式：JSONL（JSON Lines），每行一条独立 JSON 对象，以 \n 结尾；多行之间互不嵌套。可直接用 jq -c '.status=="failure"' .op-log.jsonl 等工具流式分析。

8.1 字段 Schema

字段类型说明
tsstringISO-8601 时间戳（UTC，形如 2026-07-09T12:34:56.789Z）。省略时由系统自动补填。
opstring操作名，见 8.2。
channel"vault" | "engine"来源：vault=侧边栏「知识库」视图 / 笔记编辑器；engine=Agent 的 kb_* 工具。
status"success" | "failure"操作结果。
source?string源路径 / URL（导入、重命名等）。可选。
target?string目标路径 / 知识库 id。可选。
detail?object结构化补充信息（如 {itemCount, template}）。可选。
error?string失败时的错误信息（status==="failure" 时出现）。可选。

9.1 AFFiNE/BlockSuite 编辑器（替代 SiYuan Lute）

点击知识库笔记不再显示原始 Markdown 源码，而是通过 BlockSuite WYSIWYG 编辑器（Page + Edgeless 双视图）呈现：

  • 双视图：📄 页面（富文本块编辑，支持标题/列表/代码/引用/数据库块）+ 🎨 画布（白板/自由排版）
  • 保存机制：编辑器通过 Yjs CRDT 增量快照（.bsdoc sidecar）保存完整富块保真度；同时导出轻量 Markdown 供外部编辑。轮询自动保存（1.5s）。
  • 技术栈：@blocksuite/store@0.19.5 + @blocksuite/blocks@0.19.5 + @blocksuite/presets@0.19.5。预打包 bundle 6.2MB（已裁剪 shiki 语法 33 种主流语言 + JS 正则引擎替代 wasm）。

9.2 .md 为源 + .bsdoc 缓存（Phase A）

笔记持久化模型从「.bsdoc 优先」改为.md 为唯一源：

  • 外部编辑生效：用 VSCode / 其他编辑器直接修改 .md 文件后重新打开，BlockSuite 编辑器自动以新内容 seed（丢弃旧的 .bsdoc 缓存）。
  • .bsdoc 信封：Yjs 快照现包装为 {v:1, srcHash, snapshot} JSON，srcHash 是保存时 .md 内容的 djb2 哈希。打开时比对当前 .md 哈希——一致才复用快照（富块保真），不一致则从 .md 重新 seed。
  • 兼容旧版：旧版裸 base64 .bsdoc 仍能读取（用一次后下次保存自动转信封格式）。

9.3 全文检索增量缓存（Phase B）

启动时不再全量重读所有笔记文件：

  • BM25 索引持久化：在 Vault 根目录生成 .ftindex.json（FTS 缓存）+ .kbkernel.json（内核缓存）。
  • 增量 reconcile：启动时遍历文件用 stat 比对 mtime——未修改文件跳过重读（保留缓存条目），仅重新索引变更/新增文件。热启动近零磁盘读。
  • 图谱/提及内存派生：双链图谱（KbLinkGraph）与提及索引（_buildMentionIndex）从 FTS 索引的内存文档直接派生，不再二次磁盘遍历。

9.4 标签云视图（Phase C）

侧边栏 Vault 切换按钮旁新增 🏷️/📂 切换按钮：

  • 标签云模式：列出所有 #标签#（按引用数降序），点击即搜索含该标签的所有文档。
  • 文件树模式：保持原有的库/笔记两分区树视图。
  • 标签解析：沿用 SiYuan 兼容的 #标签# 双井号格式。

9.5 附件统一存储（Phase D）

每篇笔记对应一个 <note>.attachments/ 目录：

  • 目录结构：manifest.json（[{id,filename,mimeType,size,added}]）+ 附件文件 <id>.<ext>。
  • 解决 CSP 问题：附件不直接通过 file:// 协议加载（浏览器安全策略阻止），由宿主通过 webview URI 代理映射为 vscode-resource://。
  • 可移植性：复制笔记时同步复制 .attachments/ 目录即可保持附件引用完整。
  • API：KbAttachmentStore.save/read/delete/list/deleteDir，位于 browser/knowledge/kbAttachmentStore.ts。

9.6 存储根统一（Phase E）

Agent kb_* 工具与侧边栏 Vault 现在共享同一默认存储根 ~/.saros/knowledge-base/：

  • 引擎存储：agentStudio.knowledge.storage.path 默认值改为 .saros/knowledge-base（原 .saros/kb）。
  • 自动迁移：已有旧路径 ~/.saros/kb/ 内的知识库数据会在配置变更或首次激活时自动搬迁到新根。
  • 独立配置：两个路径仍可分别通过 agentStudio.knowledge.storage.path 和 agentStudio.kb.rootDir 独立覆盖。

9.7 编辑器包体优化

BlockSuite 编辑器 bundle（media/kbblocks.js）从 13.2MB 优化到 6.2MB（省 53%）：

  • shiki 语法裁剪：218 → 33 种主流语言（gen-shiki-curated.mjs 白名单管理）
  • oniguruma wasm（623KB）→ 纯 JS 正则引擎（@shikijs/engine-javascript + createHighlighterCore wrapper）
  • cpp/cpp-macro 语法（681KB）通过 onLoad stub 拦截（嵌入式语法相对路径）移除
  • @blocksuite/icons 5 份嵌套副本去重 → 1 份（esbuild onResolve 插件）
