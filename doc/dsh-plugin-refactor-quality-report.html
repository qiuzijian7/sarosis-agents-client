五、本重构周期的主要收口动作（代码事实）

5.1 工具面退役（legacy 侧注册归零）

共退役 10 个工具族：cronjob / kanban / memory / skills / media / sessions / kb / feishu / workflow / codebase。做法统一为「注释注册 → 删方法 → 摘 import → 摘 DI 注入」。builtinToolProvider.ts 由 1452 行降至 1113 行，并删除 17 个工具文件 + 对应测试。

5.2 死代码清理

  • 删 agentSchedulerService.ts（650 行 + 测试）——服务注册撤销后无人 import。
  • 删 agentYamlParser.ts——parseAndRegisterSchedules 全仓无调用方。
  • 删 6 个从未被注册的视图（共 1256 行）：sessionExplorerView / agentStudioSidebarView / agentStudioToolbarView / agentStudioViewPane / delegationTreeView / healthMonitorPanel。

5.3 缺陷修复

修复一个「看着跑过、其实没跑」的历史缺陷：agentSchedulerService 对 async * 生成器只 await 不迭代 ⇒ 调度器从未真正执行过任何定时任务。该事实同时修正了 dshModuleContainers.ts 里「legacy 调度器没有存量行为需要对齐」的判断依据。

5.4 门面与拆分

  • 中立层门面 9 个（sessions/common/*），dshHarness 对 agentStudio 的 common 层反向依赖清零。
  • React webview 拆分：删 features/taskboard/（1397 行）+ features/agentEditor/（1864 行），产物 25.5MB → 2.7MB（-89%）。

七、建议的下一步顺序

  1. 已加 --real-llm 分支（2026-10-17）：node poc/dsh-p0/scripts/workbench-e2e.mjs --real-llm，凭据从 DSH_E2E_REAL_BASEURL / DSH_E2E_REAL_APIKEY / DSH_E2E_REAL_MODEL 取（缺任一 ⇒ SKIP，不当失败），可选 DSH_E2E_REAL_REASONING=1。读数落盘时 .out/workbench-e2e.json 的 backend 字段会标明 kind: real-llm 还是 mock-llm ⇒ 日后不会把两者混为一谈。下一步只需在有凭据的机器上跑一次并稳定两个版本，5.1 即具备条件。
  2. 先把并行会话的 hero 文案测试修绿，恢复「红 = 新问题」的信号价值——目前 3 条常红会掩盖真实回归。
  3. 等真机窗口期再动 5.1 / 5.5。在此之前不建议继续扩大删除面：现有 legacy 代码里仍有 kanbanScrapeService（依赖 kanbanTools 常量）、scheduleViewRenderer（依赖 common/agentScheduler 类型）、McpToolProvider（动态 MCP 工具面）等仍在服役的耦合点。
  4. channels / pocket 的真机收口等凭据与跨仓排期，不阻塞主线。
口径提醒：本报告把「dsh 化率」分为两类——业务能力（应当 100% 由插件提供，已达成）与引擎能力（走官方件替换，legacy 侧代码待删）。把后者计入「未插件化」会得出错误的缺口结论：dsh 引擎不使用 legacy 的 file_read / terminal / providers，删掉它们不会造成任何能力回退。
