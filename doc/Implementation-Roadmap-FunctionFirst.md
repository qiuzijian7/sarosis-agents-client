# Implementation Roadmap — Function-First Strategy

> **版本**: v1.0
> **生成日期**: 2026-05-11
> **配套文档**: `Implementation-Task-Breakdown.md` v2.0（任务原子定义）
> **优先级策略**: 核心功能 → 测试用例 → 鲁棒性
> **总工时**: 62d（单人，关键路径 13–16 周；3 人并行 7–9 周）

---

## 0. 策略说明

本路线图基于 v2.0 任务清单（63 个原子任务、125.5d）按 **"功能优先"** 重新分桶为三个阶段。
v2.0 是任务的"完整规范"；本文档是"执行顺序"。两者并行使用：

- **v2.0 文档**：每个任务的目标、依赖、产出、验收
- **本文档**：什么时候做、为什么这个时候做、做完什么样子算可以进入下一阶段

### 0.1 设计原则

| 原则 | 落地 |
|------|------|
| **MVP 闭环优先** | Stage 1 只做"用户问 → Agent 答 → 工具用"完整链路 |
| **测试不是 0 就是 100** | Stage 1 末期保留 **happy-path 烟雾测试**（5–8 个 E2E）作为合并门槛 |
| **加固不是 1 次性** | Stage 3 按风险优先级排，可中断、可分批 |
| **DI 契约必须早锁** | Phase 1（OS 六槽接口）必须在 Stage 1 就稳定，否则 Stage 3 多 Provider 撕扯 |
| **日志先于错误码** | Stage 1 至少结构化日志，错误码体系延后到 Stage 2 |

### 0.2 阶段总览

```
Stage 1: 核心功能闭环 ─── 8–9 周 / 34d ── MVP demo 跑通
              ↓
Stage 2: 测试补全 ────── 2–3 周 / 12d ── CI 绿，主流程不可回归
              ↓
Stage 3: 鲁棒性加固 ───── 3–4 周 / 16d ── 安全 → 数据 → 性能 → 能力增强
```

---

### 1.2 验收标准（Definition of Done）

✅ **功能**：
- 启动 VS Code → 打开 Agent Studio → 发起对话 → Knot 流式返回
- Agent 能调用 `file_read`/`file_write`/`shell` 三个内置工具
- 关闭重启后能在 sessions 列表看到上次对话
- 多工作区切换不丢消息

✅ **工程**：
- 6 个核心 OS 接口签名冻结
- 烟雾用例全绿（CI 阻塞）
- 结构化日志覆盖：会话开始/结束、工具调用、Provider 调用

❌ **明确不验收**：
- 无覆盖率要求
- 无性能 SLO
- 无 i18n
- 无错误码体系
- 无数据迁移工具

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| **Stage 1 跳过测试导致回归** | Stage 2 变重写 | S1-J 烟雾测试 + 结构化日志硬性合并门槛 |
| **DI 接口在 Stage 3 才发现要改** | 多 Provider 全部重做 | Phase 1 接口 RFC review，签名变更需评审 |
| **MVP 上线后用户发现安全问题** | 紧急回滚 | Stage 3 优先级 1 不可压缩，灰度前完成 |
| **数据格式 Stage 1 没设计好** | Stage 3 无法平滑迁移 | sessions schema 定义时预留 `version` 字段 |
| **Knot 单点依赖** | Knot 服务挂导致全断 | Stage 3 至少补 1 个 Provider 作为降级 |
