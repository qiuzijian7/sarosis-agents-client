# Agent 搭建 — 架构流程图

> 本文档描述了从用户输入到任务完成的完整 Agent 系统架构与执行流程。

---

## 1. 架构总览

整个 Agent 系统由 **五大核心模块** 组成：

| 模块 | 职责 | 说明 |
|------|------|------|
| **用户输入层** | 接收用户请求 | 自然语言 Query，是流程的起点 |
| **意图识别与任务规划** | 理解需求并拆解任务 | 由 LLM 驱动，将模糊输入转化为可执行计划 |
| **记忆系统** | 维护上下文与知识 | 支撑 LLM 在推理过程中拥有持久化与临时性记忆 |
| **执行循环** | 逐步完成子任务 | 核心引擎，负责思考→行动→观察的闭环 |
| **知识库** | 提供领域知识支撑 | 为 Agent 提供外部事实、业务规则与参考信息 |

## 2. 详细流程说明

### 2.1 用户输入 (Query)

- **作用**：接收来自用户的自然语言请求，是整个 Agent 系统的触发点。
- **输入形式**：文本消息、语音转文字、结构化命令等。
- **关键考量**：
  - 输入可能模糊、不完整或包含歧义
  - 需要支持多轮对话的上下文继承
  - 应考虑输入的安全性与合规性检查

### 2.2 意图识别与任务规划 (LLM)

这是 Agent 的"大脑"，负责将用户模糊的需求转化为清晰的执行计划。

**核心功能**：
1. **意图识别**：分析用户输入，判断用户想要做什么（查询、计算、生成、操作等）
2. **任务拆解**：将复杂请求分解为多个可执行的子任务
3. **依赖分析**：识别子任务之间的先后依赖关系
4. **计划生成**：输出结构化的执行计划（如 JSON/XML 格式的任务列表）

**与记忆系统的交互**：
- 读取短期记忆，了解当前对话上下文
- 读取长期记忆，获取用户偏好、历史交互模式
- 将新的对话记录写入短期记忆

**示例**：
```
用户输入："帮我分析一下上个月的销售数据，并生成一份图表报告"

LLM 输出计划：
1. [查询] 从数据库获取上月销售数据
2. [计算] 对数据进行汇总与统计
3. [生成] 创建可视化图表
4. [文档] 生成报告文档
```

### 2.3 记忆系统 (Memory)

记忆系统为 Agent 提供了"记忆能力"，使其能够在多轮交互中保持连贯性。

#### 2.3.1 短期记忆 (Short-term Memory)
- **内容**：当前对话历史、最近几轮的用户输入与 Agent 回复
- **特点**：容量有限、访问速度快、随会话结束而清除
- **实现方式**：对话上下文窗口、滑动窗口机制
- **作用**：让 Agent 理解当前对话的上下文，避免重复询问已知信息

#### 2.3.2 长期记忆 (Long-term Memory)
- **内容**：用户画像、偏好设置、历史任务结果、领域知识
- **特点**：容量大、持久化存储、可检索
- **实现方式**：
  - 向量数据库（如 Milvus、Pinecone、Weaviate）
  - 关系型数据库（结构化信息）
  - 文档存储（非结构化知识）
- **检索方式**：基于语义相似度的向量检索、关键词检索、混合检索

#### 2.3.3 记忆管理策略
| 策略 | 说明 |
|------|------|
| **记忆写入** | 将重要信息从短期记忆提炼并持久化到长期记忆 |
| **记忆更新** | 当用户偏好或事实发生变化时，更新已有记忆 |
| **记忆遗忘** | 定期清理过时或低价值的记忆，控制存储成本 |
| **记忆召回** | 根据当前 Query 的语义，从长期记忆中检索相关信息 |

### 2.4 执行循环 (Action Loop)

执行循环是 Agent 完成任务的**核心引擎**，采用 **ReAct（Reasoning + Acting）** 范式，不断迭代直到任务完成。

#### 2.4.1 循环步骤

```
┌─────────────────────────────────────────┐
│            Action Loop                  │
│                                         │
│  1. 思考 (Thinking)                     │
│     └─▶ "下一步该做什么？"              │
│                                         │
│  2. 选择工具 (Action)                   │
│     └─▶ "使用哪个工具？"                │
│                                         │
│  3. 输入参数 (Action Input)             │
│     └─▶ "需要哪些参数？"                │
│                                         │
│  4. 调用工具 (Function Call)            │
│     └─▶ "执行工具"                     │
│                                         │
│  5. 观察结果 (Observation)              │
│     └─▶ "得到结果"                     │
│                                         │
│  6. 任务完成?                           │
│     ├─▶ 否 ── 返回步骤 1               │
│     └─▶ 是 ── 生成最终回复             │
└─────────────────────────────────────────┘
```

#### 2.4.2 各步骤详解

**① 思考 (Thinking)**
- Agent 分析当前任务状态，评估已完成的步骤和剩余的工作
- 结合记忆系统中的信息，推理下一步最优行动
- 输出思考过程（Chain-of-Thought），提高可解释性

**② 选择工具 (Action)**
- 根据思考结果，从工具库中选择最合适的工具
- 工具选择可以基于：
  - 规则匹配（关键词、正则表达式）
  - LLM 决策（让模型判断哪个工具最适用）
  - 强化学习（根据历史执行效果优化选择策略）

**③ 输入参数 (Action Input)**
- 为选定的工具准备输入参数
- 参数来源：
  - 用户原始输入中提取
  - 前序步骤的结果
  - 记忆系统中的上下文信息
- 需要参数校验，确保类型、格式、范围符合工具要求

**④ 调用工具 (Function Call)**
- 实际执行工具函数
- 调用方式：
  - 本地函数调用（同步/异步）
  - 远程 API 调用（HTTP/gRPC）
  - MCP (Model Context Protocol) 协议调用
- 需要考虑超时、重试、错误处理等机制

**⑤ 观察结果 (Observation)**
- 接收工具执行返回的结果
- 结果处理：
  - 解析原始输出（JSON、XML、文本等）
  - 错误检测与异常处理
  - 结果摘要与关键信息提取
- 将观察结果反馈给 LLM，用于下一轮思考

#### 2.4.3 循环终止条件

| 条件 | 说明 |
|------|------|
| **任务完成** | 所有子任务已执行完毕，达到预期目标 |
| **最大迭代次数** | 防止无限循环，设置安全上限（如 10-50 次） |
| **用户中断** | 用户主动取消或修改请求 |
| **错误阈值** | 连续失败次数超过限制，终止并返回错误 |
| **超时** | 整体执行时间超过设定阈值 |

### 2.5 工具库 (Tools)

工具库是 Agent 的"双手"，使其能够与现实世界交互，完成各种实际操作。

#### 2.5.1 工具分类

| 类别 | 示例工具 | 典型用途 |
|------|---------|---------|
| **搜索工具** | Web 搜索、内部搜索引擎、知识库检索 | 获取实时信息、补充知识 |
| **计算工具** | 计算器、数据分析引擎、统计工具 | 数值计算、数据聚合 |
| **查询工具** | SQL 查询、NoSQL 查询、API 查询 | 从数据库或接口获取数据 |
| **文档工具** | 文档读取、PDF 解析、Markdown 处理 | 处理非结构化文档 |
| **代码工具** | 代码执行、代码解释、Lint 检查 | 编程辅助、自动化脚本 |
| **可视化工具** | 图表生成、报表渲染、UI 绘制 | 数据可视化、结果展示 |
| **通信工具** | 邮件发送、消息推送、API 回调 | 外部通知与协作 |
| **文件工具** | 文件读写、压缩解压、格式转换 | 本地文件操作 |

#### 2.5.2 工具注册与管理

```typescript
// 工具定义示例
interface Tool {
  name: string;           // 工具名称
  description: string;    // 功能描述（供 LLM 理解）
  parameters: JSONSchema; // 参数结构定义
  handler: Function;      // 执行函数
  timeout?: number;       // 超时时间
  retry?: number;         // 重试次数
}

// 工具注册
function registerTool(tool: Tool): void;
function unregisterTool(name: string): void;
function listTools(): Tool[];
```

#### 2.5.3 工具调用协议

推荐采用 **MCP (Model Context Protocol)** 或类似标准化协议，实现工具的统一描述与调用：

- **输入标准化**：统一参数格式（JSON Schema）
- **输出标准化**：统一返回结构（成功/失败状态、数据、错误信息）
- **发现机制**：Agent 动态获取可用工具列表及其描述
- **安全隔离**：工具执行在受控环境中，防止恶意操作

### 2.6 知识库 (Knowledge)

知识库为 Agent 提供**领域特定知识**和**外部事实信息**，弥补 LLM 训练数据的时效性与专业性不足。

#### 2.6.1 知识来源

| 来源 | 内容 | 更新频率 |
|------|------|---------|
| **企业文档** | 产品手册、技术文档、内部规范 | 按需更新 |
| **FAQ 问答** | 常见问题与解答 | 持续积累 |
| **业务数据** | 交易记录、用户行为、运营指标 | 实时/准实时 |
| **外部知识** | 行业报告、新闻资讯、学术文献 | 定期同步 |
| **代码仓库** | 源码、注释、设计文档 | 随版本更新 |

#### 2.6.2 知识检索流程

```
用户Query ──▶ 向量化 ──▶ 向量数据库检索 ──▶ 相关性排序 ──▶ Top-K 片段 ──▶ 上下文注入
```

**关键技术**：
- **Embedding 模型**：将文本转化为高维向量（如 BGE、OpenAI text-embedding）
- **向量数据库**：高效存储与检索向量（如 Milvus、Pinecone、Qdrant）
- **RAG (Retrieval-Augmented Generation)**：检索增强生成，将检索结果作为上下文提供给 LLM
- **重排序 (Re-ranking)**：使用更精确的模型对初步检索结果进行二次排序

#### 2.6.3 知识库与记忆系统的区别

| 维度 | 记忆系统 | 知识库 |
|------|---------|--------|
| **内容性质** | 交互上下文、用户偏好 | 领域知识、事实信息 |
| **更新方式** | 自动记录对话 | 人工维护或自动同步 |
| **生命周期** | 会话级或用户级 | 长期持久 |
| **使用场景** | 保持对话连贯性 | 回答专业问题 |
| **典型实现** | 上下文窗口、向量库 | 文档库、数据库、搜索引擎 |

### 2.7 生成最终回复 (Final Answer)

当执行循环判定任务完成后，Agent 需要整合所有子任务的结果，生成面向用户的最终回复。

#### 2.7.1 回复形式

| 形式 | 适用场景 | 示例 |
|------|---------|------|
| **文本回复** | 一般性问答、解释说明 | "根据分析，上月的销售额增长了 15%..." |
| **结构化数据** | 数据查询、配置输出 | JSON、YAML、表格数据 |
| **图表/可视化** | 数据分析、趋势展示 | 折线图、柱状图、饼图、仪表盘 |
| **文件/报告** | 复杂文档、正式输出 | PDF 报告、Word 文档、Excel 表格 |
| **代码片段** | 编程辅助、自动化脚本 | Python、JavaScript、Shell 脚本 |
| **混合形式** | 综合场景 | 文本 + 图表 + 附件 |

#### 2.7.2 回复生成策略

1. **结果聚合**：收集执行循环中各步骤的输出
2. **信息去重**：消除冗余信息，保持回复简洁
3. **格式化**：根据用户需求选择合适的呈现形式
4. **引用标注**：如涉及外部知识，标注信息来源
5. **可操作性**：对于需要用户进一步操作的结果，提供明确指引

## 3. 数据流与交互关系

### 3.1 图例说明

| 线条样式 | 含义 |
|---------|------|
| 黑色实线 | 核心流程（输入→处理→输出） |
| 双向箭头 | 双向交互（读取/写入） |
| 橙色虚线框 | 工具/外部系统 |
| 紫色虚线框 | 记忆/知识模块 |
| 蓝色实线框 | 执行循环 |

### 3.2 完整数据流

```
阶段 1: 输入接收
  用户 ──Query──▶ Agent系统

阶段 2: 意图理解与规划
  Agent系统 ──Query + 短期记忆──▶ LLM
  LLM ──执行计划──▶ Agent系统

阶段 3: 执行循环（可能多轮）
  Agent系统 ──思考Prompt──▶ LLM
  LLM ──思考结果──▶ Agent系统
  Agent系统 ──工具选择──▶ 工具库
  工具库 ──执行结果──▶ Agent系统
  Agent系统 ──观察结果──▶ LLM（新一轮思考）

阶段 4: 知识检索（按需）
  Agent系统 ──Query──▶ 知识库
  知识库 ──相关片段──▶ Agent系统

阶段 5: 结果输出
  Agent系统 ──整合结果──▶ LLM
  LLM ──最终回复──▶ 用户
```

## 4. 关键设计原则

### 4.1 模块化设计
- 各模块（记忆、工具、知识库）独立封装，通过标准接口交互
- 支持模块的热插拔与动态扩展

### 4.2 容错与降级
- 工具调用失败时，自动重试或切换备选工具
- LLM 推理异常时，回退到预设规则或安全回复
- 外部服务不可用时，使用本地缓存或简化流程

### 4.3 可观测性
- 记录完整的执行轨迹（Trace），便于调试与审计
- 每个思考步骤、工具调用、知识检索均有日志记录
- 提供执行过程的可视化展示

### 4.4 安全性
- 工具执行权限分级，敏感操作需确认
- 输入输出进行安全过滤，防止注入攻击
- 知识库访问控制，保护敏感信息

### 4.5 性能优化
- 缓存常用工具结果与知识检索结果
- 并行执行无依赖的子任务
- 向量化检索使用近似最近邻算法（ANN）加速
