一句话结论

两套框架不是同一层，不能直接互相替换。

官方 Agent Teams 是 根会话 + subagent 树 + 共享任务板 的任务协作层；Bots 群聊团队是 持久 Bot 名册 + 群会话 + 成员独立影子会话 + @ 接力 的会话编排层。当前 officialTeamAdapter.js 只把官方成员只读投影到本机 Bot 名册；官方 Team 不读 vssaros.team 总线，群聊也不写官方任务板。

P1 gate=BLOCKED 当前群成员是 sessionController.create() 创建的独立会话，不是官方 continuable 后代；官方任务 owner/assignee 只认 root 或这类后代。加上随包 dsh-base 默认未开放 allowedAgentPresets，以及 2026-11-14 CDP 只读探针确认客户端没有「按 Bot preset 建后代」的公开方法，所以结论仍是：不迁移存量群、不双写任务板、不伪造调用方身份。

框架图

两套框架并列装在同一个 dsh Host 中。左边是官方 rc.2 的 Team 服务与 UI；右边是 VsSaros 的群聊运行时与表现层；中间只有只读投影和工具放行，没有共享成员/消息/任务。

官方智能团队 · Agent Teams
root + continuable subagents + shared task board
L0 宿主与开关
  • dsh-base 默认加载 Team 服务，defaultEnabled:false。
  • dsh-agent-team：isEnabled / setEnabled / createTask / getTask / listTasks / updateTask；没有 roster/member 方法。
  • 开关写 team/mode 到 root session，再 sessions.flush()，由 projection.ts 推 agentTeam 投影。
L1 工具面
  • 共享任务：team_task_create / team_task_list / team_task_get / team_task_update，带 when: agentTeams.isEnabled(agent)。
  • 成员发现与通信：subagent / subagent_fork；list_agents / send_message / wait_agent / interrupt_agent。
  • agent_preset 仅在 allowedAgentPresets 配置后对模型可见；当前默认继承父 preset。
L2 任务语义
  • 状态：pending / in_progress / completed / deleted tombstone。
  • 字段：blocked_by、write_scopes、expected_revision、ownerId。
  • 动作：claim / release / edit / set_dependencies / complete / reopen / reassign / delete。
  • CAS 按单任务 revision；依赖未满足不可认领；write_scopes 只警告重叠，不是文件锁。
  • owner/assignee 只认 exact live caller 或 mode === 'continuable' 的 listDescendants() 后代。
L3 官方 UI 与投影
  • mount.ts：conversation.input.model.options → TeamModeToggle。
  • conversation.session.header.actions.subagent.footer → TeamBoard（只读任务板）。
  • conversation.chat.commandview → TeamCommandRow；shell.overlay → TeamDisableConfirmation。
  • 任务事件写 root session 日志并回放；任务板通过投影帧更新，改任务只能让模型调工具。
Bots 群聊团队
持久群定义 + 群会话 + 成员影子会话 + 接力编排
L0 数据与契约
  • agent-rooms.json：ROOMS_FILE_VERSION=2，含 rooms[]、rounds[] 快照、pendingMessages、digestPending / digestStartedAt。
  • <file>.owner 单写者租约；未来版本只读冻结；写失败返回 409/503，不假成功。
  • contracts/group-activity.schema.json：vssaros-group-progress、房间变更、dock 可见性等 window 事件契约。
L1 群运行时
  • lib/core/rooms.js：纯逻辑，openingCall、callsFrom、四档 wakeMode、roundStatusOf、ROUND_SCHEMA=1。
  • lib/rooms.js：群会话不调模型，relayStream 合成 group_relay；relay() 取 inbox/callbacks，按 maxConcurrentTurns 限流派发。
  • 成员由 sessionController.create(..., agentPreset) 建独立影子会话；同成员 single-flight + 回合串行。
  • 轮次写穿：replies / events / speaking / approvals / asks / late / background；重启未完成轮次收口为 cut。
  • POST /x/agents/api/rooms { action:'cancel', id, callId? } 中止在途轮次并调用 Agent.cancel({kind:'user'})。
L2 人机协作与目标
  • core/goals.js：group_goal 阶段账本，start / status / pass / rework / revise / complete / stop；证据验收与返工。
  • core/asks.js：group_ask 选择卡，最多 6 题、推荐项、打字顶替卡片。
  • 群成员工具审批由群接住：approve allow/reject；ask-answer / skip 回叫成员。
  • 阶段任务只是 { botId, task, status }，没有 taskId、依赖 DAG 或 CAS。
L3 表现层与跨插件消费
  • client.workspaces.js：Bots 页签、群行、新建群聊、右键菜单、活动群「停止本轮」、全局执行浮层。
  • client.conversationViews.js：群设置卡、GroupRelayView、GroupMemberDock、审批与选择卡。
  • client.subagents.js 与官方子代理目录共用 conversation.session.header.actions 槽位。
  • SuperAgent group_route 表 / group-runs.tsx / flow-card.tsx 只读消费群进度，不改 Ticket/Step/SSE。

两条主数据流

官方 Team：开关 → 投影 → 下一回合工具可见 → 任务板。
1 用户打开开关
模型菜单 TeamModeToggle，仅 root 会话
→
2 Host 持久化
setEnabled(root,true) → team/mode → flush()
→
3 投影回写
agentTeam.enabled=true，约 1–2s 后 UI 更新
→
4 下一模型回合
注入 team:policy 与 4 个 team_task_*
→
5 建成员与任务
subagent / list_agents / send_message / team_task_create
→
6 CAS 流转
get → update(claim, expected_revision) → complete
→
7 只读任务板
TeamBoard 显示共享任务；无任务时 return null

官方不会自动唤醒成员；依赖满足、任务变更、模式切换都不主动起回合。owner 失活也不会自动释放。

Bots 群聊：用户消息 → 合成工具 → 成员影子会话 → 群记录/进度/目标。
1 用户发消息
source.kind==='user' 进 inbox；或 postToRoom 转投
→
2 群会话不调模型
relayStream 合成一次 group_relay
→
3 选人与限流
openingCall 四档唤醒；running.size < maxConcurrentTurns
→
4 成员影子会话
followup / steer → waitFor → noteTurnEnd
→
5 结果回写
room.log + rounds[] + tool result + relayAnswerText()
→
6 UI 与跨插件
GroupRelayView / MemberDock / Bots 行 / vssaros-group-progress
→
7 人机闭环
group_goal / group_ask / 审批 / 后台迟到 / cancel / 重启 cut

群聊没有官方任务板的 CAS/DAG；group_goal 是按阶段、按 Bot 推进的验收账本，适合讨论与返工，不适合多成员抢占同一任务。

集成边界与门禁

工具放行
TEAM_TASK_TOOL_PREFIX='team_task_' 与 mcp__* 同口径，避免写了 tools: 的 Bot 把官方 host plane 全局工具 deny 掉。显式写 !team_task_* 可排除；官方 when: agentTeams.isEnabled(agent) 仍保证关闭时不可见。
只读适配器
officialTeamAdapter.js 监听成员事件，按 root → listDescendants() → continuable 过滤 → registerExternalBot('dsh-team:*')，附 taskBoardSummary()。不 createTask、不 updateTask、不 send_message。
P1 gate=BLOCKED
四个缺口：① 群成员是独立会话；② 官方 owner 只认 root/continuable 后代；③ allowedAgentPresets 默认未开放；④ 运行时 remote 没有按 Bot preset 建后代的公开方法。结论是不迁移、不双写、不伪造身份。
若要继续迁移，先补两件事

Host 侧动态 allowedAgentPresets 配置（覆盖动态 Bot 名册），以及真实 subagent 生成回归：验证模型、技能、MCP、审批、Workspace Grant、工作区权限不丢失。验证不通过就维持群聊作为人物/对话/审批层，官方 Team 只作为独立能力存在。
