1总览与分层

系统分三层，边界由一条进程内总线固定下来：判断交给模型，护栏由代码保证。Bots 插件管 bot 的名册、会话、记忆与委派；superagent 管计划、任务、选人、预算与沉淀；两者不互相 import，只通过 globalThis[Symbol.for('vssaros.team')] 通信。

交互层 · DSH Desktop

左侧会话区（对话 / 轨迹 / 记忆 / 技能 / 待办 / Bot 设置）复用 dsh 聊天框与记忆系统；右侧业务区是 superagent 自己的概览 / 来源 / 触发 / 评估 / 设置。

判断与编排

桥接层 · 团队总线

version 1，挂 globalThis 而非 import；任一侧 HMR 重载，订阅与登记都不丢。提供名册、委派、建 bot、外部 bot 与终态回报。

唯一跨包通道

Bots 层 · vssaros-agents

扫描两个根的 .agent.md、开新会话并 steer 任务、回合结束登记报告、写技能草稿区、注册 preset、维护外部 bot 名册。

执行与资产
三条设计约束
  1. 不另起名册：能力卡片来自 scanAgentsFromConfig（内置 + 自定义两个根），主管创建的 bot 写进同一个目录并带 created-by: supervisor。
  2. 不另起技能库：复盘产出写到 <dataRoot>/skills/<id>/SKILL.md，待审核的放 .drafts/，与 vssaros-skills 同一格式同一目录。
  3. 不另起回复通道：bot 回合结束由 installAssignmentTracker 发布终态到总线，Team 处理后用 durable relay 送回主会话，不走 relay 的自动回传（会重复）。

2组件框架图

蓝框是 superagent 的编排组件，蓝底长条是进程内总线，绿框是产出资产。实线箭头是向下派活，绿色虚线是向上回报。

总线为什么挂在 globalThis：两个插件是独立包，不能互相 import；HMR 重载时模块闭包会重建，注册表与订阅表放在总线对象上才不会丢。Team.install() 另用 Symbol.for('vssaros.team.subscription') 保证同一进程只有一份订阅，避免新旧实例抢着推进同一个计划。

4数据与存储

8 张表都在 orchestrator.sqlite，用 CREATE TABLE IF NOT EXISTS 在各自模块构造时建立，表名统一加 team_ 前缀，避开老库 schema 6 遗留的 task 表。按用途分三组：

计划域 · 4 张

team_plan 计划（goal / status / cwd / ticketId）
team_task 步骤（after 依赖 / state / hop / att / report / assignmentId）
team_member 实际参与过的 bot
team_exchange 每次给 / 报 / 失败 / 取消的往来（seq / hop / from / to / kind）

TeamStore · src/app/team.ts

资产域 · 2 张

team_bot 主管创建的 bot（配额计数、preset、文件路径）
team_approval 高风险建 bot 草稿（draft → approved / rejected）

TeamStore · 由团队总线 createBot 写入

复盘域 · 2 张

team_skill 技能记录（scope / origin / evidence / risk / version / file）
team_workflow 工作流（params / steps / gates / budget / triggers / runs / ok）

表之间的关系

关系键说明
plan → taskteam_task.plan → team_plan.id一个计划 ≤12 步；步骤 key 在计划内唯一，after 只能引用同计划已存在的 key，成环直接拒绝。
task → exchangeteam_exchange.plan + stepId每次派活、回报、失败、取消记一条；hop 累计跳数，上限 6。
task → assignmentteam_task.assignmentId指向 Bots 委派台账里的记录；对账时按它 bus.get(id) 补齐重启期间错过的终态。
plan → botteam_bot.plan每计划最多 3 个主管创建的 bot；全局最多 20 个。
plan → skill / workflowplanId / fromPlanId计划结束时由 onPlanEnd 生成；幂等 + 并发保护，重复结束不会重复沉淀。
workflow → plan（复跑）fromPlanId 只记来源命中已保存工作流时，用它的 steps 生成一个新计划，runs+1。

技能正文不只在表里：team_skill.file 指向共享技能库中的 SKILL.md（或 .drafts/SKILL.md）。frontmatter 至少含 name / description / version，title 会被映射成 displayName；scope / origin / evidence / risk 写进正文（技能库元数据白名单会丢）。

5契约清单

5.1 团队总线（跨包，只增不改）

方法方向说明
provide(impl) / available()Bots → 总线顶层角色注册实现；消费者先判 available，Host 启动早期会明确报错而不是静默。
listBots()superagent → Bots能力卡片数组，过滤隐藏 bot，带 origin: 'supervisor' 标记。
delegate({bot,task,cwd?,fromName?})superagent → Bots开新会话 + 会话级模型选择 + steer；返回 AssignmentView；并发上限 8，超限立即 409 不排队。
createBot({draft})superagent → Bots校验并写 .agent.md、标 created-by: supervisor、初始化记忆、同步 preset；全局 20 个兜底。
subscribe(fn) / publish(view)Bots → superagent回合结束或中断时发布终态；订阅者抛错不影响别人。
get(id) / cancel(id,reason?)superagent → Bots对账与停止计划时取消运行中的委派。
registerExternalBot(spec)superagent → Bots把 SuperAgent 登记进 Bots 名册；agent_message 命中时调 onMessage 送进主管会话。

5.3 送回主会话的事件

事件时机载荷要点
team_report每个步骤终态plan / step / title / bot / state / report 或 error；requestId 带 hop，天然幂等。
team_plan_end所有步骤终态plan / goal / state（done / failed）/ 各步骤状态；提示用报告回答请求。

两者都走 sessions.relay() 的 durable effect，Host 重启不丢。

6闸门与配额

调度

每计划并行 3；最多 12 步（含追加）；接力最多 6 跳；报告截断 2000 字（全文留在 bot 会话日志）。

建 bot

每计划 3 个、全局 20 个；同名 / 同 id 返回现有 bot，不重复创建。

风险分级

申请 shell 写、外发、凭据、git push/tag 等 → 待办，人批准；只读 / 查 / 跑测试 → 自动批准。技能正文含命令或外发同样进 .drafts/。

沉淀

技能描述覆盖率 ≥ 0.8 命中已有技能 → 发新版本；工作流匹配 ≥ 70% → 直接套用；工作流预算 300k tokens / 90 回合 / 并行 3。

失败与恢复

情况代码行为
某步骤失败 / 无文本产出标 failed 并 relay 原因；所有等待它的步骤级联标 skipped；计划以 failed 结束，仍触发复盘产出「回归检查」技能。
委派并发已满 / bot 不存在Bots 侧结构化报错（409 / 404）；give() 捕获后把步骤标 failed 并写明原因，不静默。
报告早于 delegate() 返回Team.early 先收下，登记 assignmentId 后再补处理。
任一侧重启 / 晚加载install() 每 30 秒重试订阅与对账，按 bus.get(assignmentId) 补齐错过的终态。
人停止计划运行中的委派逐个 cancel，等待中的步骤标 skipped，计划置 cancelled（不触发复盘）。
