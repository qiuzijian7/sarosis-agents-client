0. 一句话

dsh 是一个**被壳启动的进程**（"boot a DeepSeek Harness profile —— an ordered stack of plugin-bundle patch layers under your own overrides"，dsh --help ✓ 已核对）。 壳要做的事只有四类：**① 把它抬起来**、**② 跟它握手（控制桥）**、**③ 满足它反向问你的事（ide.request）**、 **④ 托管它自己产出的页面**。其余全是 dsh 内部（插件、工具、技能、MCP、审批默认值）✓。

1. 进程与 profile（壳必须能拼出一次启动）

契约壳必须提供证据不做会怎样 ✗
启动命令行 dsh --profile <name> [--patch <yml> …] [app-args…]；--dump-config 自检组合；--from-default-profile <tpl> 建新 profile dsh --help ✓ 已核对（实测输出见探针 p3-23/24/25） 壳会去猜"组合对不对"，而 dsh 已经把答案（组合后的树）给你了 ✓
数据根与 profile 根 DSH_HOME（profile / 会话 / 凭据都在这下面）；插件用它自己的 dataRoot 三链（config → 环境变量 → ~/.vssaros） poc/dsh-p0/scripts/lib.mjs 的 DSH_HOME；零覆盖层也能跑 ✓ 已在探针验证（p3-23） dev / 生产串数据根（读写到别人的库）✗
插件安装（幂等） 把插件目录 stage 到 <profile>/.vssaros/plugins/<name>-<version>，再 dsh plugin --profile <p> add file:<dir> dsh --help 的 dsh plugin … add ✓；staging 口径在 dshHostSupervisor ◻，探针里逐字复刻过 ✓（p3-03 / p3-04 / p3-27） 改了插件代码却不换版本 ⇒ 装上去的还是旧的（dsh 按版本解析 ✓）—— 探针的"逐字节一致"断言就是为这个 ✗
覆盖层（可选） 需要注入配置时，写 - id: <行 id> / config: 的 patch 文件；**同一行只许被一份覆盖层打**（第二份会把整份 config 替换掉 ✗） dshHarness/common/dshHostConfig.ts 的 renderHostOverlays() 是**单一真源** ✓ 有守卫断言（"supervisor 必须把 hostConfig 交给它"） 两份覆盖层打同一行 ⇒ 先写的键**静默消失** ✗（报告 2.7 的实测）

3. 反向通道 ide.request（dsh 反过来问壳）

8. 已知边界（照抄报告 + 本次新增，别当成 bug 才查）

① 平面错位（报告 2.7 ⑤）：机制已查清，落地方案与报告草图**不同**（2026-10-12 实测） ✗：
现象：官方把工具下移到 per-agent（preset）plane，让 preset 成为"能力预算开关"；我们的模块行在 host plane ⇒ 任何 preset 下**全部工具都可见** ✗（minimal 的用户实际拿到全量工具面 ✓）。
官方机制（三件事，都实测过）：
· preset 就是**一整行**：- id: preset-standard / name: '@deepseek-ai/dsh-agent-preset' / config.plugins: [完整行列表] （dsh-web-app/presets/standard.patch.yml ✓）；host 级同名行统一 disabled: true ✓。 会话在创建时选一个 preset，preset 身份（工具/模型/skills）首回合后锁定 ✓。
· ⚠ `--patch` 打 preset 是"整份替换 config" ✗（实测：给 preset-standard 只写一行我们的模块， dump 出来的 config.plugins 里**官方那些行全没了** ✗）⇒ 报告 7.3 说的"在 standard / cordis 的 preset 里 各 insert 一份我们的行"**不能直接照做** ✗ —— 只能**生成整份 preset**（含官方行 + 我们的行）✓。
· ✅ 官方有按 agent 限制工具面的原生机制：ctx.tools.restrict({ allow?, deny? }) —— "对单个 agent **继承的全局工具**应用允许或拒绝掩码，掩码取交集，作用域注册保持可见，dispose 时解除" ✓ （dsh-tools/lib/types/index.d.ts:505-513, 637-644）；隐藏工具会为该 agent **移除其全部 schema 成本** ✓ （这正是"能力预算"要的效果 ✓）。而且我们已经在用它：vssaros-agents 的 .agent.md 工具 allowlist 走的就是这条 ✓。
⇒ 可行的落地方案（待拍板，工作量 ≥ 2 轮）：① 生成一份"我们的 preset"（从官方 preset 复制 + 追加我们的行 ✓， 并配一条**守卫**比对官方 preset ⇒ 官方改了会红 ✓）；② 用 restrict 在每个 preset 作用域里按需掩掉我们的工具 ✓ （工具名清单可直接取自本页 §7 的快照 ✓ ⇒ 不用手写 ✗）；③ 把 dsh-agent-preset-registry 的 config.default（现为 standard ✓）指向我们的 preset ⇒ 默认会话才拿到我们的工具 ✓ + 掩码生效 ✓； ④ 新增"每个 preset 的工具面 = 期望集合"守卫 ✓。
⚠ 残差（必须一并接受，否则会以为没修好） ✗：用户**显式选官方 minimal** 时，那个 preset 里 没有我们的行 ⇒ 我们的 host-plane 工具仍会全量可见 ✗ —— `restrict` 是**按作用域**的， host-plane 的注册不在任何 preset 作用域内，掩不到 ✗。要彻底关掉只剩"把行真正下移"（或让官方 preset 也包含我们的行 ✗）。 ⇒ 这条要么接受为残差并写进用户可见说明 ✓，要么改走"把工具行从 host plane 下移"的大改造 ✗。
