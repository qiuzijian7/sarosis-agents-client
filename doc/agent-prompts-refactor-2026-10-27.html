一、这一轮真正做什么

步骤动作为什么必须这样
1把 19 个 md 正文写回 TS 的 systemPrompt（模板字符串转义：反斜杠 / 反引号 / ${）真源在 TS；md 是产物
2把 tools 恢复成 git 原值我误把 md 里的 VS Code 口径工具名（file_read / search_code / terminal…）写回去 ⇒ check-agent-tools 立刻报 16 个未知工具。工具白名单必须用 dsh 真名
3给 knowledge-base-expert 补 6 个 kb 工具（kb_list / kb_read / kb_topic_overviews / kb_write_note / kb_build / kb_mindmap）重构后的提示词让 Agent 调它们，但白名单里没有 ⇒ allowlistDenyOf 会静默 deny，Agent 变成"只会说话"
4给 19 个条目加 suggestions（Agent 接口本来就有这个字段）只写 md 的话，下次启动被 buildAgentMd 抹掉
5守卫改为读真源（159 项）；工具维度仍交给 check-agent-tools第一版守卫查的是产物 ⇒ 会"绿着但没生效"

三、优缺点

✔ 现在真的生效了

  • 19 个 agent 的三段约束进了 systemPrompt：歧义先问、不可逆先确认、缺上下文如实说
  • kb 专家拿到 25 个工具（含 kb_write_note）⇒ 提示词说的话与权限边界一致
  • 欢迎卡建议词持久化在 TS，重启不会被抹
  • 新增守卫 check-agent-prompts.mjs（159 项，读真源）+ 既有 check-agent-tools（工具名）
  • tools 一律以 dsh 真名为准 ⇒ allowlist 不再静默失效

✘ 代价与仍未做的

  • 通用段有重复：19 份提示词各贴一遍三段约束（+453 行），改一处要改 19 处
  • 薄 agent 人设没重写：designer / writer / planner 等仍缺"什么算做好"的判据（本轮只补结构与约束）
  • 中英文标题并存：coder / tob 保留英文小标题（守卫做成中英等价，不为守卫改文风）
  • md 产物未回写：resources/.agents 里的 tools 仍是旧名，等 Host 下次启动自然重生
  • 真机行为未回归：结构可测、行为不可测；IDE 侧 912 passing / 21 failing，失败项全是既有的插件/容器守卫问题，与提示词无关
