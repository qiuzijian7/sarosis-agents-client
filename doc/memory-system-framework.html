VsSaros 记忆系统框架说明

面向 DeepSeek Harness（dsh）Agent 的长期记忆体系：架构、数据流、优缺点与使用手册。

生成日期 2026-11-02 插件源码版本 0.8.1 dev profile 已装内容为 0.7.2（不含收件箱） 产品 profile 仍为 0.6.11 新增的沉淀链 / 收件箱尚未经真机验证

1 一页概览

本项目的记忆系统由三层组成：dsh 插件层负责“对话里怎么用、页面里怎么管”，本地网关负责“唯一写入与存储”，引擎负责“检索、排序、衰减的算法”。

它解决什么

  • 让 Agent 跨会话记住用户的约定、项目规范、教训与事实
  • 把“该记什么”交给规则 + LLM 判定，把“记得对不对”交给人审核
  • 注入内容保持稳定，尽量命中提供方的 KV 前缀缓存
  • 所有写操作可审计、可撤销

它刻意不做什么

  • 不把整段摘要自动写进长期记忆（模型转述，噪声大）
  • 不让模型在每个回合都看到全部 23 个记忆工具（默认只暴露 4 个）
  • 不换存储形态（不搬 Markdown，不用整表 SQLite 方案）
  • 不重写检索（现有混合召回已足够）

3 核心数据流

3.1 写入：沉淀链（草稿 → 长期记忆）

自动提升的四条硬门槛（lib/core/promotion.js）

条件判据理由
① 强句式习惯约定 / 显式要求 / 项目规范 / 英文约定 / summary-fact；排除“强调提醒”“强调提醒”曾把 skill 描述误提成草稿
② 判定成功LLM 判定 judgeOk === true；超时 / 抛错 / 解析失败 / 未启用 ⇒ 一律不提fail-closed
③ 重复出现hits ≥ 2（可调 autoPromoteMinHits）；summary-fact 下限固定为 2说一次可能随口，说两次才像约定
④ 形态合规长度 12–200 字；不含疑似凭证（api key / password / token / 私钥头等）过短无信息量；过长多半是转述

另有：每回合最多自动提升 1 条；整段摘要（turn-summary / session-summary）在任何档位下都必须人工提升。

模型主动写入

memory_remember 是模型默认唯一可见的写工具，走审批闸（config.writePolicy 缺省 ask）。网关必须明确回复 ok/success 才算成功，“没报错”不算。

3.2 读取：召回与注入

常驻注入（每个会话取一次快照）

  • dsh 侧调用 loadContext(agentId, agentId, undefined, {tokenBudget, skipSessionBlocks, recordAccess:false, autoPage:false})
  • 不带 query：注入内容不随提问变化，前缀稳定
  • 块按 recency 升序输出：新条目追加在尾部，已注入字节不变；抢占预算仍是“新的优先”
  • 跳过摘要 / 观察两块（dsh 传的 sessionId 是分区键，与真实会话 id 永不相等，恒为空）
  • 注入不算使用：不写访问记录，避免 retention 被注入频率灌水

按需召回（工具）

  • memory_search：检索长期记忆
  • memory_recall：格式化召回（可选策略）
  • memory_api：只读通用入口，覆盖 28 个已确证的只读方法
  • 引擎流程：BM25 + 向量 + 图谱 ⇒ RRF（k=60）⇒ diversifyBySession ⇒ 重排 ⇒ token 预算裁剪
  • 中文分词：jieba，不可用时降级为 bigram，英文用 Porter 词干

4 安全与治理

机制做法价值
单一写入方所有写入经网关审计 / 迁移 / 索引一致性只在一处保证
审批闸模型发起的写工具走 ask；页面上的人工提升 / 丢弃 / 撤销不再弹窗判据是“谁会因此改用户数据”：人按按钮本身就是确认，叠两层只会养成盲点
审计可区分policy = ask / auto / human / auto-distill能分清“人确认的”和“门控自动放行的”；证据（hits / 句式）写入 policyKey
可撤销提升后的撤销 = 先软删长期层那条，成功后才把草稿改回待审顺序反了，忘记失败时再提升会写出重复
可恢复被取代的旧版本进归档 90 天；迁移前有备份误判不再是永久丢失
写路由防护批量动作路由要求 application/json、仅 POST、动作白名单、单次 ≤ 50 条、请求体 ≤ 64KB跨站表单发不出 JSON，是廉价的 CSRF 防线
隐私引擎隐私过滤 + 自动提升的凭证关键字拦截疑似凭证类内容不会自动写入

入口：活动栏容器 agentStudio.memory，页面路由 /x/memory/。同一路由按宿主注入的 surface 决定形态：侧栏为摘要版，编辑区为详情，无参数为完整版。

库主页（React 工作台）

10 个页签：记忆 / 会话 / 槽位 / 教训 / 整合 / 审计 / 钩子 / 提交 / 报告 / 技能。当前全部只读。支持导出 JSON / Markdown / 技能。

6 优点分析

检索能力强

BM25 + 向量 + 图谱 2 跳经 RRF 融合，再做按会话去重与重排；中文有 jieba 与 bigram 降级链，跨平台不依赖原生二进制。对比 5 个同类插件，只有本项目同时具备三路召回与重排。

注入面对缓存友好

冻结快照、不带 query、升序排版、副作用收口。新记忆只追加在尾部，前缀逐字节不变；同类插件（plus / evolve / longterm）独立得出了同一结论。

写入有“人 + 机器”双层把关

规则提取 → 次数累积 → LLM 判定 → 窄门控；未通过的进收件箱并写明原因。自动与人工在审计里可区分，且都可撤销。

数据安全意识完整

归档代替硬删、迁移前备份、失败回滚且版本不前进、单一写入方、字段白名单。误判不再等于永久丢失。

模型工具面克制

23 个工具中默认只暴露 4 个，节省约 4k schema token；读类能力由只读的 memory_api 兜住，用户仍可在页面使用被隐藏的能力。

可测试性好

门控、收件箱模型、相似度、迁移、剪枝均为纯逻辑模块；有真 HTTP 路由测试、真 React 渲染冒烟、源码级接线守卫，并对关键守卫做过反向突变验证。

与既有取舍的对应

能力领先点
工具面团队 / 联邦 / 哨兵 / 技能 / 晶化等，远超同类（同类最多 8 个）
审计与可观测审计账本 + 心跳 + 统计；自动提升有独立计数，能区分“门控没放过”与“根本没在跑”
容量治理子代理数据族通配剪枝；草稿 500 行 / 30 天；归档 90 天

9 使用说明

9.1 使用者：如何让它“记住”并管好记忆

  1. 直接说约定：在对话里用明确句式，例如“以后所有构建都必须走 pnpm，不要用 npm”“约定：提交信息用中文”。系统会提取为候选草稿，hits=1。
  2. 同一句再说一次：命中同一指纹，hits 变为 2。若句式属于强句式、长度合规且 LLM 判定通过，将自动提升进长期记忆（每回合最多 1 条）。
  3. 打开记忆工作台（活动栏的记忆图标，路由 /x/memory/），在顶部收件箱里处理：
    • 待审：每条显示 hits 与“未自动提升：原因”。点行展开看人话解释。
      • 提升：写入长期记忆（等于你的确认，不弹审批窗）
      • 改写：改好文字后点“改写后提升”，原文会被保留在草稿行的 originalText
      • 丢弃：标为 rejected；下次同一句仍可能被重新提出，丢弃不是永久否决
    • 批量：勾选多条后“批量提升 / 批量丢弃”；单次最多 50 条，逐条独立，部分失败会提示“成功 N 条，失败 M 条”
    • 撤销：操作后出现 10 秒撤销条；也可在“自动提升动态 / 已处理”里点“撤销提升”或“恢复到待审”
  4. 查看全部：点“查看完整记忆 →”进入详情页的 10 个页签，可导出 JSON / Markdown / 技能。
  5. 不处理的草稿：30 天后自动淘汰，不会无限堆积。
看不到自动提升？常见原因：①同一句没有说第二遍；②句式不在白名单（“强调提醒”不进自动通道）；③判定器没有结论（fail-closed）；④档位是 off；⑤插件仍是旧版本。收件箱里每条的“未自动提升：…”会告诉你是哪一条。

9.2 模型 / Agent：默认可用的工具

工具类型用途要点

9.3 配置与运维

插件配置项

配置缺省说明
gatewayUrl / 环境变量 VSSAROS_MEMORY_GATEWAY_URL无（不猜）记忆网关地址；通常由 VsSaros 经 --patch 注入。未配置时页面如实提示，不冒充空
agentId空显式指定分区（单租户 / 探针）；设置后不叠人设
tokenBudget1024工作记忆注入预算
writePolicyask模型写工具的审批策略；可按会话人设覆盖
autoPromotehigh-only自动提升档位；off 恢复“只产草稿”；不认识的值回落 off
autoPromoteMinHits2自动提升的重复门槛；summary-fact 下限固定为 2
distillJudge / distillJudgeTimeoutMsfalse是否用 LLM 过滤草稿候选。注意：autoPromote=high-only 时自动提升路径也会使用判定器，与此开关无关
没有“页面上切换档位”的入口：档位来自 patch 注入，页面不能写。要做需要新增 memory-config.json 写通道（设计稿待确认第 2 条）。

网关与数据

  • 网关默认端口 3111（环境变量 AGENTMEMORY_PORT）；插件通过 POST /provider/<method>、body { "args": [...] } 调用。
  • 数据根目录下：memory-drafts/、memory-audit/、migrations/。
  • 迁移成功的判据：网关日志出现 [mem-migrate] 迁移前备份：… 与 [mem-migrate] v0 → v1：…；二次启动为空操作。

发布与安装要点

  1. 改了 lib/*.js 后：先 node --check，再触碰入口 lib/client.js（产物 revision 只认入口 mtime/size），最后再 bump 版本号。
  2. 新增模块必须登记进 package.json 的 files，否则打包丢失、装后 import 失败（check-plugin-files.mjs 会拦）。
  3. 引擎改动要在 extensions/agentmemory-memory 下 npm run compile（out/ 不入库）；dev app 启动才会让新网关生效。
  4. 安装到 profile：用与 dev Host 同版本的 dsh CLI；不要用跨盘 file:G:/… 路径——先把插件复制到 profile 同盘的 .vssaros/plugins/，manifest 指过去，再 plugin install；装完需重启 Host，会打断正在进行的会话。
  5. 不要为了“生效”去杀 3111：重拉起的仍是安装版旧代码。
