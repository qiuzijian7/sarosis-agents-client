1 · 结论速览

  • 「聊天框上方」不是独立组件，而是上游 ConversationPanel 用槽拼出来的一条区域： heroWorkspaceRow → renderSlot("conversation.input.dock", zone) → renderSlot("conversation.composer.bar", …) → InputBar。 仓库可复核
  • 其中 InputBar 的 promptRow 把 conversation.input.accessory 放在输入行左侧； 「上方一行」是 input.dock / composer.dock / hero options 的 chip 簇。 官方截图里能看到 slides ▾ · Standard mode ▾ · PPT 这一排。 仓库可复核chip 文案推导
  • worktree 不是 UI 概念，是会话运行时概念：working_directory 服务读会话事件投影 workingDirectory；可选 create_worktree 工具创建检出目录并切换调用 Session 的目录； header.cwd 是创建元数据，保持不变。本仓库 src/ 里 0 处 git 调用。 文档可复核
  • 点击 chip / 选择目录后影响的是当前操作目录，不是授权根： sandboxPolicy.resolve() 仍以创建目录为授权根（上游有意区分）； 会话 cwd、header.cwd、workingDirectory 三者会分叉。 文档 + 测试可复核
  • 本仓库为此打了一个路径身份补丁：把 fileAddressFor() 的「绝对路径按 renderer cwd 缩写」删掉， 改为保留绝对身份，避免 worktree 切换后绝对路径被二次拼接。 patch + 回归测试可复核
  • 选中态落在 dsh.sessions.current / dsh.workspace.view.v5，由 preload 把 desktop-storage.json 注入 localStorage 实现重启恢复；只对 owner 窗口生效。 仓库可复核

3.1 槽与 DOM 顺序 仓库可复核

patches/@deepseek-ai+dsh-client-ui-conversation+0.2.2-rc.1.patch:13-29 的 hunk 保留了上游 ConversationPanel 的真实结构：

  variant: hero ? "hero" : "composer",

4 · 点击后的调用链：如何影响项目目录

  1. UI 层：chip / 下拉项 / inert 输入框上游推导 点击触发 onRequestWorkspace / workspacePickerOpen（conversation patch :62-63,256-257）或 uiWorkspace 的选择入口。
  2. uiWorkspace 导航入口workspace patch 可复核 startSession(workspaceId, options)（同步，:173-177，可被 registerSessionStarter 短路）、openSession(target, source) → replaceMain(target, "reveal")（:136-139）、async openWorkspaceSession(...) → connectBlank → replaceMain（:144-156）。
  3. 会话创建 / 目录落地sessions.create({workspaceId}) → sessions.retain(id,{source:'mainView'})；新会话 cwd = workspace.path（test/workbench-navigation.test.mjs:422-426 断言 {blank:true,cwd:'/project'}）。Host 侧 createMinted(request.cwd, composition) 会 ensure project directory "${cwd}"（session-controller patch :220,235）。
  4. 真正的「切目录」：working_directory / create_worktree文档 + 锁文件可复核 dsh-working-directory 的 get(session) 读投影、set() 追加 working-directory/change（harness-0.2.1-feature-review.md:81-83）；可选 create_worktree 创建保留的检出目录/分支并切换调用 Session 的目录（:36），header.cwd 不变。包见 package-lock.json:1375,3527-3528，默认关闭，权威清单是 dsh-app-boot/lib/index.js 的 OPTIONAL_BUNDLES。本仓库 src/ 0 处 git 调用。
  5. 主进程 IPC（选目录 / 打开文件位置）src/preload/app.ts:149-151 __DSH_DIRECTORY_PICKER__.pick() → ipcRenderer.invoke(DESKTOP_IPC.directoryPick) → src/main/shell/app.ts:1024-1028 dialog.showOpenDialog({properties:['openDirectory','createDirectory']})，取消返回 null；window.dshDesktop.openInFinder(cwd) → shell.showItemInFolder（:851）。另有 ctx.remote.session.openWorkspacePath({path})（chat patch :311）。
  6. 主视图重建replaceMain(..., "reveal")；失败时 if (!opened.ok) throw opened.error（chat patch :56,312），UI 用 role="alert" 就地显示（dsh-desktop-client-ui/client.js:55-60）。没有「切换 worktree 的二次确认弹窗」证据。

三个「目录」必须分清 文档 + 测试可复核

概念来源切换 worktree 后
header.cwd会话创建元数据不变（上游有意设计）
sessions.byId[].cwdrenderer 会话快照可能滞后，仍是原根 —— 补丁注释原话 "Renderer cwd may lag behind the Host after a worktree change"
workingDirectory 投影会话事件投影（当前操作目录）变为新 worktree 路径
sandboxPolicy.resolve().workspaceRoot创建时的授权根不变；注入新 current directory 后实测仍返回 original，mismatch=true（harness-0.2.1-feature-review.md:91-93）
已知不一致（文档明确标注为待修）：Office/PPT 的 workspacePolicy、workspaceRoot、 automaticSkill 仍读 header.cwd（harness-0.2.1-feature-review.md:85-99）， 所以用户切换当前目录后，常规工具与 Office/PPT 可能用不同根目录，产物落回原项目。 文档的建议是「统一通过 workingDirectory 取当前目录，再独立验证其位于现有许可范围，不能简单把 current cwd 写成新的权限根」。

路径身份补丁（本仓库为 worktree 专门打的）

patches/@deepseek-ai+dsh-client-ui-chat+0.2.2-rc.1.patch:8-18 把 fileAddressFor() 改了：

- const root = cwd.replace(/\\/g,"/").replace(/\/+$/,"");
- if (root !== "" && normalized.startsWith(`${root}/`))
-   return sessionFileAddress(sessionId, normalized.slice(root.length + 1));  // 绝对 → 相对
+ // Renderer cwd may lag behind the Host after a worktree change.
+ // Keep absolute file identity; genuinely relative paths remain relative.
+ return sessionFileAddress(sessionId, path);                                  // 保留绝对身份

原因见 docs/file-preview-cwd.md:3-9：补丁前，嵌套 worktree 的绝对文件名被缩成相对后缀， 后端再用「当前 Agent working directory」（已是新 worktree）去拼，同一段 worktree 路径被拼两次。 test/preview-worktree-path.test.mjs:23-64 用真实临时文件 + bundle 抽取的函数验证 9 组 cwd/path（中文空格 #、跨工作区、跨盘、UNC、反斜杠、cwd===path）补丁后都保留绝对身份。

7 · 待确认 / 报告边界

  1. chip 本体源码缺失：本 checkout 无 node_modules。要 100% 复核「显示文字怎么算、onClick 具体调什么」，需装依赖后读 dsh-client-ui-chat / -conversation / -workspace 的 bundle（版本 0.2.2-rc.1）。
  2. worktree 默认关闭：create_worktree 是可选 Agent 工具，需确认目标环境是否启用；「切换目录」基础能力由 working_directory 提供，与 worktree 是两件事。
  3. 没有专门展示该 chip 的截图：仓库里 hero-v021.png 是产品总览（能看到 chip 簇），没有 worktree 下拉的单独截图/GIF；mockup 的下拉结构按仓库内 dshWbModeMenu 复刻，非该 chip 的逐像素截图。
  4. Office/PPT 根目录不跟随是文档记录的已知问题，不是本次分析新发现；是否要在 VsSaros 侧规避需单独决策。
  5. 补丁生效前提：docs/file-preview-cwd.md:9 明确「源码测试不能证明已安装应用加载了该补丁」，需 rebuild/reinstall 或受支持的客户端重载流程。
  6. 本报告只做分析，未修改任何仓库文件；VsSaros 侧也未改生产代码。
