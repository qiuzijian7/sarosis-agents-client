各 Bot 的「飞书配置为一项」· 四款方案（历史留档）

2026-11-10 用户已定稿：不再按四款选型。最终形态 = 设置 → Channel 绑定卡内选飞书应用（可选已有 / 添加新应用）+ chat_id + groupPolicy；独立「飞书配置」卡已移除。本目录四款稿与上一版单方案稿仅留档，勿按它们确认。

四款用同一份数据（3 个 Bot，各有自己的绑定）与同一套交互（切 Bot、选已有应用 / 添加新应用、填 chat_id、保存 / 删除绑定、宽窄容器、深浅外观、自证探针），差别只在「这一项放在哪」。点任意「打开完整交互版」可单独操作。

2026-11-10 规格修订：按你的要求去掉「全局应用池」与「当前 Bot 选用的应用」——后者改名为「绑定」。一条绑定 = 选择已有应用（或就地添加新应用：App ID / App Secret）+ 配置 chat_id。已有应用只是「选择已有应用」的下拉可选项，不单独展示列表；不再有 bot→应用映射，Channel 绑定也已并入这一项。
补充（groupPolicy）：添加新应用可设默认群策略，新建绑定可单独覆盖（open / allowlist / disabled，默认 open）。它落在绑定级才生效——action:'feishu-app' 只存 appSecret/name，塞进应用表单会变成「填了不生效」的假入口。

数据契约：绑定落 agent-bindings.json（appId / chatId / targetId），应用凭据落 agent-im-accounts.json；写口 action:'create' 建绑定、action:'feishu-app' 添加新应用；Secret 明文永不回传。

怎么选

若你说的「一项」是与「设置」同级 ⇒ 选 A：绑定表独占一页，配置空间最大，一眼可见（对齐你截图里的页签条）。
若不想增加顶层页签、要最小改动 ⇒ 选 C：层级最浅、窄容器最稳。
若以后分组还会变多（模型/记忆/技能/权限…）⇒ B 最贴官方设置弹窗的左导航；若以后要接 Telegram / Discord 等更多渠道 ⇒ D 的「一行一项」扩展最自然。
