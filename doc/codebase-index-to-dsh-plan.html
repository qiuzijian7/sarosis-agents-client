0. 一句话

读侧已经在 dsh 里了（就是现有 @vssaros/dsh-codebase，11 个工具 + 只读页）⇒ 真问题是"写侧（索引编排 + tree-sitter 解析）能不能也落进 dsh"。
结论：能，但要分期、且第一刀不是"搬索引器"而是"自证 Host 能跑 tree-sitter" —— P0 已做完，答案是"能"（UMD 运行时在 Node 里直接可用、worker_threads 里 11ms init / 20ms 解析 ✓）； 剩下的卡点不在算法，而在 ① wasm 资产怎么交付（1.71 MB 起 / 21.1 MB 全量） 与 ② .codebase-memory/ 的所有权（IDE 现在独占，我们自己的纪律是"不写工作区产物"）。 推荐路线 = 影子索引：dsh 把图写进自己的数据根、与 IDE 产物逐字同形，所有权交接留到被明确要求时再做。

2. 目标与非目标

目标非目标 ✗
· dsh 侧能自己产出代码图谱（不依赖 IDE 是否开着、是否索引过）；
· 产物与 IDE 逐字同形（artifact.json + graph.db.zst 契约），读侧零改动即可消费；
· 索引期间不冻结任何 UI（因为本来就在 Host 进程）；
· 全程不动 src/（那是并发会话区域 ◻）。 		· 不做"IDE 侧 P2-1 的替代品"（两条线各有各的动机，成果可共享但目标不同）；
· 不搬 SQLite/FTS5 后端（主进程 mmap + FTS5；dsh 侧要另立，见 P4）；
· 不搬编辑器集成（class hierarchy / find symbol / 3D layout / LOD）—— 纯 IDE 专有；
· 不做双写（同一目录两个写者 = 迟早互相踩 ✗）；
· 不顺手改 IDE 索引器的行为（那边有 50 条契约测试钉着）。

3. 形态选择：三选一，推荐"影子索引"

形态做法代价判定
甲 · 所有权交接 dsh 成为唯一索引者，IDE 侧索引器降级/关闭；dsh 写 <ws>/.codebase-memory/ 必须先完成 IDE 路线 A（同步消费者 async 化 + 释放内存 store）+ 共用 index.lock 协议；一落地 IDE 侧功能就依赖 dsh 是否在跑 ✗ 本阶段不做（等被明确要求）
乙 · 影子索引（推荐） dsh 把图写进自己的数据根（<dataRoot>/codebase-index/<workspace-hash>/），产物逐字同形；读侧优先影子、没有再回退 IDE 的产物；IDE 侧一行不改 两份图（磁盘 + 一次额外索引 CPU）；同一工作区"dsh 看到的图"与"IDE 页面的图"可能不同 ⇒ 必须在页面/工具里如实标出来源 ✗ 推荐：结构上不可能双写、不碰 src/、每期可独立回滚
丙 · dsh 产出、IDE 消费 dsh 索引后把产物交给 IDE 读（IDE 变成纯消费） 本质是甲的传输方向倒过来，同样要动 IDE 侧；且 IDE 侧载入路径的 2.4–4.3s JSON 解析一点没省 不做（收益被 IDE 自己的载入瓶颈吃掉）
为什么推荐乙而不是甲：甲乙的必做工作完全相同（P0 的 wasm/Host 解析自证、P1 的索引器升级、P2 的真解析）， 差别只在"最后写哪、谁放手"。乙把那个差别推到最后一刻，于是前面每一期都不需要协调并发区域、也不会让 IDE 侧功能依赖 dsh 进程是否活着 ✓。 而且"逐字同形"这个约束在乙里是免费拿到的：产物同形 ⇒ 将来真要交接，改动量≈改一个目录常量 ✓。

4. 分层设计（L0–L6）

每层都给"落点 / 输入输出 / 怎么验"。层与层之间用现成契约接，不新增跨插件 import（本仓硬规矩：插件是独立安装进 profile 的包，相对路径依赖在 stage 后必断 ✗）。

层落点输入 → 输出怎么验
L0 运行时与资产 vssaros-codebase/lib/parser/（新） wasm 路径 + 源码文本 → AST（worker_threads 池，1→N 个 worker；每个 worker 一份 wasm 实例；超时兜底） P0 探针：真起 worker、真 parse、缺 grammar 必须显式报错（不许回退成"解析 0 个文件" ✗）

L2 解析 P1 沿用正则顶层符号；P2 换 tree-sitter 文件 → 符号（label/name/qualifiedName/startLine/endLine） P1：既有 symbolCheck（含"不该抽的缩进声明"反例）；P2：与真图抽样对账

4.1 产物归属与配置链（乙方案的关键定义）

索引输出根：config.indexDir  →  VSSAROS_DATA_ROOT/codebase-index  →  <未配置 ⇒ 不索引，工具如实报错>
读侧实际根：影子产物存在 → 用它；否则 → 现有 IDE 产物（<ws>/.codebase-memory/）；两者都报在返回里
  • 不猜：与现有 workspaceRootOf 同一条纪律 —— 没配就报"未配置"，不回落去读别人的东西 ✓。
  • 影子目录名用 <workspace 绝对路径的 sha256 前 16 位>（同一台机器上多工作区互不干扰；迁移/改名后旧目录不会被误用）。
  • 页面与工具必须显示"图来自哪个根"（现有 resolveRoot 已经回传 workspaceRoot ⇒ 扩成 graphSource: 'shadow' | 'ide' 即可）。
