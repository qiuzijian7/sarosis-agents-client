# 其他内置工作台是否符合「小红书笔记编辑工作台框架」

**调研时间**：2026-10-24 · **样本**：本仓 14 个声明了 `vssaros.workbench` 的插件（8 自有 + 6 未注册/SSR）
**框架来源**：`doc/xhs-note-aiwriting-mockup.html`（v3 定案）+ **`dsh-plugins/vssaros-studio`**（唯一按该框架落地的实现）

---

## 0. 结论（先看这段）

| 判定 | 数量 | 是哪些 |
|---|---|---|
| **完全符合** | **0** | —— |
| **核心符合**（注册式 + 共享层 + 令牌） | **7** | workflow / kanban / memory / codebase / kb / agents / scheduler |
| **最接近框架形态**（三栏 + 嵌入式官方对话） | **1** | **studio**（载体，但 3 处偏离，见 §3.1） |
| **不符合**（SSR / 未注册 / 零共享层） | **6** | imagegen / marketplace / media / parallel / sessions / skills |

**一句话**：这个框架描述的是**「创作型工作台」的形态**，不是所有工作台的通用形态；目前只有 `studio` 走了它的布局，其余 13 个只在「注册式 / 令牌 / 锚点」这些**通用条款**上部分达成。

> ⚠ 重要前提：**7 个自有工作台是「列表/工具型」**（看板、知识库、日程、图谱…），强套三栏 + 右对话反而更差。真正该问的是「**哪些工作台属于创作型**」，而不是「为什么它们不像小红书」。

## 1. 框架到底规定了什么（7 条，可逐条检查）

从 mockup v3 的定案 + `studio/lib/client.js` 的实测注释里提炼：

| # | 条款 | 具体含义 | 出处 |
|---|---|---|---|
| **F1** | **注册式工作台** | `desktopWorkbenches.register(descriptor, Panel)`，`customFrame: true` | studio:334 |
| **F2** | **三栏骨架** | 左 = 业务/创作信息（约 250px）· 中 = 画布/预览 · 右 = 对话（约 420px） | mockup v2 形态图 |
| **F3** | **右栏 = 官方对话，不走 `sidebar.right`** | 用 `props.conversation` **嵌入式**渲染；`sidebar.right` 这条路**实测不通**：chat-only 形态被整条裁掉、pane 上限 2、只作用于「在屏会话」 | studio:4-13 |
| **F4** | **平台级入口** | 右上角 `shell.overlay`（与「升级」并列）；studio 因宿主限制落成「工作台内『开始对话』」 | mockup v2 · studio:8 |
| **F5** | **颜色只用令牌** | 100% `--dsw-alias-*`，尺寸 `--wb-*`，暗色靠 `body[data-ds-dark-theme]`；**禁止自造一套 `--pink/--surface`** | mockup v3:13 |
| **F6** | **业务色单一入口 + 作用域** | 品牌色只有一个变量，作用域限制在 `.wb-xhs` 内；默认 `data-brand='host'`（跟随 `--dsw-alias-brand-primary`） | mockup v3:19 |
| **F7** | **按容器响应，不按窗口** | 容器查询 + `ResizeObserver` 打 `data-narrow`；**不能用 `@media` 判宽**（同窗不同宽分不开） | mockup v3 坑 2/3 |
| **F8** | **面板守卫** | 包一层 `layout.selectPanel`，仅当本工作台在前台且目标是清空面板时拦下（否则官方 hero 会把中栏切回会话页） | studio:258-283 |

## 3. 逐项判定

### 3.1 studio（唯一按框架落地，但有 3 处偏离）

**已符合**：F1 注册式 + `customFrame`；F2 三栏（左站点 iframe / 右官方对话）；F3 **嵌入式 `props.conversation`**（并明确记录「`sidebar.right` 走不通」的原因）；F8 面板守卫。

**偏离**：

| 偏离 | 事实 | 影响 |
|---|---|---|
| **F5 / F6 未达成** | 扫描到 `--page / --bar / --surface / --stroke / --muted` 等**自造变量**，`--dsw-alias-*` 仅 4 处，裸色 20 处 | 暗色不跟随（与 mockup v3 批评 v2 的正是同一问题） |
| **iframe 承载站点** | 左栏是 `<iframe data-vssaros-studio-site>` | 与「零 iframe」规范冲突；但对「承载外部站点」是合理例外（需在规范里写明） |
| F4 平台级入口降级 | 没有 `shell.overlay`，用工作台内「开始对话」按钮 | 达不到「任何工作台都能用」，只在 studio 内可用 |

### 3.2 7 个自有注册式（核心符合，形态不适用）

workflow / kanban / memory / codebase / kb / agents / scheduler：

- **符合 F1**（全部注册）、**F5 部分**（有 `wb-*`，但仍有裸色 —— agents 204、kb 78、memory 55 处，含 SSR 内联样式）；
- **不符合 F2/F3/F7/F8**（没有三栏、没有右对话、没有容器查询、没有面板守卫）；
- **判定**：它们**不应该**套这个框架。看板/图谱/日程的信息结构是「列表 + 详情」，右栏放对话会挤掉主信息区。
- **但有一条该抄**：scheduler 的 `wb-*` 用得最干净（14 类 / 裸色仅 2 处）——这是「工具型」的正确样板，而不是 studio。

### 3.3 6 个未注册（不符合，且短期不该套）

| 工作台 | 形态 | 为什么不符合 | 是否值得改成框架 |
|---|---|---|---|
| imagegen | 静态 app + 画布 | 未注册、零 `wb-*`、433 处裸色 | **半值得**：结果预览适合「中画布 + 右对话」，但画布编辑器重写成本极高 |
| marketplace | 壳 + vendor React | 未注册、零 `wb-*` | **不值得**：商城是「浏览 + 安装」，属列表型 |
| media | SSR 资产浏览器 | 未注册、无 CSS 变量 | **不值得**：列表型，且已有 `data-*` 锚点最全 |
| parallel | SSR PTY 网格 | 未注册、终端层 | **不值得**：终端类应豁免共享 UI 层 |
| sessions | SSR 列表/磁贴 | 未注册 | 不值得（列表型） |
| skills | SSR 列表 + 抽屉 | 未注册 | 不值得（列表型） |

## 4. 建议：把框架拆成两档，别当通用标准

### 4.1 A 档 · 所有工作台都必须（通用条款）

| 条款 | 现状 | 动作 |
|---|---|---|
| 注册式（F1） | 7/14 | 六个未注册包按「列表型」逐个迁（media 优先） |
| 颜色只用令牌（F5） | 7/14 有 `wb-*`；裸色仍多 | 把裸色清零纳入守卫（`check-workbench-style.mjs` 已有「无裸色」项，需扩到 SSR 包） |
| 容器查询 + `data-narrow`（F7） | 2/14 | 列表型也需要（sideview 320px 场景） |
| 机器锚点 `data-*` | 普遍较好 | 保持 |
| 零 iframe | 1 例外（studio 站点） | 在规范里写明例外 |

### 4.2 B 档 · 只有「创作型」才套（框架本体）

判定标准（三条同时满足才算创作型）：

1. 有**产物**（笔记/文案/图/方案），不是「查/管/配」；
2. 主区是**编辑器或画布**，不是列表；
3. 需要**边写边问**（对话是工作流的一部分，不是辅助）。

按这条标准，当前**只有 studio（含 xhs 场景）与 imagegen 的「结果预览」**沾边；`编曲 / 小红书笔记创作 / 文案转演示`（这三是商城里的第三方）也属于这一档。

### 4.3 推进顺序（若要做）

| 步 | 内容 | 工作量 | 说明 |
|---|---|---|---|
| 1 | **studio 补 F5/F6**：把 `--page/--bar/--surface` 换成 `--dsw-alias-*`，品牌色收敛成单一入口 + `.wb-studio` 作用域 | S | 直接修掉「暗色不跟随」，且不改变布局 |
| 2 | 把「创作型三栏」写进 `doc/workbench-authoring-standard.md` 作为**可选档位**（含 F2/F3/F8 的代码骨架） | S | 让下一个创作类工作台有模板 |
| 3 | 用这套档位重做一个真创作台（建议 **小红书笔记** 本身，因为 mockup 已定案） | M | 验证框架可用性 |
| 4 | 列表型包补 `@container` + `data-narrow`（media / sessions / skills 优先） | S–M | 与创作型无关，但影响 sideview 可用性 |

## 5. 附：扫描方法与可复现

```bash
# 逐包统计注册/右对话/iframe/令牌/裸色/容器查询（脚本在 %TEMP%，不入库）
node %TEMP%\wb-conformance-scan.mjs      # 粗扫（含注释，会把示例色算进去）
node %TEMP%\wb-conformance-scan2.mjs     # 剥注释后精扫 → %TEMP%\wb-conformance2.json

# 可靠计数（PowerShell，逐包 grep）：wb-* 去重类名 / --dsw-alias- / #rrggbb
```

**已知口径问题（避免误读）**：

- `hex` 计数**包含注释与 SSR 内联样式**（如 agents 的 204 处多来自 `detail.js`/`groupPage.js` 的内联页样式）⇒ 只能当量级，不能当「违反 F5 的次数」；
- 第一次扫描把注释里的示例色（如 `#4a90d9`）算进 kb 的「裸色」⇒ 已用剥注释版复核；
- scheduler 在粗扫里显示全 0，是扫描器被它 `client.js` 里的正则字面量带偏；可靠计数是 **14 个 `wb-*` 类、裸色 2 处**。
