整体架构：六层模型

本项目的 worktree 机制由六层组成，从底层数据模型到上层 UI，每层职责清晰。

Layer 1: 数据模型 session.ts

ISessionWorkspace

repositories: ISessionRepository[]  // 非 folders
label: string
icon: ThemeIcon
// 无 uri, 无 isVirtualWorkspace

ISessionRepository

uri: URI                // 源仓库 URI
workingDirectory: URI      // worktree 路径
detail: string           // 分支名等
baseBranchName: string     // 基分支
// git 信息平铺，无嵌套 gitRepository
worktree 判断逻辑（本项目独有）：上游用 gitRepository.workTreeUri（仅 worktree 时非空），本项目用 workingDirectory !== uri 判断。_isWorktree(repo) = !isEqual(repo.workingDirectory, repo.uri)

上游 VS Code 没有这个子系统。本项目在 sessions/contrib/worktree/ 下实现了完整的 worktree 管理。

Worktree 完整生命周期

从创建到归档的 6 个阶段，每阶段标注关键组件和方法。

1

创建 Worktree

WorktreeService.createWorktree(info) 在 workbench Browser 进程执行 git worktree add。支持两阶段创建模式（IWorktreeInfoOptions → IWorktreeInfo）。状态变为 WorktreeStatus.Pending。

2

Session 绑定

Provider 创建 session，设置 workspace.repositories[0].workingDirectory 指向 worktree 路径（与 uri 不同）。通过 onDidChangeSessions.added 通知 dispatcher。

3

自动任务派发

WorktreeCreatedTaskDispatcher._trackSession() 检测到 _isWorktree(repo) = !isEqual(workingDirectory, uri) 为 true 后，调用 _dispatchWorktreeCreatedTasks() 读取所有 runOn: 'worktreeCreated' 任务并执行（如 npm ci && npm run watch）。agent-host session 受 chat.agentHost.runWorktreeCreatedTasks 配置控制。

4

开发与验证

用户在 worktree 中修改源码 → watch 自动增量编译 → 按 F5 运行 pinned 任务 → 浏览器/终端/断点验证。可选创建 Checkpoint（IWorktreeCheckpointService snapshot 工作树状态）。

5

归档（Archived）

用户归档 session → session.isArchived 变为 true → dispatcher 的 autorun 检测到后调用 taskHandles.clear() → 自动 dispose 所有 watch/dev server 进程句柄。

6

移除与清理

用户删除 session → onDidChangeSessions.removed 触发 → _sessionDisposables.deleteAndDispose(sessionId) 清理整个 DisposableStore（含 autorun、task handles）。可选 WorktreeService.removeWorktree() 删除物理 worktree 目录。

Checkpoint 机制

📸

Snapshot（创建检查点）

捕获当前 worktree 的工作树状态（含 untracked 文件），用临时 git index + write-tree 生成 tree object，commit-tree 创建悬挂 commit，update-ref 指向 checkpoint ref。

Browser + Node 双实现

Restore（恢复检查点）

将 worktree 工作树恢复到指定 checkpoint 的状态。通过 git diff 计算差异，git restore 恢复文件。

与上游 VS Code 的关键差异

维度上游 VS Code本项目 (fork)差异程度
数据模型folders[].gitRepository.workTreeUrirepositories[].workingDirectory🔴 高（结构性）
worktree 创建位置agent-host Node 进程workbench Browser 进程🔴 高
worktree CRUD基本操作完整 CRUD + prune + reset🟢 fork 更强
worktree UI无树视图 + 命令面板🟢 fork 独有
Checkpoint在 GitService 中独立服务 + UI 命令🟢 fork 更强
两阶段创建无有（opencode 兼容）🟢 fork 独有
状态管理无WorktreeStatus 状态机🟢 fork 独有
自动任务派发有（检测 workTreeUri）有（检测 _isWorktree）🟢 已适配
runner 注册表有有（已移植）🟢 已对齐
AgentHost runner有（terminal-based）❌ 缺失🟡 中
配置开关chat.agentHost.runWorktreeCreatedTasks有（ANY_AGENT_HOST_PROVIDER_RE）🟢 已恢复
worktree 误触发防护workTreeUri 天然区分_isWorktree() 判断 uri≠workingDirectory🟢 已修复
关键风险：数据模型结构性差异（folders[].gitRepository.workTreeUri vs repositories[].workingDirectory）导致每次从上游移植代码都需要适配层。AgentHost runner 缺失，对 agent-host session 可能无法正确执行远程任务。
