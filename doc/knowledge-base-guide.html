VsSaros 知识库 · 使用说明

从资料导入到 Agent 检索：一套运行在 IDE 内、零外部服务、离线可用的个人知识库。

渲染进程内运行 Markdown / Obsidian 兼容 BM25 + 向量混合检索（RRF） 双链知识图谱 可用飞书同步

1. 五分钟上手

1打开视图

侧边栏「知识库」视图 → 新建知识库（默认名「我的知识库」，落在 ~/.vssaros/knowledge-base/<vault-id>/），或 选择文件夹作为知识库 复用已有 Obsidian 库。

2导入资料

三处任意一处点「导入知识库」：聊天消息按钮 / write_file 卡片按钮 / 工作区文件右键。资料即刻落盘到「库」分区（库/raw/）。

3构建为笔记

右键库文件 →「构建为笔记」（或批量构建全部未处理项）。产出结构化笔记 + 双链 + 导航与摘要。

4建向量索引

设置面板 →「重新构建向量索引」（需先配置 Embedding Provider；未配置时全文检索仍可用）。

5开始提问

在聊天里直接问 —— Agent 会调用 kb_search 检索你的笔记，回答带 [[笔记名]] 引用。

+可选：同步飞书

node .codebuddy/kb-feishu-sync.mjs --vault <vault> --src <目录> --apply，让笔记出现在飞书个人知识库（见第 10 节）。

依赖说明：导入与构建需要 Chat Provider（LLM）；语义检索需要 Embedding Provider（可选，未配置则只有全文检索）。两者都在通用模型设置里配置。

3. 导入资料

3.1 三个入口，同一条管线

入口位置适合场景
聊天消息按钮任意助手回复下方的「导入知识库」把一段高价值对话沉淀为资料
write_file 卡片按钮聊天里文件写入卡片上的「导入知识库」Agent 刚生成的文档直接入库
工作区文件右键资源管理器 / 工作区视图文件右键「导入知识库」把手头的 md / 资料文件批量入库
三者共用 KbImportController：阶段 1 落盘 → 立即（或稍后）阶段 2 构建。聊天入口默认两步连做，工作区右键同理。

3.2 导入两阶段流程

 聊天 → 导入 → 构建
助手回复：RAG 的进化路径…
复制 导入知识库 1
阶段 1：分类 + 落盘 2
schema 分类（type / topic）→ 写入 库/raw/<类型>/<标题>-<日期>.md（带 frontmatter 保留溯源）
通知：已保存到知识库「库/raw」分区（概念/RAG）。可右键库文件「构建为笔记」生成结构化笔记。
阶段 2：构建笔记 3
两阶段 LLM（分析规划 → FILE 块批量产出）→ 笔记/01-基础概念/RAG 进化.md，同时建立 [[双链]]、更新导航、生成摘要
构建方式 4
默认走 Agentic 构建（knowledge-base-expert Agent，可用工具与技能）；Agent 无产出或报错时自动回退直连 LLM 管线，两条路径共享构建缓存

要点

  1. 导入即落盘，不会丢失——即使构建失败，原件仍在 库/ 里，可稍后重试。
  2. 分类由 schema 驱动（概念 / 方法 / 案例 / 问答…），决定笔记落到哪个目录。
  3. 阶段 2 会自动补 sources 溯源双链，指向 库/ 中的原件。
  4. 构建方式可在设置中关闭（见第 9 节），关闭后为纯 LLM 直连，更快更省但无工具能力。
导入需要可用 Chat Provider；若报 CORS 被拦截，请检查 Provider 配置与网络代理。

单个构建 vs 批量构建

  1. 单个：库文件右键「构建为笔记」——只处理这一份资料。
  2. 批量：工具栏「构建」——处理所有未构建的库文件；全部处理完会提示「所有库文件已构建」。
  3. 构建中：文件名旁出现旋转图标；完成后发出通知「笔记构建完成」。
  4. 缓存：同内容重复构建走缓存，不会重复消耗 LLM 额度。
产出物清单：结构化笔记（按类型/主题分目录）+ [[双链]] + 确定性补链（零 LLM 成本扫描全库标题）+ 导航（index / overview）+ 社区洞察（insights）+ 目录摘要（各目录 .overview.md）。

语义索引与当前 embedding 模型不一致时的提示 3

三种检索模式

  1. hybrid（默认）——全文（BM25）与语义（向量）双通道结果做 RRF 融合排序（k=60，命中的笔记带有 ■ 双通道标记）。
  2. fulltext——纯 BM25（含中文单字 + 二元切分），无需 Embedding，秒回。
  3. semantic——纯向量相似（需先建索引），能召回同义表述。

结果里的三样东西

  • 引用回链：每条命中附 [[笔记名]]，可直接点开或写进回答。
  • 目录摘要：命中目录的 .overview.md 摘要随结果返回，用于「先看概览再决定深入」。
  • 不一致警告：索引 tag 与当前 Embedding Provider 不一致时提示重建，避免用错向量算相似度。
在聊天里不需要显式指定工具——问知识库相关问题，Agent 会自行调用检索。

6. Agent 工具

三个知识库工具可在聊天中被自动调用，也可显式要求使用。

6.1 kb_search——知识库检索

{
  "query":  "死循环防御",        // 必填，自然语言或关键词
  "mode":   "hybrid",           // hybrid（默认）| fulltext | semantic
  "limit":  10                  // 返回条数，默认 10，最大 50
}

返回：知识库检索「…」命中 N 条 + 每条 score / uri / 摘要 / [[引用]] + 相关目录摘要。

6.2 kb_suggest_links——隐式双链建议

{
  "docUri":   "file:///…/笔记/03-核心组件/Agent死循环检测与防御.md",  // 必填
  "limit":    5,      // 默认 5
  "minScore": 0.72    // cosine 阈值 [0,1]，默认 0.72；调高更严格
}

找出「语义相似但尚未建立 [[双链]]」的笔记（本地向量运算，零 LLM 成本），建议补链以增强图谱连通性。

6.3 kb_topic_overviews——目录摘要一览

{}   // 无参数

列出所有目录的摘要（.overview.md 中间层产物），用于在深入检索前先了解库内容分布。

场景建议用法
不知道库里有没有某主题先 kb_topic_overviews 看概览，再 kb_search 深入
答案需要出处kb_search，用返回的 [[笔记名]] 作引用
整理笔记、完善图谱kb_suggest_links 找候选，人工确认后补链
只想知道原文，不需要推断kb_search 用 fulltext 模式
上下文注入：除了被动调用，聊天消息还会自动携带「知识库目录摘要」标签（L1 常驻，见第 9 节），让 Agent 在无检索调用时也知道库里大致有什么。

7. 图谱与摘要

 关系图谱
实线 = 已有 [[双链]]；虚线 = kb_suggest_links 建议的隐式关联 1

图谱怎么来的

  1. 节点/边来自笔记正文的 [[wikilink]]，外加构建期「确定性补链」（扫描全库标题互链，零 LLM）。
  2. 社区检测：Louvain 算法聚类，再对每个社区做一次 LLM 语义摘要（GraphRAG 思路），写入 insights.md。
  3. 增量一致性（重要）：删除 / 重命名 / 移动笔记后，图谱与索引立即更新，不需等下次全量重建。

三份自动产物

  • index.md：全库目录索引。
  • overview.md：整体概览。
  • insights.md：社区列表 + 每社区主题与摘要。
  • <目录>/.overview.md：单目录摘要（变更 ≥10% 才重算，省 LLM 成本）。

8. 文件管理

操作方式说明
新建 / 重命名右键菜单改扩展名会弹确认（可能影响打开方式）；命名限制：不含 \ / : * ? " < > |，不以 . 或空格结尾
剪切 / 复制 / 粘贴右键菜单 / 快捷键目标有同名文件时询问「替换 / 跳过」（可对本次全部冲突应用）
删除Delete移入回收站，可还原
永久删除Shift+Delete不可恢复，有二次确认
撤销Ctrl+Z撤销知识库文件操作（移动/重命名/删除等）
批量操作多选后右键批量删除同样区分「回收站 / 永久」
删除后索引会即时清理（选择性删除）：该文档从全文索引、向量索引、图谱节点与边中同步移除，不会出现「搜到的笔记已经不存在」的幽灵结果。
删除笔记不会删除 库/ 中的资料原件；反之删原件也不影响已构建的笔记（除 sources 溯源会失效）。

五项设置

  1. 知识库位置：默认 ~/.vssaros/knowledge-base/<vault-id>/；也可指向已有 Obsidian 库目录（库/ 与 笔记/ 会建于其中）。
  2. Agentic 构建：唯一的知识库配置项 sessions.agentStudio.kb.agenticBuild，默认开启；开启时构建交给 knowledge-base-expert Agent（获得工具与技能注入），失败自动回退直连管线。
  3. 语义索引：查看规模与模型 tag；换 Embedding Provider 后用「增量重建」只重算 tag 不匹配的块（不必全量）。
  4. 模型配置：Chat 必填；Embedding 可选。
  5. 飞书同步：总开关 + 同步脚本路径 + 同步范围（库内相对目录，逗号分隔，留空 = 整个知识库）+ 目标位置（my_library 或文件夹 token）+ 远端手改策略（本地覆盖 / 跳过并记录冲突）+ 限流间隔；下方三个动作按钮在集成终端执行并在结束时保留输出。
切换 Embedding Provider 后，旧向量与旧模型维度不一致 ⇒ 请执行「重新构建向量索引」；本地模型首次会自动下载。

两个开关的分工：启用飞书同步 = 同步能力总开关；允许定时自动同步 = 是否让定时任务（工作日 10:00）自动执行——两者是「与」关系，都开启才会自动同步；手动同步不受这两个开关限制。
# 预览（默认 dry-run，不产生任何飞书写操作）
node .codebuddy/kb-feishu-sync.mjs --vault "$env:USERPROFILE\.vssaros-dev\knowledge-base\<vault-id>" \
     --src "库/ObsidianWorkspace/AI_Workspace/AI-Agent-Knowledge-Base" --dry-run

# 真正同步（分批，建议每批 10 篇观察）
node .codebuddy/kb-feishu-sync.mjs --vault ... --src ... --apply --limit 10

# 远端被手工改过时的策略：overwrite（默认，本地覆盖）| skip（跳过并记冲突）
node .codebuddy/kb-feishu-sync.mjs --vault ... --src ... --apply --on-conflict skip
参数说明
--vault知识库根目录（必填）
--src要同步的库内相对目录，可多次指定
--dry-run / --apply预览计划 / 实际执行（默认 dry-run）
--limit N本批最多处理 N 篇（分批放量用）
--interval ms每篇间隔（默认 800ms，避免触发限流）
--on-conflictoverwrite 默认 / skip
--parent新建文档的落点（面板显示为「同步到」）：my_library = 飞书个人知识库（默认）；或填云空间文件夹 token。仅影响新建文档，已同步的按原位置更新

10.1 同步做了什么

扫描笔记→ 内容指纹比对→ 新建 / 更新 / 跳过→ 图片占位 → 上传插图 → 删占位→ 回写 token / url / hash
  • 增量：前端 frontmatter 记录 hash（本地原文）与 remoteHash（远端同步后指纹）+ token/url。内容未变 ⇒ skip（零 API 调用）。
  • 格式适配：表格内的 [[别名|目标]] 会转成别名文本（否则竖线会被当表格分隔符截断内容）；不再注入重复 H1。
  • 图片：飞书导入不认本地图片路径（会变空占位），脚本改为「占位标记 → docs +media-insert 定位插图 → 删占位」。
  • 手动修改检测：remoteHash 与当前远端指纹不一致 ⇒ 判定远端被手工编辑，按 --on-conflict 处理。

10.2 定时同步

已配置 IDE 自动化任务（automation kb，工作日 10:00 增量同步）；也可手动执行上述命令，或按需改成其它时间。

首次同步前需完成 lark-cli auth login（user 身份）。若脚本提示未登录，重新登录即可，不要尝试其它修复。

设计边界（非缺陷）
  • 导入管线的 LLM 调用不经过 Agent 驱动（除开启 Agentic 构建），因此不会自动激活内置技能——技能仅在聊天中手动激活或由 knowledge-base-expert Agent 注入。
  • PDF / 图片等复杂文档的解析（OCR、版面）未内置；可先转成 Markdown 再导入。
  • 笔记语义质量取决于所选 LLM / Embedding Provider。
