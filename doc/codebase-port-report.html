③ 使用说明

3.1 它是什么 / 不是什么

这是一个 dsh 插件：把"代码图谱"（节点=文件/符号，边=IMPORTS/CONTAINS/CALLS/USAGE/INHERITS/IMPLEMENTS）做成可离线安装、可复用的能力，供 dsh 侧的智能体/页面用 ✓。它不替 IDE 建图——除非走交接档（见 3.4 ✓）；平时它读 IDE 已建好的图 ✓。

3.2 安装与配置（都在 dsh 的覆盖层里，插件不动 src/ ✓）

vssaros-codebase:
  workspaceRoot: <工作区>           # 必填 ✓
  indexDir:      <dsh 索引目录>      # 可选；缺省 <DSH_HOME>/codebase-index/<工作区哈希>/
  indexTarget:   'shadow'             # 缺省 ✓；'workspace' ⇒ 交接档（甲档 ✓）
  indexWatch:    true                 # 可选；缺省关 ✓ ⇒ 交接档必须开（否则图静默变旧 ✗）
  parser:        'auto'               # 缺省 auto ⇒ 资产可用就真解析、不可用如实降级 ✓

3.3 常用动作（都是工具 ⇒ 写动作要过审批闸 ✓）

要做什么用哪个说一句话
建 / 更新图谱codebase_index（写·审批 ✓）档位/落点/上限都在审批理由里 ✓；增量为主，连续增量太多次会自动兜底全量 ✓
看现状（落点/档位/新鲜度/保鲜）codebase_index_status（只读 ✓）甲档的两条告警（保鲜没开 / 双输）在这里能问出来 ✓
查（检索 / 依赖 / 热点 / 架构 / 改动 / 追踪 / Cypher）7 个读工具 ✓第一个会加载全量图，之后走缓存 ✓
看覆盖率（图里 vs 现在扫得到）codebase_coverage（只读 ✓）⚠ 是集合差（没有逐文件失败原因 ✗）；扫描被截断时覆盖率只是下界 ✓
搬图（跨机器/团队）codebase_export_artifact / codebase_import_artifact（写·审批 ✓）导入会先验证再落盘 ✓（坏图拒绝 ✓）

✓ 交接：设 indexTarget='workspace' + 跑一次 codebase_index + 务必同时开 indexWatch=true ✓
✓ 回退：codebase_delete_project 带 which="workspace" 删掉工作区那份 ⇒ 权限立刻回 IDE ✓（⚠ 只改配置不够 ✗ —— 权限凭据是那份清单、不是配置 ✓）

关键机制一句话
落点判据只有一个主人 ✓写/读/删除/导入导出都调 shadow.js::writeDirOf ⇒ 结构上不可能"写一处、读一处" ✗✗
两档解析regex（快，只有 IMPORTS/CONTAINS ✓）/ tree-sitter（真解析：符号与行号准确 + 四种符号间边 ✓）；缺省 auto ✓，档位与耗时落盘可见 ✓
所有权声明（producer ✓）→ 让路（IDE 严格 === ✓）→ 回退（删清单 ✓）三段；权限凭据是清单，不是配置 ✗
审批闸写动作（index / delete / export / import）都进 WRITE_TOOLS ✓，理由按工具名分岔并点名将被动的目录 ✓
诚实边界（写死在页面/输出里 ✓）覆盖率是集合差（无逐文件原因 ✗）· 截断不下"图过期"结论 ✗ · 7 天阈值是启发式 ✓ · ingest_traces 无对应物 ✓
