一、TL;DR：值得抄的 8 条 + 明确不抄的 4 条

#结论为什么
值得抄（我们的 P1–P4 要按它修订）
R1拖拽用 Pointer Events，不用 HTML5 DnD；配 6px 阈值、克隆 ghost、FLIP 动画、Esc 取消、边缘自动滚动它的注释明说理由：Pointer 事件在 触摸 WebView 里可用、且避开宿主原生拖拽。我们的页面跑在 Electron WebContentsView 里，正撞这条
R2落点判定要"轴自适应 + 最近矩形兜底"网格换行后纯 x 轴判定会错；卡片间有间隙时指针可能不在任何卡上 ⇒ 两处都要兜
R3每个组件一份 normalizeConfig（逐组件迁移 + 类型纠正）比"整份布局一个大版本号"实用得多：单个组件的配置能各自演进而不动别人
R4组件实例有生命周期：registerCleanup/registerInterval + isAlive() + 渲染 token重绘/换页/异步回来时**不泄漏、不写脏 DOM**。我们 P4 一旦"按卡取数"就必须有这套
R5未知组件渲染"占位卡"而不是忽略（记录 provider 插件名）插件卸载/未加载时用户**看得见**发生了什么，还能删掉它；比"静默消失"体验好一级
R6改布局只更新 CSS 变量，不重绘组件（--hp-row/--hp-gap + is-editing class）拖拽/缩放时组件内部状态（滚动位置、输入框、图表）不被重置
R7保存要"合并 + 可等待"：200ms 合并突发写，返回同一个 promise；卸载时冲刷拖拽/打卡会连发几十次保存；我们跨进程写盘 + 有锁，更需要合并与"写成功"的确认语义
R8拖拽/缩放要有专门的自动化测试（真 Chromium + 真 CSS + hasTouch + 关动画跑位置断言）它是本项目唯一"用测试钉住交互"的地方（scripts/test-sorting.mjs）—— 我们上一版方案只靠探针断言 DOM，**不够**
明确不抄
N1多页（pages[] + 页签）的**完整 UI**一期无必要；但 schema 预留（见 R10）—— 它的 HomePagesSettings.pages[] 已经证明这条路可扩展
N2**用户脚本组件**（customWidgetsFolder 扫描目录 + 热重载 + 粘贴代码新建）它的运行环境是单机 Obsidian；我们是 HTTP 页面 + 有 dshWriteOwnership 守卫 ⇒ 这是一条**新的执行/写入通道**，风险远大于收益，必须单独立项
N3它的具体组件（天气/微信/多微表格/批注/媒体…）都在 Obsidian 的数据模型上，与 dsh 无关
N4React/原生 DOM 的命令式渲染方式我们的页面是**服务端渲染的 HTTP 页**，没有 React 运行时；要保留"服务端出骨架"这条主线（见 §5）

3.2 ★ 精华一：PointerSorter —— 一套完整的"网格拖拽重排"

项目 src/ui/sortable.ts。它把"拖拽"拆成 6 件必须各自处理的事，每件都有明确理由：

要点做法理由（它的注释原文 / 我的解读）
输入通道Pointer Events（pointerdown/move/up）+ setPointerCapture原文："Pointer events also work in touch WebViews and avoid Obsidian's native drag handling" ⇒ 触摸 WebView 可用 + 避开宿主原生拖拽
点击 vs 拖拽DRAG_THRESHOLD = 6 px 才起拖；起拖后置 suppressClick，在捕获阶段吞掉随后的 click否则"点一下手柄"会变成一次 0 距离拖拽，把正常按钮点击吃掉
视觉反馈克隆一张 ghost 挂到容器父节点（保留页面 CSS 变量），拖动只改 transform: translate3d()transform-only ⇒ 每帧不动 layout；挂父节点 ⇒ 页面级 CSS 变量仍生效
落点判定① 命中卡直接用它；② 否则取到矩形距离最小的卡（max(...)²+max(...)²）；③ 判断该卡是否"孤行"再决定用 x 还是 y 中线；④ 换算成 beforeId换行后的网格用 x 轴判定会错；卡片有间隙时指针可能不在任何卡上；插入点语义（beforeId）比索引算术更稳
滚动rAF 每帧：靠近容器上下边 48px 内自动滚动（delta = ceil(dist/4)）首页比一屏高时，不这么做就拖不到屏幕外的位置
落位动画FLIP：先记录所有卡矩形 → 改 DOM → 用 Web Animations 从旧位置滑到新位置；尊重 prefers-reduced-motion；动画带 id 便于测量前先 cancel；可传入 ghost 的矩形让"落下的卡从预览处滑出"没有 FLIP 就是"瞬移"，用户会怀疑自己拖错了
取消Esc / pointercancel / lostpointercapture / window.blur 全部收口到 finish(false)；离开编辑模式、换页、重建 DOM 前都显式 cancel()拖拽是**跨组件的全局状态**，不显式收口必然残留高亮/ghost
算法可测纯函数 moveBefore(items, id, beforeId) 抽出来单独导出顺序算法能脱离 DOM 单测（scripts/test-sorting.mjs 就在用）
// 插入点语义（src/ui/sortable.ts:8-17）—— 注意 before > from 时要 -1
const to = before > from ? before - 1 : before;
const [moved] = items.splice(from, 1);
items.splice(to, 0, moved);

3.3 ★ 精华二：WidgetHost —— 每张卡一个生命周期宿主

src/view.ts:18-113。它解决的问题是"**组件是长期活着的、会被反复重绘的**"：

  • 渲染 token：每次渲染自增，异步回调回来先比 token ⇒ 过期结果直接丢弃（if (token === this.token)）。
  • registerCleanup / registerInterval：组件注册的清理与定时器在**重绘或卸载时自动执行**（dispose() 里统一跑）⇒ 组件作者不用自己管。
  • isAlive()：给"异步加载完再画"的组件用。
  • addHeaderAction(icon,label,onClick)：组件可在卡片标题栏加按钮，**重绘时自动清除**（不必手写 DOM 回收）。
  • setSubtitle：标题栏右侧副标题（如"共 12 条 · 3 分钟前"）。
  • isEditing()：组件可据编辑态改变行为（例如编辑时不自动刷新）。
对我们的直接含义：我们服务端渲染没有"组件重绘"问题（P1–P3 用不到），但 P4"按卡取数/自动刷新"会立刻需要同款约定：定时器、清理、过期结果丢弃。 建议 P1 就把契约字段留出来（哪怕先不做），免得 P4 时推翻组件接口。

3.4 ★ 精华三：registry + provider 占位 + 配置演进

src/widgets/registry.ts，4 个值得抄的具体决定：

  • 未知 kind 一律保留：isWidgetKind 只要"非空字符串"就认 ⇒ 注释原话"第三方组件所属插件未加载时，配置不能丢"。渲染时给占位卡（getWidgetProvider(kind) 拿到提供者插件名显示给用户）。
  • 内置 kind 不可被覆盖（registerWidget 直接抛），第三方同名会覆盖自己（便于热重载）。
  • 卸载用"定义同一性"校验：unregisterWidget(kind, definition) 只在"当前注册的正是我"时才删 ⇒ 防止 A 插件卸载时误删 B 插件的同名注册。
  • 注册变化可订阅：onRegistryChange(kind, registered) ⇒ 视图据此**原地补画/移除**占位卡，而不是整页重载。
  • 配置归一化两层：normalizeWidgetConfig()（取 definition 的 normalizeConfig?.，缺省 {...defaultConfig(), ...raw}）+ 通用助手 normalizeWith(defaults, raw)（按默认值类型纠正：数字强转 + 有限性检查、布尔接受 "true"、字符串 String()、数组/对象做形状校验）。

3.5 ★ 精华四：保存与设置校验

  • 合并写 + 可等待（src/main.ts:113-131）：200ms 内多次 saveSettings() 只落一次盘，并返回**同一个 promise** ⇒ 调用方 await 到的是"真的写完了"；onunload 冲刷未决写（:94-104）。
  • 读入即 sanitize（loadSettings → sanitizeSettings(raw)，:108-111）⇒ 老数据/脏数据在**入口**被规整，后面所有代码都能假设"内存里的设置是合法的"。（我们上一版方案的"坏 JSON 回落默认"只覆盖了"整份坏"，这里是**逐字段**规整，更细。）
  • 组件配置在保存时再跑一次 normalizeConfig（ui/modals.ts:37-41）⇒ 用户手填的值也被纠正后才落盘。

六、优化方案（对上一版 dsh homepage 方案的修订）

按"改动成本 / 收益"排序。R1–R5 是必须在 P1–P3 内做掉的；R6–R10 分别落在 P1 / P2 / P4 的相应步骤里。

#修订落在哪一步为什么必须（而不是"更好"）
R1拖拽改为 Pointer Events：6px 阈值 → 克隆 ghost（挂容器父节点、transform-only）→ rAF 跟随 + 边缘自动滚动 → 落点高亮 → 松手 FLIP 动画；Esc/pointercancel/blur 收口取消；离开编辑态/换布局前显式 cancelP3我们的页面在 Electron WebContentsView 里；HTML5 DnD 在触摸/WebView 场景不可靠，且会和宿主原生拖拽打架
R2落点判定加轴自适应（命中卡是否"孤行"决定用 x/y 中线）+ 最近矩形兜底；插入点用 beforeId 语义，纯函数抽出来P3（纯函数部分可进 P1）12 列网格换行后，纯 x 轴判定会插错位置；卡片间隙处指针不在任何卡上

6.2 修订后的交互算法（要点，**代码自写**）

  • 起拖：pointerdown 落点在卡上 → 记录起点；移动 > 6px 才认定起拖（并把后续 click 吞掉）。
  • 预览：克隆卡片为 ghost，挂到网格的**父容器**（保留主题变量），只改 transform。
  • 落点：命中卡 → 用它；否则取**距离最小**的卡；据"该卡是否独占一行"决定用 y 中线还是 x 中线；换算成 beforeId；插回原位 = 无操作。
  • 收尾：松手 → 记录 ghost 矩形 → 改顺序 → 用 FLIP 把每张移动过的卡从旧位置滑到新位置（读 prefers-reduced-motion，用户禁动画时直接落位）。
  • 取消：Esc / 指针中断 / 窗口失焦 ⇒ 不提交、恢复原样；离开编辑态 / 换页 / 重绘前一律 cancel()。
  • 尺寸：右下角手柄拖动按列/行吸附；Esc 恢复；方向键逐格；窄屏只调高；按钮 ◀▶ 与手柄共用同一个 setSize。
