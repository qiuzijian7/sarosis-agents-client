06Chat 使用说明

何时用

场景用哪个
一两次委派delegate_task
开始编码前多区域探索plan_explore
大规模扇出 + 编排逻辑（分组/流水线/汇总/重试）workflow

调用参数

{
  "script": "纯 JS 体（顶层 await；return JSON；勿写 export const meta）",
  "meta":   { "name": "audit-concurrency", "description": "…", "phases": [{"title":"扫描"}] },
  "args":   { "files": ["…"] },                     // → 脚本全局 args
  "canvasAnchorUid": "uid-a3f2…"              // 可选：完成后结果归档画布锚点 OUTPUT
}
  • 观察：工具卡内嵌每个 agent() 状态（100ms 刷新）；完成文本自带投影摘要；⟨投影⟩工作流自动落盘
  • 取消：Stop → run cancelled（≤5s 收敛、子代理全中断、无残留）
  • 失败自纠：语法错/超 caps/meta 缺字段 → isError + 明确原因 → 模型改脚本重调（无部分输出）

07画布使用说明

节点配置（双击编辑）执行语义
Saros.Agentprompt（{{input}}=上游）、agentId子代理跑完 → SAROS_JSON 快照
Saros.Promptprompt 模板纯文本物化（本地，无后端）
Saros.IfElse / SwitchevaluationTarget（如 verdict.ok）上游 JSON 点路径 truthy → {verdict,branch,value}
媒体节点—ComfyUI/provider 既有 executor（波次混排）

⇗ 导出为脚本

  1. 工具栏点 ⇗ → 按波次生成脚本（层内多节点=parallel；媒体节点=null 占位+注释；缺 prompt=null+警告）
  2. 脚本注入当前 Chat（需先选中 Agent）→ 模型可加 for 扇出等动态能力后执行
  3. 导出产物已通过「worker 沙箱真实执行」验证（生成器不自产语法错）

与 Chat 双向

  • 读：脚本 nodeOutput(stageUid, slot?)（画布节点须已运行；查无 uid → fatal 明确报错）
  • 写：工具传 canvasAnchorUid → return 值落该节点 OUTPUT（SAROS_JSON，可再被后续 nodeOutput 读）

08脚本规范（7 hooks）

// 范式：map-reduce + 画布联动
phase('读取画布')
const sketch = await nodeOutput(args.sketchUid, 0)        // ← 画布快照（json/text/media）
phase('生成')
const drafts = await parallel(args.styles.map(s =>
  () => agent(`以 ${s} 细化：${JSON.stringify(sketch)}`, { label: s, /* schema, agentId 可选 */ }))
return { drafts: drafts.filter(Boolean) }                // 失败=null；return 必须 plain JSON
hook失败语义
agent(prompt, {label,phase,schema,agentId})子代理失败 → null（不杀 run）
pipeline(items, s1…) / parallel(thunks)普通 stage/thunk 抛错 → 该项 null；fatal 穿透杀脚本
nodeOutput(uid, slot?)查无/越界 → fatal INVALID_ARGUMENT（fail-loud）
caps：并发 5 / 总数 1000 / 条目 4096超限 → fatal（模型可读原因）
红线：脚本无 fs/网络/timer；worker 隔离=可终止+结果边界（非安全边界）；纯同步死循环靠 terminate 兜底（description 已约束）。
