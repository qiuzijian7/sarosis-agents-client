02使用说明

按这一步步来；括号内是对应的代码依据，见文末「源码依据」。

1

在根会话里打开开关

输入框右下角点 「Hy4 · Default ⌃」 → 弹出「模型与推理等级」菜单 → 打开 「启用智能体团队协作」。子会话不显示这行开关。若会话被锁定、正在保存，或模型请求历史尚未加载，开关暂时不可点；保存失败时由菜单宿主给出提示。

2

等状态回写（约 1–2 秒）

官方开关不做乐观更新：要等 Host 落盘并把 agentTeam 投影推回浏览器，开关才变色（本机实测约 1–2 秒，取决于落盘与投影推送）。期间开关被置为 pending 且没有 loading，这是「点了像没反应」的主要来源。开启成功后界面仍不会出现新面板，属正常。

3

发一条明确要求分工的消息

模型在这一回合才拿到 team:policy 策略段与四个任务工具；它会用 subagent / subagent_fork 建可继续执行的队友，用 list_agents / send_message 发现与联系，用 team_task_create 建任务。示例（示意，可按实际任务改写）：

把这个需求拆成 3 个互不重叠的任务：分别派 reviewer / coder / tester 并行处理；用共享任务板记录标题、依赖和负责人，认领后完成后汇总给我。
4

在 Subagent 入口看任务板

会话标题栏的 Subagent 入口里，成员树下方出现「共享任务」：灰点=待处理、橙点=被依赖阻塞、蓝点=进行中、绿点=已完成；标题右侧显示数量。点任务行展开完整描述与负责人（打开一项会收起上一项）。面板只读，改任务只能让模型用工具做。

5

用完可关闭

同一菜单关掉开关；会话已经发过模型请求时会弹「确认停用智能体团队协作？」，说明停用会停止共享任务工具与协作指令，并可能影响缓存复用。取消 / Esc 不改状态；确认后任务与子代理都保留，选择本身重启后仍有效，重新打开可继续。

VsSaros 专属前置：写了 tools: 白名单的 Bot 会话，过去会把 host 层 team_task_* 一并 deny 掉 —— 开关打开也拿不到工具。@vssaros/dsh-agents 0.2.387 起按 mcp__* 同口径默认放行（可用 !team_task_* 主动排除）。改动需重启 Host 装载新版本；标准 preset 会话不受该限制。官方 when: agentTeams.isEnabled(agent) 仍保证开关关闭时工具不可见。

05规则与边界

这些限制决定了「哪些现象是正常的」。

条目规则
生效范围选择属于根会话，整棵 subagent 树共用；后代模式取自存活的根。普通分叉是新树的根，默认关闭。
成员与通信队友就是 continuable subagent：subagent / subagent_fork 创建，list_agents 发现，send_message 联系，wait_agent 等收件箱。Team 不注册自己的成员/消息工具。
任务最多 256 个未删除任务；team_task_list 每页最多 100；删除保留墓碑。所有更新走 CAS，未就绪（依赖未完成）、过期修订、未授权修改都报类型化错误。
不会自动发生任务变更不结束 wait_agent、不加收件箱、不唤醒空闲成员；owner 不会因成员不活跃 / 中断 / 退出而自动释放。需要人继续干活就 send_message。
文件系统全员共享同一工作目录，没有 worktree / 合并 / 文件锁；writeScopes 只是提示性元数据，重叠只警告。Lead 需自己划分写范围并检查最终 diff。
开销策略段 + 四个 schema 是每个成员每次请求的固定 token 成本；开关旁 ⓘ 也明确「复杂任务表现更佳，token 开销相应更高」。
与 VsSaros Bot / SuperAgent两套系统互不感知：官方 Team 不读我们的 Bot 名册、群聊或 SuperAgent 组队；officialTeamAdapter.js 只把官方成员以 dsh-team:* 只读投影进外部 Bot 名册，无专用 UI。
Bot 会话工具放行@vssaros/dsh-agents 0.2.387 起 team_task_* 默认穿过 tools[] allowlist；!team_task_* 可主动排除；守卫 check-agent-tools.mjs 判据 D 逐个验证 18 份内置 Bot 名单。
