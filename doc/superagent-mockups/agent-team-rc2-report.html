前提校正：不能把「rc.2 新增智能体团队」写成事实

dsh-plugins/dsh-compat.json:16 记录 rc.2 相对 rc.1「依赖树同构，新增 @deepseek-ai/dsh-cua-bundle」，并明确「唯一的破坏性变化是 dsh-skill-office 三个技能改成三个工具」；rc.2 条目一次也没提到 Team。本地能证实的只有：Agent Team 包从 experimental- 前缀改名为 dsh-agent-team / dsh-tool-agent-team / dsh-client-ui-agent-team，和 tool-subagent* 一起出现在依赖树里。

  • rc.2 的 38 插件种子 profile-seed/seed.json:4-41 不含 Team bundle（默认不装/不启用）。
  • W/dsh-runtime/0.2.2-rc.2/ 无 node_modules、真机无 0.2.2 安装、无 npm 缓存 ⇒ 官方工具的 JS、patch、9 个工具名、开关状态均无法本地验证。
  • 行为细节唯一可靠依据是 incubator/dsh-plugin-teamflow/docs/benchmarks/teamflow-vs-dsh-builtin-agent-team.md，它标注的对照版本是 dsh-v0.1.7-alpha.1（2026-09-22）实验层，不是 rc.2。

01 · 版本事实按证据等级

点卡片「展开」看精确落点；上方过滤可只看 A 级（能在本机复现的）或 B 级（文档推断）。

02 · 与本机 Bot 是否兼容

判定：部分兼容 —— 更接近「两套系统互不感知，启用即可能冲突」

本机 Bot 是 vssaros-agents 用 Symbol.for('vssaros.team') 挂在进程内的私有团队总线（Bot 名册 / 外部 Bot 登记 / 委派台账 / 群聊状态）。官方 Agent Teams 没有接入这个总线：全仓 dsh-plugins/ 下 agent-team / spawn_teammate / team_task_ 只出现在一份文档台账里。两者不共享成员、消息、任务，也不共享 Bot 名册。

03 · 与 SuperAgent 组队功能的差异10 项

官方列的行为证据来自 0.1.7-alpha.1 基准文档（B 级）；SuperAgent 列来自 0.1.122 源码（A 级）。当前出厂配置下 SuperAgent 的 teamEnabled 默认 OFF，所以这是「两个都需显式开启的可选特性」之间的对比。

04 · 能借用什么 / 替换会回退什么

可以借鉴（官方的强项）

  • 持久 mailbox 与「离线排队、恢复后送达、accepted/queued 两态」的消息语义；本机 teamBus.js:117-169 已有类似订阅形态可扩展。
  • 共享任务板的 CAS 不覆盖、tombstone、配额（maxTasks: 256）等运行时原语。
  • 如果 Team 层稳定，SuperAgent 的「编排骨架」有机会上移复用，把门禁/计量留在自己这层。

直接替换会丢掉的东西

  • 人工「同意」门与 mayConsent() 发起人校验：官方实验层明确没有。
  • SQLite 的 team_proposal / team_step / team_bot / team_approval、fingerprint 与 7 天方案复用：官方只有会话日志回放。
  • usage_call 分账、meter() 累计、step_approval_rule 步骤审批：官方「零质量语义」。
  • 外部 Bot / vssaros-* preset / workOnly 工具白名单、DS Bot 共存保证、以及 teamEnabled=false 的原型单 worker 快路径。

05 · 风险与「不要夸大」

三个真实风险

  • 工具名 scoped 覆盖：实验层文档说 Team 组合包会 disabled: true 掉 tool-subagent* 四行；SuperAgent WORK_TOOLS 依赖 subagent / send_message / list_agents / interrupt_agent，启用后可能破坏 worker 子代理与原型流程。
  • 命名碰撞：两边共用 dsh 的 agentPresets / sessionController / standard；standard 被 SuperAgent 子代理与官方 preset 共用，teammate 名还可能撞 vssaros-* Bot id 或外部 Bot superagent。
  • 无共存保证：dsb-coexist.spec.ts 只测 DS Bot 与 SuperAgent；仓库里没有 official-team × external-bot 的共存测试。

报告中刻意没有下的结论

  • 没说 rc.2「新增」了智能体团队（compat notes 反驳）。
  • 没把 maxMembers: 8、TeamId === SessionId、9 个工具、禁用 subagent 直接套到 rc.2（无源码验证）。
  • 没断言 54 个官方工具里含或不含 Team 工具（check-agent-tools.mjs:82 是动态计数，本机无 node_modules）。
  • 没说 dsh-experimental-agent-team-profile 在 rc.2 可安装（dshPluginRecommendations.ts:85 仍是旧实验名，rc.2 lockfile 里没有）。
  • 没忽略 teamEnabled 默认 OFF 与预算闸门已放开这两处 2026-11-12 的新变化。

06 · 要真正定论，还差什么

  • 安装 dsh-runtime/0.2.2-rc.2/node_modules（或跑一次 profile 种子），让 check-agent-tools.mjs 能扫到 dsh-tool-agent-team 的 name: "…"，拿到 54 个工具真名。
  • 打开官方组合包的 cordis.patch.yml，确认 rc.2 是否仍 disabled: true 掉 tool-subagent* —— 这是「兼容 / 冲突」的分水岭。
  • 把 dshPluginRecommendations.ts:85 的旧实验包名对齐到 dsh-agent-team，否则按版本拼出的 spec 在 rc.2 锁文件里不存在。
  • 在隔离 profile 里同时启用官方 Team 与 vssaros-agents，实测 vssaros.team 总线是否能把官方 teammate 登记为外部 Bot；补一条 official-team × external-bot 共存测试。
  • 注意种子里随包 SuperAgent 还是 0.1.121（seed.json:34），比仓库 0.1.122 落后一版，验证前先对齐。
