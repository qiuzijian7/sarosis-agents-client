③ 三处改动与影响面

改动做法影响面 / 风险
P1 侧栏紧凑版
插件侧		 页面按宿主注入的表面信号渲染两态：侧栏＝摘要（按钮 + 4 mini KPI + 活跃会话 5 条 + 待处理 + 口径脚注），编辑区＝现在的完整页。信号用既有机制（window.vssarosDsh.surface，由 --vssaros-dsh-surface= 注入），新增一个取值。 ★ 不变量：隐藏 meta 锚点块在两种表面都渲染 ⇒ p3-09 不受影响；这条要写进守卫，否则"侧栏改版把探针搞红"是必然的。
P2 编辑区承载
IDE 侧		 新增「dsh 插件页」的 EditorInput + EditorPane（照 AgentStudioDashboardEditorInput/Pane 的形态），内部摆 WebContentsView 加载 /x/dashboard/，surface 传编辑区值。这条路径当前不存在（编辑区只承载聊天页）。 ⚠ 与方案文档 dsh-foundation-refactor-plan.html §5.12/9.1「dsh 页面不进 mainPart、去掉『在完整面板中打开』类入口」相冲突 ⇒ 需要你一句话改口径。先例：聊天页本来就在编辑区（surface=chat）。
P3 按钮通道
桥		 侧栏页点按钮 → 经页面桥新增一条命令（如 openPluginPage），照既有 DshPageCommand 形态（联合类型 + preload + host 校验 + 版本号）。 比"页面自己想办法"更符合既有安全模型（桥是封闭白名单）。影响 dshPageBridgeProtocol.ts 的版本号与 validatePageCommand；探针需覆盖"未知命令被拒"。

④ 两条要你拍板

D1　编辑区里的「完整页」是哪一个？

推荐 A：我们的 dsh 可编排页（同一页、不同 surface 渲染）—— 与你的意图一致，但需新增编辑区承载路径（P2），并改一句方案口径。
不推荐 B：原生完整 Dashboard（命令 agentStudio.openDashboard 现成，零 IDE 改动）—— 但内容是原生的，我们的可编排页仍只在侧栏，等于你要的东西没实现。

D2　侧栏紧凑版里保留哪些控件？

推荐：保留范围切换（今日/7 天/30 天/全部，紧凑分段）＋口径脚注；把「编排」与「添加组件」移到完整页（窄栏里拖拽/缩放体验差、易误触），侧栏只留「打开完整 Dashboard」这一个动作。
备选：侧栏也留编排入口（我可以做，但窄栏里手柄只有几像素，误触概率高）。

⑤ 验证计划（实现时）

  • p3-46 扩：同一布局下 两种 surface 渲染的锚点集合完全一致；侧栏版不出现编辑态把手；紧凑版仍给出 4 个 KPI 与「打开完整 Dashboard」按钮。
  • p3-09 不动：锚点在隐藏 meta 块里、与 surface / 布局均无关（现有 89 条断言继续全绿）。
  • IDE 侧：新 EditorInput/Pane 的注册与命令 + 桥版本号的既有守卫（--common）＋ 真机点一次按钮（这次起真 IDE 或按 p3-09 的进程内假 Host 驱动）。
