# 知识库（侧边栏「资料库」· Knowledge Base）

> **一句话**：知识库是 Agent Studio 内置的「个人资料库」—— 把聊天消息、工作区文件、网页内容沉淀成结构化 Markdown 笔记，自动建立双链图谱与语义索引，既供人浏览检索，也供 Agent 在对话中调用。**全部在渲染进程内完成：无需外部二进制、无需 IPC、离线可用。**
>
> 本文档分两部分：**一、简介**（对比其他项目/方案存在的问题，以及我们如何解决）；**二、使用说明**（详细操作步骤）。

---

## 一、简介

### 1.1 它是什么

```
输入（四条管线）
  ① 聊天消息「导入知识库」按钮     ② write_file 卡片「导入知识库」
  ③ 工作区/资源管理器文件右键       ④ 侧栏「导入」下拉（Obsidian 库 / 文件 / 文件夹 / .code-workspace / URL）
        │
        ▼  阶段 1：schema 分类 → 原样落盘（带 frontmatter 溯源）
   <vault>/库/raw/<类型>/<标题>-<日期>.md          ← 资料原件，只进不改，导入即不丢
        │
        ▼  阶段 2：构建为笔记（默认 Agentic：knowledge-base-expert Agent；失败自动回退直连 LLM）
   <vault>/笔记/<类型目录>/<主题>/<笔记>.md         ← 结构化笔记（Obsidian 风味 Markdown + [[双链]]）
        │
        ├─ 确定性补链（enrichWikilinks，扫描全库标题互链，零 LLM 成本）
        ├─ 导航与洞察：index.md / overview.md / insights.md（Louvain 社区 + 社区语义摘要）
        ├─ 目录摘要：<目录>/.overview.md（变更 ≥10% 才重算）
        │
        ▼  三份索引（进程内内核 KbNativeKernel，删除/重命名即时生效）
   KbFullTextIndex（BM25）   KbLinkGraph（双链图谱）   KbVectorIndex（语义向量）
        │
        ▼
   Agent 侧：kb_search（唯一检索入口）/ kb_suggest_links / kb_topic_overviews + <kb_overview> 自动注入
   人侧：资料库视图（文件树/搜索/图谱/思维导图）+ 笔记编辑器 + 知识库设置面板
```

层次结构（代码集中在 `src/vs/sessions/contrib/agentStudio/`）：

| 层 | 关键文件 | 职责 |
| --- | --- | --- |
| 视图层 | `browser/views/knowledgeBaseView.ts`、`kbSettingsEditorPane.ts`、`kbGraphEditorPane.ts` | 侧栏「资料库」（树 / 搜索 / 排序 / 文件操作 / 回收站）、设置面板、关系图谱 |
| 控制器 | `browser/kbImportController.ts` | 导入全生命周期：分类 → 落盘「库」→ 构建笔记（agentic / 直连）→ 导航维护 → 门控 → 摘要 |
| 内核 | `browser/views/knowledgeBase/kbNativeKernel.ts`、`kbIndex.ts`、`kbGraph.ts`、`kbVectorIndex.ts` | 全文索引（BM25）、双链图谱（单文档即时更新）、向量索引（含 embed 文本缓存） |
| 知识管线 | `browser/knowledge/`（schema / classifier / frontmatter / enrichWikilinks / communityDetection / topicOverviews / obsidianNoteFormat / feishuSyncCore…） | 类型体系与分类、格式真源、确定性补链、社区检测与摘要、飞书同步 |
| 服务 / 工具层 | `browser/kbNativeKernelService.ts`、`browser/providers/tool/kbVaultRecallTools.ts` | 视图与编辑器共享同一内核实例；三个 Agent 工具；`<kb_overview>` 消息标签注入 |
| 异步加速 | `views/knowledgeBase/kbWorker.ts`、`kbWorkerManager.ts` | Worker 预计算图谱与提及索引，避免主线程二次全量读盘 |

### 1.2 其他方案存在的问题

| 方案 | 存在的问题 |
| --- | --- |
| **Obsidian 等纯本地笔记工具** | ① 只有「人写人看」，Agent 无法检索 —— 要让 AI 用还得自身外挂向量插件 + 另一套模型配置；② 与 IDE / 代码工作区割裂，聊天里产出的结论要手工复制粘贴成文件；③ 双链靠手写，新笔记不会自动连上已有知识；④ 没有「构建」环节，长文/网页/资料永远是原文，不产生结构化笔记与摘要。 |
| **云端知识库（Notion / 飞书 wiki / 语雀）** | ① 必须联网、内容上传云端，内网/离线/保密场景不可用；② Agent 接入依赖平台 API 与配额，检索能力受接口限制；③ 数据不在本地文件系统上，无法 grep、无法 git 管理、无法与代码仓同仓联动。 |
| **富块笔记（AFFiNE / BlockSuite 路线）** | ① 引入体积大（13 MB 级 webview 包）与 **MPL-2.0 许可证风险**；② 引入私有 `.bsdoc` 二进制快照格式，数据被锁在自家编辑器里，Markdown 不再是真源；③ 生态不通用，无法直接用 VS Code / Obsidian / git 等既有工具链。（本项目曾试过此路线并已放弃，见 `doc/affine-replace-siyuan-plan.md`） |
| **RAG 平台 / 向量数据库服务（RAGFlow、Dify、独立向量库）** | ① 要额外部署服务或数据库，运维成本高；② 向量索引是唯一检索通道，缺 BM25 会漏掉精确术语/代码符号；③ 检索结果不可解释、无「笔记 → 原文」的溯源链路；④ 库内容分布不可见，无法「先看概览再深入」。 |
| **纯文件夹 + grep** | 只有字符串匹配，没有语义召回、没有双链关系、没有图谱与社区摘要；中文检索基本失效。 |
| **旧式「抽取引擎」（Hyper-Extract / llm-wiki 范式）** | 一次性抽取产物不可读、不可改、不可追溯；同一份资料反复处理、跨会话碎片化；与笔记生态不兼容。（该系统已整体下线，能力由 `kb_search` 等补位，见 `doc/kb-deprecate-hyper-extract-refactor-plan.md`） |
| 以上方案的**共同缺失** | 都没有「**导入 → 构建 → 索引 → 注入 Agent 上下文**」的闭环：要么只解决人，要么只解决机器；且普遍缺少增量一致性（删除/重命名后索引残留幽灵文档）、缺缓存（重复花 LLM/Embedding 钱）、缺冲突与限流保护。 |

### 1.3 我们如何解决

| 上游问题 | 我们的解法 |
| --- | --- |
| Agent 用不上人的笔记 | **人机双入口、同一条管线**：同一份 `.md` 既在侧栏「资料库」里给人读/改，又通过 `kb_search` 给 Agent 检索；聊天消息/文件一键「导入知识库」，Agent 产出的结论可直接沉淀回库。 |
| 数据上云 / 联网依赖 | **本地优先**：Vault 就是一个本地文件夹，内容全是 Obsidian 风味 `.md`（frontmatter + `[[双链]]` + callout），可用任何编辑器、git、grep 处理；内核在渲染进程内运行，离线可用。 |
| 富块格式锁死数据 + 许可证风险 | **Markdown 是唯一真源**：明确放弃 BlockSuite/`.bsdoc` 路线，改用 react-markdown webview 渲染（`kbBlocksEditorPane`），散落在仓库里的任何 `.md` 都能直接拖进库。 |
| 只有向量检索、结果不可解释 | **混合检索（BM25 + 向量 RRF 融合，k=60）**：默认 `hybrid`，可切 `fulltext`（无需 Embedding，秒回）/ `semantic`；结果带 `score`、`uri`、摘要与 `[[引用]]` 回链，可点开原文。Embedding 未配置时静默降级为全文检索并给引导，不报错。 |
| 库内容不透明、检索靠猜 | **三层渐进披露**：L1 聊天自动注入 `<kb_overview>` 目录摘要标签（TTL 60s、1.5s 超时、1500 字符预算）→ L2 `kb_topic_overviews` 列目录摘要 → L3 `kb_search` 深入；构建期自动产出 `index.md` / `overview.md` / `insights.md` / `<目录>/.overview.md`。 |
| 资料无法结构化 | **两阶段构建（默认 Agentic）**：阶段 1 立即落盘（**导入即不丢**，构建失败原件仍在 `库/`）；阶段 2 由 `knowledge-base-expert` Agent（技能注入 + 工具能力）产出结构化笔记，Agent 无产出/报错时**自动回退**直连 LLM 管线，两条路径共享构建缓存。 |
| 双链靠手写、图谱稀疏 | **LLM 产链 + 确定性补链**：构建时按格式约定产出 `[[双链]]`，再零 LLM 成本扫描全库标题补链；`kb_suggest_links` 用已存向量做纯本地相似度计算，推荐「语义相关但尚未链接」的笔记补链。 |
| 索引残留幽灵文档 | **即时一致性**：删除/重命名/移动后，全文索引、向量索引、图谱节点与边、提及索引**四份同时剔除**（`removeDoc` / `removeDocsUnder` / `upsertDoc`），不会出现「搜到的笔记已经不存在」。 |
| 重复花 LLM / Embedding 钱 | **多层缓存**：构建缓存 `.kb-build-cache.json`（agentic 与直连共享）、社区摘要缓存（键 = 成员标题指纹）、目录摘要 freshness 缓存（变更 ≥10% 才重算）、**embed 文本缓存** `.kbembedcache.json`（按 tag + 文本指纹复用，切换/切回 provider 不重复计算，2 万条淘汰）。 |
| 噪音与碎片化 | **Schema 驱动分类 + 去抽象化门控**：类型体系指导分类与目录归类（模型未按约定输出时按 frontmatter `type` 二次兜底）；派生类笔记需「≥2 个不同来源」确认才标为 `active`，配合别名归一抑制碎片噪音。 |
| 同步到团队/外部平台易出错 | **飞书同步内建**：同步脚本随产品发布（`resources/.agents/kb/feishu-sync.mjs`），单向、增量、幂等；以 frontmatter 身份锚定（`feishu.token/type/space/parent/url/hash/rev/syncedAt`），内容指纹未变即跳过（零 API 调用）；表格内 `[[别名|目标]]` 自动转文本、图片走「占位 → 插图 → 删占位」；支持 dry-run 预览、分批限流、远端手改冲突策略；多类别 → 多飞书知识库并可自动建库。 |

### 1.4 特色能力清单

| 能力 | 说明 |
| --- | --- |
| Agentic 构建（默认开启） | 构建交给 `knowledge-base-expert` Agent（技能强制注入 + 工具），失败自动回退直连管线 |
| 目录摘要 L1 自动注入 | 每轮用户消息自动携带 `<kb_overview>`（缓存 + 超时 + 字符预算） |
| 混合检索（RRF） | BM25 全文 + 语义向量按 `1/(k+rank)`（k=60）融合，结果带引用与目录摘要 |
| 双链图谱 + 即时一致性 | LLM 产链 + 确定性补链；删除/重命名后四份索引即时剔除 |
| 社区检测与语义摘要 | Louvain 社区 + 一次批量 LLM 生成主题名与摘要，写入 `insights.md` |
| 隐式双链建议 | `kb_suggest_links` 纯本地向量计算，排除已建链 |
| 多层缓存 | 构建 / 社区摘要 / 目录摘要 / embed 文本缓存 |
| provider 一致性提示 | 向量索引 tag 与当前 Embedding Provider 不一致时，搜索区直接提示重建 |
| 去抽象化门控 | 派生类笔记需 ≥2 个不同来源才 `active` |
| 格式约定单源化 | 笔记格式规则集中在 `knowledge/obsidianNoteFormat.ts`，构建提示词由它生成 |
| 内核实例共享 | 视图与笔记编辑器共用同一内核实例（一次扫描、两份界面） |
| 思维导图 | 导入后自动生成/补充 JSON Canvas（`.canvas`）思维导图 |
| 导入链接 / URL | 抓取网页正文 + 图片本地化到 `库/raw/assets/`，支持小红书 · 抖音 · 知乎 · YouTube · B站等 |
| 飞书同步 | 增量镜像到飞书个人知识库，保留目录结构、支持图片与冲突检测 |

### 1.5 与「记忆」「代码图谱」的分工

| 能力 | 管什么 | 主要入口 |
| --- | --- | --- |
| **知识库** | 用户**主动沉淀**的笔记资料，落盘为可读可改的 Markdown | `kb_search`（Agent）、「资料库」视图（人） |
| **记忆系统**（agentmemory） | Agent **运行时记忆**（会话/长期记忆），由网关子进程承载 | 记忆库面板、记忆标签 |
| **代码图谱**（内置 Codebase） | 当前代码仓库的**结构化代码检索** | `search_graph` / `search_code` / `search_files` |

> 三者被刻意分开：Agent 检索人写的资料用 `kb_search`，检索代码仓库用 `search_code` / `search_files`（`kb_search` 的工具描述里也明确写了这条边界）。侧栏「资料库」顶部以 **知识 / 记忆 / 代码 / 媒体库** 四个 Tab 收敛这三类内容的浏览入口。

## 二、使用说明

### 2.1 前置条件与依赖

| 依赖 | 是否必需 | 说明 |
| --- | --- | --- |
| Chat Provider（LLM） | **必需** | 导入分类与「构建为笔记」都要用；未配置时导入会失败 |
| Embedding Provider | 可选 | 未配置时只有全文检索（BM25），语义通道自动降级、不报错；可在「知识库设置 → 🧬 Embedding 模型」配置 |
| 飞书 `lark-cli` | 可选 | 仅飞书同步需要；同步脚本已内置，无需自备 |
| 网络 | 可选 | 仅「导入链接 / URL」与飞书同步需要 |

### 2.2 五分钟上手

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 1 | 左侧活动栏点开 **资料库**（Book 图标），切到「知识」Tab → 点 **新建知识库**（默认名「我的知识库」），或用「选择文件夹作为知识库」复用已有 Obsidian 库 | 生成 Vault，落盘 `<vault>/库/`、`<vault>/笔记/` |
| 2 | 导入资料：任选 2.5 的四个入口之一（聊天消息按钮 / write_file 卡片 / 文件右键 / 侧栏「导入」下拉） | 资料立即落盘 `库/raw/`，并提示已保存 |
| 3 | 构建为笔记：库文件右键 **构建为笔记**，或点侧栏头部 **批量构建笔记** | 产出结构化笔记 + 双链 + 导航与摘要 |
| 4 | （可选）建向量索引：**知识库设置（⚙）→ 🧬 Embedding 模型 → 重新构建向量索引** | 语义检索可用；未建索引时仍可用全文检索 |
| 5 | 提问：在聊天里直接问知识库相关问题（如「知识库里关于死循环防御是怎么说的？」） | Agent 自动调用 `kb_search`，回答带 `[[笔记名]]` 引用 |
| + | （可选）同步飞书：**设置 → 📤 飞书同步** → 预览同步计划 → 立即同步 | 笔记增量镜像到飞书个人知识库 |

### 2.3 界面总览

**侧栏「资料库」**（视图 id `agentStudio.knowledgeBaseView`，容器 `agentStudio.knowledgeBase`）：

  - **关系图谱**（在中间栏打开）

### 2.4 创建 / 切换 / 关联知识库

| 操作 | 路径 | 说明 |
| --- | --- | --- |
| 新建知识库 | 资料库视图 → Vault 下拉 → **新建知识库**（或视图头 `+`） | 默认名「我的知识库」，磁盘上一个文件夹 = 一个 Vault |
| 复用已有目录 | Vault 下拉 → **选择文件夹作为知识库** | 指向已有 Obsidian 库等目录，`库/` 与 `笔记/` 会建于其中 |
| 导入 Obsidian 库 | 「导入」下拉 → **导入 Obsidian 库(.md+双链)** | 复用 `.md` + `[[双链]]` 生态 |
| 关联工作区 | 「导入」下拉 → **导入 .code-workspace**，或工作区文件右键 → 导入到知识库 | 把工作区目录**关联**入库（原位，不拷贝）；若 `.code-workspace` 内含 `codebase-memory` 配置会一并写入 Codebase 索引配置 |
| 切换 Vault | Vault 下拉点选 | 索引与文件树随切换重建 |

### 2.5 导入资料（四入口 + 两阶段流程）

**四个入口，同一条 `KbImportController` 管线：**

| 入口 | 位置 | 适合场景 | 是否自动构建 |
| --- | --- | --- | --- |
| 聊天消息按钮 | 任意助手回复下方的 **导入知识库** | 把一段高价值对话沉淀为资料 | ✅ 落盘 + 立即构建 |
| write_file 卡片按钮 | 聊天里文件写入卡片上的 **导入知识库** | Agent 刚生成的文档直接入库 | ✅ 落盘 + 立即构建 |
| 工作区文件右键 | 资源管理器 / 工作区视图文件右键 **导入知识库** | 把手上 md/资料文件入库 | ✅ 落盘 + 立即构建 |
| 侧栏「导入」下拉 / 库分区按钮 | 资料库视图 → 导入下拉（Obsidian 库 / 文件 / 文件夹 / .code-workspace / URL）、库分区工具栏 **导入链接 / URL** | 批量导入或网页剪藏 | ⛔ 只落盘，需再右键「构建为笔记」 |

**两阶段流程：**

1. **阶段 1（落盘，立即完成）**：schema 分类（失败降级安全兜底）→ 写入 `库/raw/<类型>/<标题>-<日期>.md`（带 frontmatter 保留溯源）→ 追加 `log.md`。通知：*已保存到知识库「库/raw」分区（概念/RAG）。可右键库文件「构建为笔记」生成结构化笔记。*
2. **阶段 2（构建笔记）**：默认 **Agentic**（`knowledge-base-expert` Agent，技能注入 + 工具）→ 两阶段产出 `---FILE:` 块 → 落盘 `笔记/<类型目录>/<主题>/<笔记>.md`；Agent 无产出或报错时**自动回退**直连 LLM 管线，两条路径共享缓存。

> **导入即不丢**：即使构建失败，原件仍在 `库/` 里，可稍后重试。
> **网页导入**：正文经内容抽取服务抓取，图片下载到 `库/raw/assets/<slug>/` 并改写为本地相对路径 —— 本地图片随后可被飞书同步上传。

### 2.6 构建为笔记

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 单个 | 库文件右键 **构建为笔记** | 只处理这一份资料 |
| 批量 | 侧栏头部 **批量构建笔记** | 处理所有未处理库文件；全部处理完提示「所有库文件已构建」 |
| 反馈 | 文件名旁出现旋转图标；完成发通知 | 构建是异步的，可继续做别的事 |
| 缓存 | 同内容重复构建走缓存 | 不重复消耗 LLM 额度 |

**产出物**：结构化笔记（按类型/主题分目录）+ `[[双链]]` + 确定性补链 + 导航（`index.md` / `overview.md`）+ 社区洞察（`insights.md`）+ 目录摘要（各目录 `.overview.md`）。

**笔记长什么样**：

```markdown
---
type: 概念
title: 什么是 AI Agent
created: 2026-09-20
sources: ["[[库/raw/概念/什么是Agent-2026-09-20.md]]"]
status: active
---

# 什么是 AI Agent

> 一句话定义……

## 核心特征

- 自主性、反应性、主动性……
- 相关：[[大模型幻觉]]、[[Agent Loop 构建指南]]
```

> `type` / `title` / `created` 是格式约定；`sources` 与 `status` 由管线维护（**不要手改**）。派生类笔记需 ≥2 个不同来源才会被标为 `active`。
> 导航文件 `index.md` / `overview.md` / `insights.md` 由系统自动维护，**不要手工编辑**（下次构建会覆盖）。

### 2.7 检索与问答

**人侧**：资料库视图搜索框 —— 默认 **全文检索**（点击切换为 **文件名筛选**），配合 **排序** 与 14 种排序模式。

**Agent 侧三个工具**（`category: 'knowledge'`，聊天中自动调用，也可显式要求）：

| 工具 | 参数 | 用途 |
| --- | --- | --- |
| `kb_search` | `query`（必填）、`mode`（`hybrid` 默认 / `fulltext` / `semantic`）、`limit`（默认 10，最大 50） | 唯一检索入口；返回命中 `score` / `uri` / 摘要 / `[[引用]]` + 相关目录摘要 |
| `kb_suggest_links` | `docUri`（必填，取自 `kb_search` 的 uri）、`limit`（默认 5）、`minScore`（cosine 阈值，默认 0.72） | 找「语义相似但尚未建链」的笔记，纯本地向量运算 |
| `kb_topic_overviews` | 无参数 | 列出各目录摘要，先看分布再决定深入检索 |

**上下文注入**：除被动调用外，每轮用户消息会自动携带 `<kb_overview>` 标签（各目录 `.overview.md` 摘要，TTL 60s + 1.5s 超时 + 1500 字符预算），Agent 即使不调工具也知道库里大致有什么。

**建议用法**：

| 场景 | 建议 |
| --- | --- |
| 不知道库里有没有某主题 | 先 `kb_topic_overviews` 看概览，再 `kb_search` 深入 |
| 答案需要出处 | `kb_search`，用返回的 `[[笔记名]]` 作引用 |
| 只要原文、不要推断 | `kb_search` 用 `fulltext` 模式 |
| 整理笔记、完善图谱 | `kb_suggest_links` 找候选，人工确认后补链 |

**示例提问**：

```text
- 知识库里关于「死循环防御」是怎么说的？
- 先列一下知识库的目录摘要，再帮我总结「多 Agent 系统」这一块
- 帮我看看《Agent 死循环检测与防御》这篇有没有该连但没连的笔记
```

### 2.8 阅读与编辑笔记

- 点击树中 `.md` → 中间栏打开 **知识库 Block 编辑器**（react-markdown 管线：KaTeX 公式、代码高亮、wikilink / embed 解析、目录大纲）。
- **Markdown 是唯一真源**：编辑保存即写回 `.md`，与 Obsidian / VS Code / git 生态互通。
- **思维导图**：侧栏头部「思维导图」打开或生成 `.canvas`；导入新内容后系统也会自动提取结构、创建或补充 JSON Canvas。

### 2.9 图谱与摘要产物

- **关系图谱**：侧栏头部「关系图谱」在中间栏打开（Canvas 力导向）。节点/边来自笔记正文 `[[wikilink]]` 与构建期确定性补链；社区检测用 Louvain 聚类，再对每个社区做一次批量 LLM 语义摘要。
- **自动产物**：

| 文件 | 内容 |
| --- | --- |
| `index.md` | 全库目录索引（按 type 分组） |
| `overview.md` | 整体概览（类型 × 主题统计） |
| `insights.md` | 社区列表 + 每社区主题与摘要 |
| `<目录>/.overview.md` | 单目录摘要（变更 ≥10% 才重算，点开头、不被笔记扫描） |
| `log.md` | 操作留痕 |

- **增量一致性**：删除 / 重命名 / 移动笔记后，图谱与索引**立即更新**，无需等下次全量重建。

### 2.10 文件管理

| 操作 | 方式 | 说明 |
| --- | --- | --- |
| 新建 / 重命名 | 右键菜单、`Ctrl+N` / `Ctrl+Shift+N`、`F2` | 改扩展名会弹确认；命名不含 `\ / : * ? " < > \|`，不以 `.` 或空格结尾 |
| 剪切 / 复制 / 粘贴 | 右键菜单或 `Ctrl+X` / `Ctrl+C` / `Ctrl+V` | 目标同名时询问「替换 / 跳过」（可对本次全部冲突应用） |
| 删除 | `Delete` | 移入回收站，可还原 |
| 永久删除 | `Shift+Delete` | **不可恢复**，有二次确认 |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`） | 撤销知识库文件操作（移动 / 重命名 / 删除等） |
| 批量操作 | 多选后右键 | 批量删除同样区分回收站 / 永久 |
| 拖拽 | 树节点拖拽 | 支持拖到 VS Code 资源管理器 / 系统 |

> **删除后索引即时清理**（选择性删除）：文档从全文索引、向量索引、图谱节点与边中同步移除。
> 删除笔记**不会**删除 `库/` 中的资料原件；反之删原件也不影响已构建的笔记（仅 `sources` 溯源失效）。

### 2.12 飞书同步（可选）

**在设置面板里做，不必记命令**：设置 → **📤 飞书同步**

1. 勾选 **启用飞书同步**（同步能力总开关）；如需每天自动跑，再勾 **允许定时自动同步**（工作日 10:00）—— 两者是「与」关系；**手动同步不受开关限制**。
2. 确认 **飞书 CLI**（`lark-cli`）：面板自动检测并显示版本，可「重新检测」；未安装会给安装引导，有新版可一键在集成终端升级。首次使用需完成 `lark-cli auth login`（user 身份）。
3. 配置 **同步范围**（库内相对目录，逗号分隔，留空 = 整个知识库）、**同步到**（`my_library` 个人知识库，或云空间文件夹 token）、**远端手改策略**（本地覆盖 / 跳过并记录冲突）、**限流间隔**（默认 800ms）、**类别层级**、**自动建库**、**删除清理**。
4. 点 **🔍 预览同步计划（dry-run）** 确认无误 → **📤 立即同步到飞书**；随时 **📄 查看同步日志**（命令在集成终端执行并保留输出）。

**同步做了什么**：扫描笔记 → 内容指纹比对 → 新建 / 更新 / 跳过 → 图片占位替换为真实插图 → 回写 `token` / `url` / `hash` 到 frontmatter。

- **增量**：内容未变即 `skip`（零 API 调用）；`remoteHash` 与远端当前指纹不一致 ⇒ 判定远端被手工编辑，按冲突策略处理。
- **多类别 → 多知识库**：类别 = 同步源目录下第 N 级目录（`categoryDepth` 默认 1），各类别对应一个飞书知识库，未映射时可自动建同名库；类别变更时文档自动跨知识库搬迁。
- **格式适配**：表格内 `[[别名|目标]]` 转为别名文本（避免竖线截断表格）；不重复注入 H1。

**等价命令（排错用）**：

```powershell
# 预览（默认 dry-run，不产生任何飞书写操作）
node resources/.agents/kb/feishu-sync.mjs --vault "$env:USERPROFILE\.vssaros\knowledge-base\<vault-id>" --src "库/xxx" --dry-run

# 真正同步（分批，建议每批 10 篇观察）
node resources/.agents/kb/feishu-sync.mjs --vault ... --src ... --apply --limit 10

# 远端被手工改过：overwrite（默认，本地覆盖）| skip（跳过并记冲突）
node resources/.agents/kb/feishu-sync.mjs --vault ... --src ... --apply --on-conflict skip
```

### 2.13 排错与已知边界

| 现象 | 原因 / 处理 |
| --- | --- |
| 导入报「CORS 被拦截」 | Chat Provider 不可达或代理问题 —— 检查模型配置与网络 |
| 检索只有全文、没有语义 | 未配置 Embedding Provider，或未构建向量索引（设置 → 重新构建向量索引） |
| 语义结果明显不准 | 索引 tag 与当前 Embedding Provider 不一致 —— 执行「重新构建向量索引」（或切换后的增量重建） |
| 构建没产出笔记 | Agentic 构建无产出会自动回退直连；仍失败时按日志前缀 `[KbImportController]` 排查 |
| 图谱里少了刚建的链接 | 新笔记在维护阶段刷新图谱；删除/重命名则即时生效 |
| 删了笔记还能搜到 | 不应出现（选择性删除已即时清理）；如遇请提供复现步骤 |
| 删除笔记后悔了 | `Ctrl+Z` 撤销，或从回收站还原 |
| 飞书出现重复文档 | 历史事故遗留（早期脚本「创建成功但未记账」缺陷，已修复）；历史重复文档需在飞书侧人工清理 |

**设计边界（非缺陷）**：

- PDF / 图片等复杂文档的**版面与 OCR 解析未内置**，请先转 Markdown 再导入。
- **无 ASR**：无字幕视频只能总结到标题/简介/封面。
- 小红书详情页等 SPA / 登录墙页面可能只拿到 OG 元数据；`m3u8` 不下载。
- 笔记语义质量取决于所选 LLM / Embedding Provider。
- 导入管线的 LLM 调用（除开启 Agentic 构建）**不经过 Agent 驱动**，因此不会自动激活内置技能。
