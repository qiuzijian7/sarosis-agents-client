## 2. 逐项：功能与 UI

### 2.1 内容创作（7 个）

**编曲工作台**（13 文件，唯一把"AI 对话按需抽屉化"写进 README 的）
- 功能：灵感库 —— 旋律动机 / 和声走向 / 歌词片段 / 节奏型；搜索、类型与标签筛选、归档；需要 AI 时从右侧抽屉打开。
- UI：**业务整页**（`customFrame`），右侧抽屉不常驻；列表 + 筛选 + 编辑。
- 数据：`<数据根>/bianqu-workbench/ideas.json`，三个接口 `/api/bianqu-workbench/{ideas,ideas/update,ideas/remove}`；卸载不删数据。
- 可借鉴：**"对话是抽屉不是常驻"** 这条取舍写进 README，用户一眼知道布局。

**小红书笔记创作**（12 文件，最小的一个）
- 功能：按主题+素材生成标题/正文/话题标签，可编辑、保存、复制定稿。
- UI：单列表单 + 结果区（client `lib/client.js` 18 KB 预构建，源码在 `src/`）。
- 特点：**纯客户端工作台**（`dsh/index.js` 只有 77 字节，`apply(){}`）—— 不需要 Host 服务也能工作。

**文案转演示素材**（text2demo）
- 功能：口播文案 → 可翻页、可逐步入场的演示动画；顺带生成视频标题/标签/三比例封面。
- 定位："**自己在本机用**：不上架、不上传、不投稿"（README 首段就划了边界）。

**Oil 内容创作**（140 文件，最大体量之一）
- 功能：不建封闭数据库 —— 正文与产物是**普通文件**（`~/Movies/视频项目/<日期>_<标题>/topic.md` …），任何编辑器与 AI 文件工具都能读。
- 可借鉴：**"文件即数据"**，把可迁移性放在功能之前。

**自媒体内容创作**（左选题右对话）
- 功能：选题看板（候选 → 写作中 → 已完成，一带方向/目标平台）→ 一个选题产多平台稿；素材库；跨项目发布数据汇总。
- UI：**左侧面板固定（选题/方向/平台），右侧就是 DSH 原生对话**；项目可切换、可重命名、可"从工作台移除"，位置丢失会显式标"位置丢失"。
- 接口：`/api/content/{bootstrap,projects,projects/relink,projects/delete,action,app}`。

**内容运营工作台**（media，**未注册**）
- 功能：官号选题 / 达人合作 / Campaign / 营销日历 / 内容数据 / 每日成果。
- UI：**四个窗口可交换位置、调整大小、收起恢复**；黑白极简风格，日历保留状态色 —— 这是 19 个里唯一的"可自由拼装窗口"布局。
- 可借鉴：**黑白底 + 只给状态上色**，日历类界面非常好读。

**双11省钱情报局**
- 功能：写下想买的东西 → 告诉你哪个平台、哪天几点买、先领什么券；数据全在本机。

## 3. 横切发现（比单项更重要）

### 3.1 宿主服务名不同：两套工作台契约并存

| | 我们自有 8 个 | 商城 19 个 |
|---|---|---|
| host 服务 | `@vssaros/dsh-workbenches`（注入名 `desktopWorkbenches`） | **`dsh-desktop-workbenches`** |
| 清单声明 | `vssaros.workbench`（title/description/layout/panes/…） | **没有这个字段**，注册时传 inline descriptor |
| 共享界面 | `wb-*` + `--dsw-alias-*` | **19 个里 0 个用 `wb-*`**（1 个出现过 1 次） |

抽样三份清单都能看到：`"dsh": { "client": { "platform": "web", "inject": ["dsh-desktop-workbenches", …] } }`。
⇒ **我们的 UI 统一规范对商城生态零影响**；反过来，商城条目的视觉也无法被我们统一。

### 3.2 三种典型形态

1. **内嵌 OSS 应用**（思维导图、画板）：只接管"存哪/开哪份"，绘图内核零改动 —— 适合能力已经很成熟的领域；
2. **单页业务工作台**（编曲、投标、合同、选址、装修）：左侧业务区 + 右侧对话（常驻或抽屉）；
3. **纯客户端轻工作台**（小红书、双11）：`apply(){}` 空服务端，数据只在本地。

### 3.3 数据落盘有共同约定

几乎都是 `<DSH 数据根>/<plugin-id>/…`，并**明说"卸载插件不删数据"**。Oil 更进一步：产物是普通目录（`~/Movies/视频项目`），可直接被编辑器/Agent 读写。

### 3.4 规模两极分化

- **最小**：小红书 12 文件、装修源码 5 KB、双11 源码 260 行；
- **最大**：Oil 140 文件、合同审核 72k 行（含 bundle）、装修 bundle 436 KB。
- **源码可审计性差异极大**：只发 bundle 的（装修）用户没法从仓库判断它做了什么 —— 而市场页的"静态能力扫描"正是在补这个洞。

### 3.5 5 个未注册（reg=false）

`media / huaxue / seo-geo / oil-creator / product-update-tracker`：`lib/client.js` 里没有 `desktopWorkbenches.register`（或用了别的注册入口）。对市场的含义：**"能装" ≠ "能跑"**，装完可能仍是 SSR 页或需要特定宿主版本（花学工作台就把兼容矩阵写在 README 里）。

## 4. 给"下次开发工作台"的经验（从这 19 个 + 我们自己的规范对照）

1. **先定形态，再写代码**：内嵌成熟应用 / 单页业务 / 轻客户端 —— 三种的成本差 10 倍，选错再改最贵。
2. **对话的位置是一等决策**：抽屉（按需）还是常驻右栏（编曲说清"不常驻"，自媒体说清"右侧就是原生对话"）。写在 README 第一段。
3. **数据放在 DSH 数据根，卸载不删**；能"文件即数据"就不要造数据库（Oil 的可迁移性最好）。
4. **只接管"存哪/开哪份"**：内嵌应用（导图/白板）证明这条路可行且成本最低。
5. **视觉克制**：黑白底 + 只给状态上色（媒体工作台），比全彩更容易读；**换主题要真跟随**（19 个里多数只有一套色）。
6. **可自由拼装的窗口**（媒体工作台的四个窗口可交换/缩放/收起）适合"多信息源并看"，但实现成本高 —— 只有它做了。
7. **兼容性要显式声明**（花学工作台的 `doctor.mjs` + 兼容矩阵）——比用户装上打不开再回来骂强。
8. **别只发 bundle**（装修 436 KB 无源码）：市场的能力扫描只能兜底，仓库可读性才是长期口碑。
9. **不伪造能力**：这次调研里"AI 审核/找位置/生成"都写清了输入输出与边界，没有夸大成"全自动"。
10. **用宿主现有服务，不自己造轮子**：19 个都走 `dsh.client.inject` 拿宿主槽位（slots/sidebar/layout/conversation/controller），没有一个自己起 iframe —— 这与我们"零 iframe"的规范一致。

### 6.1 从 19 个源码里新补的 4 条经验（此前的 10 条见 §4）

11. **选中态要能被对话读懂**：门店选址的右侧对话全程知道"你选中的是哪个点" ⇒ 多模态工作台的关键是**共享一个 selection 状态**，而不是各画各的。
12. **把"再生成"与"接受"分成两个按钮**：双11 的「帮我排一下 / 不改了」把循环与定稿分开，避免用户以为必须一直改。
13. **结论必须能点回原文**：投标/合同/SEO 三类的可信度全在"来源引用"上，不是界面漂亮。
14. **可审计性也是产品力**：装修工作台源码 5 KB、能力全在 436 KB bundle 里 —— 用户和市场的能力扫描都无法判断它做了什么；反过来 Oil 用"普通文件即数据"做到了完全可读可迁移。
