主页组件规范

适用范围：dsh-plugins/vssaros-dashboard 的主页（完整页 /x/dashboard/）里的**每一个卡片组件**。
最后更新 2026-10-22（主页改 React 渲染 + 卡片头统一 + 每卡错误边界）。

0. 三十秒版

  • 元数据写在 lib/catalog.js 的 WIDGETS；渲染写在 lib/app/src/app.jsx；样式写 lib/app/src/app.css。
  • 卡片标题/图标/强调色由外壳统一画（读目录岛的 name/icon/accent），组件里不许再画 h2 标题。
  • 颜色只用两层：--dash-*（页面派生层级）+ 语义明确的 --dsw-alias-*（品牌/状态/遮罩/阴影）。
  • 每个组件外面已包 CardBoundary：你抛错只坏自己那一块，但别指望它兜异步/事件里的错。
  • 改完必须跑：vendor/build.mjs → p3-46 → dump-shell.mjs → bump 版本。

1. 数据契约（catalog.js）

每个组件只有元数据，没有渲染函数（render() 已于 2026-10-22 删除，别再往里加）：

字段必填含义 / 约束
kind✓唯一 id，同时是 WIDGETS 注册表的键。同一 kind 只允许一张卡（normalizeLayout 会丢掉重复的并说明原因）。
name✓卡片标题 + 画廊条目标题。卡片标题的唯一来源。
description✓画廊副标题 + 卡片图标的 tooltip。
icon✓单色图标名（app.jsx 的 ICONS 键）。现有：graph / graph-line / list / list-unordered / home / pulse / folder / clock / watch / timer。写错不会白屏，会回落 grid。
accent✓卡片头图标颜色（#RRGGBB）。它在卡片底上必须 ≥3:1（图形元素）。
defaultSize✓{ w, h }：w = 占列 1–12；h = 最小高度（行），24px/行 —— 实际高度由内容撑。
defaultConfig✓出厂配置工厂函数。
normalizeConfig(raw)可选越界夹紧 / 过滤去重。由宿主在交给页面前调用（index.js 的 layoutForClient）；组件侧再 clampInt 一次当第二道防线。
configFields可选可配字段声明，有了它就自动长出卡片设置面板（编辑态齿轮），没有就不显示齿轮。三种类型：
· { type:'number'（默认）, key, label, unit?, min, max, step?, fallback }
· { type:'toggle', key, label, fallback:true|false }
· { type:'select', key, label, options:[{value,label}], fallback }
· { type:'text', key, label, maxLength, placeholder?, fallback }（trim + 超长截断 + 空白回落）
声明必须与 normalizeConfig 同口径——守卫用行为断言逐字段钉住：number 喂 max+100 要夹到 max、toggle 喂垃圾值要回落 fallback（不能按 JS 真值当 true）、select 喂非法选项要回落 fallback 且合法值必须原样保留。否则用户填了会被悄悄改掉。

1.1 布局契约（layout.js）

// 落盘文件（<数据根>/dashboard/layout.json）——**多套布局**
{ version: 1, active: '工作',
  presets: { default: { settings, updatedAt, items[] }, 工作: { … } } }

settings = { rowHeight(24..400), gap(0..48, 默认 12), maxWidth, mode: 'flow' | 'free' }
items[]  = { id, kind, w(1..12), h, config, title?, x?, y? }

// ⚠ version 2 起间距默认 12px（v1 是 0：卡片描边贴描边，看起来是一整块）；
//   读 v1 文件时会把**显式存的 gap: 0** 迁到新默认（那不是缺省、是存了 0，只改默认值救不了）。
// ⚠ 出厂默认顺序（2026-10-23）：工作台 → 关键指标 → 诊断行 → 会话明细（工作台最先）。

// mode = 'flow'（默认）：items 顺序 = 视觉顺序；h = **最小高度**（行，上限 MAX_ROWS=30），没有 x/y
// mode = 'free'        ：位置由 (x 0..11, y 0..MAX_ROWS_FREE-1) 决定；h = **真实高度**（行）
//                        ⇒ 上限用 MAX_ROWS_FREE=400，不能用 30（一页装不下会全部叠在一起）

// ⚠ 老形状（顶层 items/settings，P2 单布局时代）**照读不误**：`normalizeLayoutFile` 在内存里
//   包成 presets.default，**不写盘**（"读一页不该产生文件"那条纪律）；真正落新形状只在写口。
  • 两种模式的坐标必须互斥：flow 不许留 x/y（切回去用 stripPlacement 剥掉），free 必须有 —— normalizeItem 只认"两个都给"，只给一个是半套数据，当没给。
  • flow → free 是有损换算：先把每张卡的实测高度折算成行（measureRows），再用 packFlow 贪心装箱；否则 h=1 的卡只有 24px 高、内容全溢出。
  • free 模式下拖动/缩放后由 resolveOverlaps(items, anchorId) 兜底：锚点钉住，其余按 (y, x) 依次下沉到不撞为止（被推开的卡之间也要再解一次）。
  • 虚高卡片自动修：flow 下 h 只是最小高度，一旦被错误写大就永久留着。页面加载后自查一次：量内容高度，把虚高 ≥3 行的卡缩回内容高度 —— 只在内存里改、不落盘（"读一页不产生文件"），下次改布局时一并保存。阈值 3 行是为了不抹掉用户有意留白；手动「收紧高度」不限差量（明确要收就全收）。
  • 未知 kind 一律保留在布局里 → 渲染成占位卡（"该组件不存在：xxx"），不能静默消失。
  • 落盘：<数据根>/dashboard/layout.json；写口：POST /api/layout（内容，原子写 + 锁 + 按预设的 updatedAt CAS）与 POST /api/layout/presets（switch / saveAs / delete，同一把锁、不参与 CAS）。settings.mode 必须一起提交，否则服务端归一化成 flow ⇒ "切过去刷新又变回来"。
  • 预设的几条硬规则：?preset=xxx 只是预览（不改盘上 active）；saveAs 重名要 409（overwrite: true 才覆盖）；rename 保序改名（Map 插入顺序即落盘顺序，先删再插会把这份挪到末尾）、不动内容与 updatedAt、重名 409 / 原名不存在 404 / 新名为空 400 / 改同名回 unchanged；delete 不能删到空（最后一个 ⇒ 400），删掉 active 会自动切到 default/第一个；名字 trim + 最多 24 字（normalizePresetName）。
  • 页面拿到的是归一化后的 items（含每卡 config）——采纳服务端回传的那份，别用本地快照硬顶。

2. 渲染契约（app.jsx）

function MyCard({ model, config, onSaveConfig, setStatus }) {
	return el('div', null,
		el('div', { className: 'dash-sub' }, '副信息（可选）'),
		/* 正文：只读渲染 model，自己的临时状态用 useState */
	);
}
const WIDGETS = { kpi: KpiCard, ..., my: MyCard };   // kind → 组件
规则为什么
文案由宿主算（sessionRowModel / groupByCwd / usageBuckets），组件只造结构侧栏摘要版、React 版、/api/sessions 共用同一处口径 ⇒ 不会"侧栏 32、主页 30"
不画 h2 标题，只放 .dash-sub 副信息标题由外壳统一（图标 + accent + name）⇒ 8 个组件不会各漂一套字号/间距
不自己写设置表单：可配项只在 catalog.js 声明 configFields面板由 CardSettings 统一画（一套间距/校验/应用流程）⇒ 加组件不用再写 UI，也不会漂成 8 种表单
编排必须有至少两条"永远看得见"的出口：工具栏按钮（吸顶）+ 右下固定悬浮「完成编排」+ Esc2026-10-23 真机出现"进了编排回不来"：出口只在页面顶部，卡片一多滚下去就找不到了 ⇒ 三条路都收敛到同一个 exitEditing()
动作按钮必须带 data-dash-action 且有 onClick死代码守卫盯着：渲染了按钮却没处理器的历史事故（画廊按钮写在 return 之后）
移除/缩放手柄要带 data-dash-no-drag否则点击会被卡片级拖拽吃掉
长列表自己滚动（.dash-scroll，双帽 min(30vh, 300px)）不把整页撑长（用户明确要求过）
保存失败必须明说；409 才重载；不许静默丢弃"显示已保存但没落盘"是最难察觉的形态
错误边界：外壳已给每张卡包 CardBoundary（降级成"这块渲染失败了 + 原因"）。 它抓不到事件处理器与异步回调里的异常 ⇒ 那类逻辑自己 try/catch 并把原因写进 setStatus。

3. 视觉契约（app.css）

3.1 颜色只用两层

层用什么用在哪
官方 alias--dsw-alias-brand-primary、--dsw-alias-state-{success,warn,error}-primary、--dsw-alias-bg-mask-1、--dsw-shadow-lv3、--dsw-alias-label-primary品牌色、状态色、遮罩、阴影、正文色
页面派生 --dash-*surface / surface-2 / stroke / stroke-2 / muted / faint所有层级：卡片底、次级块底、描边、次要/弱文字

3.2 禁止清单（每条都是踩过的坑）

禁止后果
--dsw-alias-bg-layer-1 当卡片底真机上它被 IDE 主题覆盖成 sideBar.background（比页面底更暗）⇒ 卡片"凹进去"，看着像没卡片
--dsw-alias-border-l1 当描边它 = panel.border，与底差 12 级灰度（1.1:1）⇒ 等于没有边框
--dsw-alias-label-secondary 当次要文字IDE 亮色主题下它等于正文色 ⇒ 层次消失
彩色 emoji 当图标近黑底上过饱和，与官方单色体系冲突
在 CSS 里用 color-mix() 派生层级自定义属性读回的是声明原文（量不了对比度）+ 需要 Chromium 111+
只按 prefers-color-scheme 切主题官方 CSS 只认 body[data-ds-dark-theme] ⇒ 暗色环境里整页白底

3.3 几何基准

元素规格
卡片radius 10 + 1px 描边 + padding 10px 12px；编辑态改虚线 + grab。box-sizing: border-box 是硬要求：min-height（顺序流）、grid-row（自由摆放）与切模式时的 getBoundingClientRect() 必须同一盒模型 —— 默认 content-box 时差 padding+border（22px），会让每次切换都把 6 行折成 7 行、越点越高
卡片头图标 16px（accent 色）+ 标题 13px / 600，间距 6px
副信息 .dash-sub11px，--dash-faint
小按钮h28 / radius 14 / font 12；主按钮用 brand-primary 填充
pill / 徽标h20–24 / radius 10–12 / font 11–12
表格12–13px，行分隔线 --dash-stroke，hover 用 --dash-surface-2
数字一律 font-variant-numeric: tabular-nums（否则跳动）
状态点同色 16% 外晕 + 22% 内芯（StateDot 口径）

3.4 对比度门槛（可量，别凭眼）

对象阈值
正文 / 次要文字 ÷ 卡片底≥ 4.5
弱文字 ÷ 卡片底≥ 3.0
装饰描边 ÷ 卡片底≥ 1.5（WCAG 1.4.11 只管交互件，卡片不是）
交互件描边（按钮/输入/焦点）÷ 卡片底≥ 3.0
卡片底 ÷ 页面底≥ 1.12（否则看不出"抬起来"）
accent ÷ 卡片底≥ 3.0（图形元素）

派生比例在 app.jsx 的 RATIOS 里，**三档**：dark / light / hc（高对比，prefers-contrast: more 时启用，VS Code 的 hc-* 主题会带）。hc 不分明暗——它每一项都比另两档更极端。改色先改那里，别在组件里硬编码。

4. 扩展一个组件（7 步）

  1. 元数据：catalog.js 的 WIDGETS 追加一条（kind/name/description/icon/accent/defaultSize/defaultConfig，需要就加 normalizeConfig）。画廊自动出现。
  2. 数据：需要新字段 → 在 index.js 的 widgetModel 里补，并优先复用 catalog.js 的聚合函数（别在页面里重算）。
  3. 组件：在 app.jsx 写 MyCard（props 见上），注册进 WIDGETS。不要画标题。
  4. 样式：app.css 加类，统一 dash- 前缀，颜色只用 --dash-* / 语义明确的 alias。
  5. 构建：node dsh-plugins/vssaros-dashboard/vendor/build.mjs
  6. 守卫：node poc/dsh-p0/scripts/p3-46-dashboard-homepage-layout.mjs（"组件都在注册表里"会自动覆盖你）
  7. 看效果：node poc/dashboard-react-build/dump-shell.mjs → 打开 poc/dashboard-react-build/shell.html（真实服务端 HTML，不用重启 Host）

版本：只要 lib/ 里的内容变了就 bump package.json 的 version（Host 按版本重装；同版本会短路）。新增文件还要进 files 白名单。

5. 模板

5.1 catalog.js

{
	kind: 'mymetric',
	name: '我的指标',
	description: '一句话说清它显示什么、数据来自哪',
	icon: 'graph-line',            // app.jsx 的 ICONS 键（写错回落 grid）
	accent: '#4EC9B0',             // 卡片头图标色，≥3:1
	defaultSize: { w: 6, h: 2 },
	defaultConfig: () => ({ limit: 8 }),
	// 可配字段（有它就自动有设置面板；声明必须与下面的夹紧同口径）
	configFields: [
		{ key: 'limit', label: '最多显示', unit: '个工作区', min: 1, max: 30, step: 1, fallback: 8 },
		{ key: 'showTrack', label: '显示占比条', type: 'toggle', fallback: true },
		{ key: 'order', label: '排序', type: 'select', fallback: 'desc',
			options: [{ value: 'desc', label: '会话多在前' }, { value: 'asc', label: '会话少在前' }] },
	],
	normalizeConfig(raw) {
		return {
			limit: clampInt(raw?.limit, 1, 30, 8),
			showTrack: boolOf(raw?.showTrack, true),
			order: enumOf(raw?.order, ['desc', 'asc'], 'desc'),
		};
	},
},

boolOf / enumOf 是 catalog.js 里的两个小助手：布尔只认 true/false（垃圾值回落 fallback，不按 JS 真值当 true）、枚举只认白名单（非法值回落 fallback）。

5.2 app.jsx

function MyMetricCard({ model, config }) {
	const limit = clampInt(config?.limit, 1, 30, 8);       // 第二道防线
	const rows = (model.mymetric || []).slice(0, limit);   // 数据由宿主算好
	if (!rows.length) { return el('p', { className: 'empty' }, '还没有数据。'); }
	return el('div', null,
		el('div', { className: 'dash-sub' }, `共 ${rows.length} 条`),
		el('table', { className: 'dash-tbl' },
			el('thead', null, el('tr', null, el('th', null, '名称'), el('th', null, '数值'))),
			el('tbody', null, rows.map(row => el('tr', { key: row.key },
				el('td', null, row.key), el('td', { className: 'dash-num' }, String(row.value))))),
		),
	);
}
// 注册：
const WIDGETS = { ..., mymetric: MyMetricCard };

5.4 与 IDE 侧「主页」的口径差异（原在页面上，2026-10-23 移到这里）

本页读的是 dsh 自己的会话投影缓存（<dsh 数据根>/storages/session_projcache/sessions/*.json）， checkpoint 落盘 ⇒ 可能比实时略落后，因此只有会话遥测：turn / step / 耗时 / token 用量 / 子代理 / 待办计数。 IDE 那侧的「主页」是它自己的聚合口径（另有成本与告警）。

⇒ 同一个"会话数 / 用量"在两页不必相同，这不是 bug。 但请不要拿两页互相对账 —— 它们量的不是同一段时间、也不是同一份数据。

为什么放在这里而不是页面上：那段说明占两行、每天都看的人不需要它；而需要它的人（第一次觉得"数字对不上"） 会来查规范。守卫两侧都钉：文档里必须有（含点名 IDE）、页面上必须没有。

7. 还没做的（别以为是已实现）

  • 自由摆放的跨列压实：compactGrid 只做**纵向**压实（只动 y、不动 x，可预测）；Grafana 那种跨列搜索填洞需要完整求解，刻意不做。
