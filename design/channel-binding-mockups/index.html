Channel 绑定卡 · 4 套 mockup

目标：① 把标题下那一大段说明收进 ⓘ tip；② 重排绑定 item，不再把平台 / chat_id / 类型 / 方向 / 状态 / 应用 / 两个按钮挤在一行。

每格都是可交互 HTML：悬停或键盘聚焦 ⓘ 看说明，点「+ 新建绑定」展开表单，右上 ◐ 可切明暗。宽度按真机右栏 380px 模拟。

四套方案

A · 紧凑双行 推荐最小改动
身份 / 状态 / 操作在第一行，元数据在第二行。仍是列表，但层级清楚、chat_id 不挤按钮。
B · 信息卡 最强调单条
每条绑定一张卡，左侧平台色条；chat_id 完整显示并可复制，标签与操作分区。
C · 折叠详情 最省空间
默认一行只给结论，点 ⌄ 展开键值明细；每个字段旁还有短 ⓘ。
D · 开关胶囊 最现代
状态改成开关（开/关文字 + 颜色双编码），删除收进 ⋯ 菜单；需新增开关与菜单组件。

推荐

建议选 A（紧凑双行），并把 C 作为「绑定超过 5 条」时的后续增强。
  • 你的诉求是「文字太多 + item 挤」，A 直接命中：说明整段移进 ⓘ 富卡，item 拆成两行，不动数据结构、不新增组件。
  • 右栏只有 380px，B 两条就占掉大半屏；D 的开关/菜单会把「停用/删除」从明确的文字按钮变成隐式操作，运维向场景反而更容易误触。
  • 若后续绑定变多，再给 A 加一个「展开/收起」即可平滑演进到 C，不必推翻重做。

ⓘ tip 的实现口径：本项目没有统一 tip 组件，生产里「富说明走 HoverCard、短提示走原生 title、二者不叠用」（client.workspaces.js:3656 明确去掉行上原生 title 避免双浮层）。mockup 用纯 CSS 的 :hover / :focus-visible / :focus-within 富卡表达，键盘可聚焦、带 role="tooltip"；落地时应复用 S.sessHoverCard 或新建等价的小 tip，并同步删掉该元素上的 title。色值全部走 --dsw-alias-* 令牌 + 兜底，不新起调色板。

共同的信息架构（4 案一致）

  • 标题行：Channel 绑定 · N 条 · ⓘ（完整说明）· 刷新 —— 不再有平铺长段。
  • tip 富卡内容：绑定语义（一应用 + 一 chat_id）/ 仅人可增删改 / 白名单留空 = fail-closed / 飞书可选或新增应用 / groupPolicy 默认 open 仍需 @。
  • 绑定 item 必带：平台、状态（颜色 + 文字双编码）、chat_id 摘要、类型、方向、应用；长 chat_id 用截断 + tip 显示全文。
  • 新建绑定：默认收起；字段说明（chat_id 来源 / 群策略 / 白名单）各挂一枚短 ⓘ，不再靠超长 placeholder 承载文档。
  • 无障碍：图标按钮都有 aria-label，tip 可键盘聚焦，focus ring 可见，状态不只靠颜色，尊重 prefers-reduced-motion。
